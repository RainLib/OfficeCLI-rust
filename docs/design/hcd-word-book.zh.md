# Word 跨节连续画布、共享区域与位置跟随

2026-10-30。区域 Word 的各节现放进同一个滚动画布，统一显示缩放；每节正文仍有独立区域身份，共享页眉/页脚在整本中只挂载一个真实编辑器。**这里完成的是整本连续滚动及普通 nextPage 分节的屏幕编号衔接，不是同页连续分节、奇偶分节补白、精确 Word 排版或域计算的完成声明。** 管理平台和实际提醒继续后置，全部格式目标保持开放。

## 模型与界面

- `WordBookSurface.tsx` 持有整本的区域源视图、纸张位置、按宽度的页眉/页脚测量和当前编辑纸张。`WordPageSurface.tsx` 只负责一节的正文流与纸张副本。共享区域 ID 在 DOM 中只有一个活编辑器，不因继承、节数或页数增加而重复注册协作绑定。
- 页眉副本及隐藏测量均使用已经处理过的节点视图，不创建第二份编辑器；每个区域与正文宽度组合独立测量，避免把窄纸张的换行高度应用到横向纸张。
- 整本采用一个缩放系数，各节保留其原物理纸张尺寸。移除正文旧的 820px 上限；样例中 Letter 正文宽约 624px、横向 A4 正文约 930.53px。不同原纸张不被强制改成相同尺寸。
- 每节页数只供屏幕布局使用。普通下一页分节可以由前节已完成测量的页数继续编号；原生显式起始编号优先。前节测量中、复杂对象回退或编号溢出时，后节不借用过期页数。
- 继承绑定在文档顺序中一次性解析，避免逐页反复扫描所有前节。禁用的首页/偶数页绑定仍供以后启用或继承使用，但不占当前正文空间。
- 普通输入焦点优先于可视节状态：不能因为长段落输入后的视口靠近下一节，就把格式操作切到另一节。

Word 的实现约定与通用 OOXML 说明有差异：本实现继续使用节起始编号判断奇偶页，并按变体继承前节绑定，依据 [Microsoft 的 Word 实现说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/e9535962-4cf3-4279-9367-637241e4b195)。`continuous`、`nextColumn`、`oddPage`、`evenPage` 仍需要同页/补白的物理排版适配；现显示明确的独立纸张预览提示，不猜后续编号，也不把它们当作普通下一页分节。

## 协作位置

Awareness 增加整本视口标记、所属节、纸张序号及纸张内进度。不同缩放的成员按相同节/纸张定位；旧客户端仍可使用节内进度回退。选择“定位”不会自动开始跟随。

共享页眉/页脚的光标还带所属节和实际纸张上下文；同一 story 在多个节出现时，不能只凭区域 ID 跳回第一个节。位置仍是临时数据，不写入正文、版本、恢复文件或导出。

原逻辑通过 React 状态取消跟随，迟到的 Awareness 回调或动画帧可能在订阅替换前重新开始导航。新增 `ViewportFollowIntent`，同步取消并为每次跟随分配代次；旧回调不能重启已取消或重新开始的同一成员跟随。真实精确交错由定向测试验证，不能把普通 UI 的一次成功当作全部时序验收。

## 实际验证及边界

正常浏览器入口与本机 sidecar/native 服务，输入和保存均使用产品 UI：

1. 两节同时存在。第一节长段落由 1 页增长为 3 页，第二节延续起始编号从 2 更新到 4。第二节横向正文开始被旧最大宽度限制，修复后完整使用本节宽度，最终为 4 页。
2. 第二节正文的个人撤销缩回 1 页、重做恢复长正文；前节内容保留。阶段截图/数据中曾为 5 页，这是宽度修复前的结果，不作为最终页数。
3. 第二节第 2 页双击继承页眉，在本页原位激活；界面显示“链接前一节”和共享影响。活编辑器与纸张页眉位置相差约 0.54px（纸张边框）。保存至 r5 后，第一节第 3 页及第二节第 2 页显示相同“跨节共享页眉”，活区域 ID 仍为 7 个互不重复的区域。
4. Bob 通过普通原生粘贴输入自己的标记；撤销只删除该粘贴、重做恢复，同时保留 Alice 两节正文及共享页眉，正常保存为 r6。粘贴实际位于第二节开头，不能说成文末续写。
5. 缩放 25% 后，各节仍为 3/4 页。两个正文的 DOM Range 矩形均未与页间隙相交。100% 只读浏览器通过协作面板跟随到 25% 成员正在查看的同一节和纸张。
6. 首次高级滚动接口尝试后仍处于跟随状态，未算退出通过。同步意图修复后的普通只读页面，通过独立只读 WebSocket 位置夹具进行最终检查：原生 `mouseWheel` 输入使跟随停止并实际滚动；“定位”不开始跟随，PageDown 也停止跟随。这里只将前一项跨缩放记为两个浏览器；最终滚轮复验是普通 UI 加受控网络成员，范围不能混淆。
7. 部分自动化输入/焦点读取超时。核对部分文字后才继续输入；旧页面读取失败没有用来重启服务或重复未知动作。浏览器内核重置后，通过现有标签页盘点恢复了已经创建的新只读页。

## 复验

```sh
# 仓库根：生成自己的合成下一页分节/延续编号样例。
python3 scripts/hcd-word-layout-browser.py --clean --story-source --book-source
# 在打印出的 Alice/Bob 普通页面输入样例文字、共享页眉并保存，再核对实际文件。
python3 scripts/hcd-word-book-files.py /absolute/owned/word-layout-ui-example /absolute/owned/docs/assets/example
cd examples/hdoc/editor
node --import tsx --test --test-concurrency=2 src/wordBook.test.ts src/wordBookPresence.test.ts src/wordPageFlow.test.ts src/wordPaper.test.ts src/wordRegionalBinding.test.ts src/semanticStructureCarets.test.ts src/collaborationViewport.test.ts
npm run build
```

`--book-source` 明确生成下一页分节、延续编号、普通边距且无旧多栏/修订布局的输入。原始混合样例含连续分节、负边距和旧多栏，两类输入分别记录；不能用生成样例宣称原始复杂排版已修复。文件验证器要求固定的 95 次第一节标记、90 次第二节标记和相应成员/页眉标记，不能对其他内容跳过断言。受控位置夹具只连接具名临时文档，读令牌仅保存在私有测试目录。
