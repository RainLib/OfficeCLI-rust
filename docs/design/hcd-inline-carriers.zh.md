## 正文存在哪里

`SemanticInlineContainers` 为每个 `instanceId` 保留一个独立 `Y.XmlText`，空正文也分配载体。父段落只存 `{hcdInlineContainer:{version:1,id}}`，不存 PM 子树 JSON，也不把正文放进业务 `data`。嵌套正文继续引用各自的永久载体。

`hcd-inline-containers/1/definitions` 保存不含正文的节点定义，`…/bodies` 保存共享文字。定义与空载体分配不进入个人撤销；用户的文字、格式和父引用变动进入同一次历史事务。删除引用不删除永久载体，以保留迟到输入。当前内核只接受定义一致的正文编辑；业务属性变化明确拒绝，后续应接入既有属性候选协议，不能用 LWW 定义覆盖替代它。

旧的 `readSemanticInline` / `writeSemanticInline` 默认仍拒绝非叶行内节点；新增的显式编解码参数才允许此内核解析引用。非叶 wrapper 不携带格式 mark；正文内部沿用普通格式、自定义 mark、提及、来源标记及软换行。两个间隔引用同时删除时保留中间字符原有身份，避免失效相对锚点。

## 位置与历史

父载体的一个 embed 与 PM 子树的 `正文大小+2` 不是相同长度。`capture` / `resolve` 显式区分父级边界和内部载体。以下偏移均相对父节点 content，以 `A + 容器(Shared) + Z` 为例：

| PM 偏移 | 保存的相对位置 |
|---|---|
| 1，容器之前 | 父载体 index 1 |
| 2，内部正文起点 | 子载体 index 0 |
| 8，内部正文终点 | 子载体 index 6 |
| 9，容器之后 | 父载体 index 2 |
| 10，Z之后 | 父载体 index 3 |

空容器内部光标也锚定子载体；填字后仍可定位。移动父引用时，不移动或复制内部文字，因此离线输入和内部光标跟随同一载体。引用隐藏后 `resolve` 返回 null，原载体仍可读取迟到内容；撤销隐藏恢复同一引用。撤销新建只撤销自己的字符和引用，迟到同伴字符保留在原载体，重做重新显示它。**审阅/恢复 UI、保存门禁和当前导出门禁尚未接入这批新载体，不能以这些内核测试替代它们。**

写入要求调用方提交精确的当前 Fragment，拒绝过期本地投影；离线副本各自按自己的字符身份生成 Yjs 更新。重复 ID、非法载荷/标记、定义变化、未知节点属性、环、深度24、跨度1000、正文1MiB等边界均检查；写入负例在分配或正文修改前拒绝。保留载体上限10000，不实现压缩或 GC。

## 活动房间仍保持旧模型

- wire 仍为7，公开 envelope 仍为1/2，SDK仍只广告 blocks-v1；不添加插入菜单、节点视图或能力头。
- 旧投影读取器现在主动拒绝 native 的 `inline.content`。wrapper 的空 `text` 不能经过空字符串过滤而静默丢掉正文；普通、嵌套和只读输入均覆盖。
- `RoomProtocolGuard` 在影子文档中拒绝新的 body/definition Map 和父引用，拒绝后重建影子，下一条合法普通更新仍可通过。构造阶段检查失败会释放影子文档。
- 原生 `X-HCD-Inline-Containers-Version:1` 门禁继续保持；本批没有修改 native 或重新声明上批 HTTP/离线文件验收。
