## 原生契约

- `POST /v1/documents/{id}/word/link-transactions` 接受 coordinator、完整原事务、候选布局摘要及原生预检摘要。只允许当前协作服务、`/2`、coordinator 7，以及明确布局/story/link 声明。
- 原生重复核对 epoch、owner/租约/日志摘要、作者当前写权限和固定版本。根据原基准重建预检身份；候选、作者、来源绑定和影响发生变化时拒绝，不按当前 head 偷换基准。
- `apply_coordinated_flow_story_link_transaction` 在 bundle 锁内只移除指定绑定，保留全部正文、story 和资源，并发布模型 3。其请求摘要使用独立的 `hcd-word-coordinated-link/1` 域，旧链接事务不能被解释为协作提交；旧原生入口首次仍使用模型 2，不自动迁移。
- 同一请求重放返回原版本；后续正文/页面保存或显式还原后，仍不会重新应用链接、回退当前 head 或多建一版。不同请求复用编号被拒绝；页面、独立区域创建和协作链接也不能互相复用编号。
- 原生取消检查现在包含链接记录：已经提交的链接，经过后续保存或还原后也不能被标成“未准备”。真正未准备的编号可沿既有取消机制封存，迟到链接提交被拒绝。

这些接口面向可信 owner。owner 必须先停写/排空成员、持久准备签名日志，再调用提交；接口本身不会代替这些工作。当前没有新增可供普通成员直接提交链接的侧车路由或 UI 按钮。

## 固定版本回执

`POST /v1/documents/{id}/word/link-receipt` 接受 `prepared` 及 `apiHash`、`pendingHash`、`initialUpdateHash`。它只验证已经提交的记录，不触发提交。

原生核对固定基准和目标版本、完整请求摘要、作者、候选布局，并检查这一链接版本的内容索引、批注和非布局资源未被替换。签名绑定文档、epoch、coordinator、当前 owner 日志摘要、原/新 revision、事务编号、请求/待处理摘要、root、布局、原预检和新 Yjs 初始状态摘要。

签名表示原生确认了该固定版本及所绑定元数据。它不证明调用方已经正确转换 Yjs 文档或持久保存协调器日志；后续侧车恢复器仍必须独立核对原请求、签名、候选、作者和房间基线。native HTTP 样本使用人工拥有的独立夹具租约，没有伪造一个已完成的在线协作生命周期。

## 混合历史与导出

独立原生服务样本依次产生：导入投影 r1、正文 r2、页面 r3、链接 r4、正文 r5、页面 r6、还原到 r3 内容的新版本 r7。r4 回执在后续保存及还原后保持一致；精确重试返回 r4，head 仍为 r6/r7。

语义 DOCX 分别导出并重新导入 r1–r7，核对链接前后的显式绑定、各版本纸张宽度、正文标记和原图片字节。HCDZ 解包后逐版本投影与原文档一致，规范及离线校验通过。

**保留原稿的混合历史导出仍未完成。** 样本另外检查该路径以“非纯文字历史”的明确原因拒绝、不产生目标文件。不能用语义重建文件证明原稿 XML 保真，也不能将这项原生提交基础描述为完整链接产品交付。既有旧模型 link-only 原稿导出保留自己的范围。
