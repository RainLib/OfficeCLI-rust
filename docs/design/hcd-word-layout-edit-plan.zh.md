## 2026-10-30：实际侧车活动页面字段事务与原请求重试

本批从 10 月 29 日开始，最终记录在 10 月 30 日。实际侧车新增受 `HCD_WORD_ROOMS=1` 和 `HCD_WORD_LAYOUT_ROOMS=1` 控制的 `POST /v1/documents/:id/collaboration/word-active-layout`。它要求明确的节点 7 / 区域 2 / 布局 1 请求头、当前 epoch、写成员及精确 actor；请求体是 `{epoch, request}`，request 沿用 `hcd-word-layout-transaction/1`，不接受额外字段或客户端伪造作者。按原始字节限制 270 KiB 后统一严格解码 UTF-8，避免分包中文被逐块字符串解码破坏。

`WordActiveLayout` 记录同一进程中的阶段：停写确认、原生确认、签名推广、旧房间退役、候选安装、自动保存启用。确认成员后，排他 freeze 和 drain 后分别再次核对成员集合；异步就绪证明拒绝。尚未 prepared 的拒绝释放本轮并保持旧编辑器可用；已经 prepared 或未知结果保留 gate 和同一 pending，重试继续原阶段。已退役宿主先检查原退役证明，不盲目再次卸载。已经安装但启用失败的请求只重试启用，不再次提交布局或安装。

实际新宿主用私有 context 加载，在同一 lease 和 journal 下绑定并注册 owner，确认已安装后再释放 gate 和启用自动保存。工厂在返回前失败会清理它已登记的部分宿主；清理不明确时保留许可，下一次先清理原候选。成功结果缓存按文档、epoch 和完整请求匹配，变更同一事务 ID 的请求、其他作者和并发相撞拒绝。缓存有界且不持久化成员 token，重试使用当次授权回调。

HTTP 409 需要结合稳定 `code` 判断，不能一概当作“未提交”。例如 `migration-outcome-unknown` 要继续同一个原请求；不能改 transactionId 重新发起。当前阶段/成功缓存限同一侧车进程；丢失进程后仍需现有签名拓扑恢复核对原请求，不能据缓存不存在重建提交。drain 若保存了其他成员的新输入并推进基准，原页面请求可能被拒绝，需要重新审阅，不静默改写已经确认的请求。

## 2026-10-29：在线成员停写确认协议与区域输入接线

新增 `WordTopologyPause`（客户端）和 `WordTopologyRounds`（服务端）。布局 `/2` 的普通浏览器明确声明 `hcdWordTopology=1`；该声明不授予写权限，也不把旧客户端升级成可执行页面事务的客户端。现有旧协议正常编辑不受影响。实际侧车记录声明并在已鉴权的 stateless 处理中接收 ready，发起轮次仍由待接的活动事务负责。

客户端先检查可用状态、正在保存/恢复、图片及节点资源任务，再同步调用区域输入暂停适配器。适配器在所有当前 PM view 上检查 composition 和历史任务；组合输入中直接拒绝，不先强制退出输入。可暂停时同步设各 view 不可编辑，随后等待设备写入和 provider 同步排空，再核对版本代次/状态。准入期间不把保留草稿静默保存，不清空设备日志，不往正文写暂停信息；本轮暂停状态同时阻止普通保存/导出绕过门禁。新增状态文案覆盖现有五个 locale。

ready 绑定确切轮次和连接。新成员、未知/旧客户端、错误 request ID、否定确认、等待超时或确认后的新修改，都不能算作全体就绪。否定确认释放已经暂停的同伴；只有匹配的 release 才解除当前暂停，旧 release 不影响新轮次。设备写入失败或超时会否定确认，但不会因为停止等待就声称写入已取消。断开后的旧文档仍遵循原有永久 fence/新文档重连规则。

服务端 prepare 必须在 admission 关闭之前执行，否则客户端无法排空和回 ack；活动事务进入排他 freeze 时还必须对当前完整成员集合再次 `assertReady`。准备失败可 release；原生事务已经 prepared 或结果未知时不能因此重新放开旧房间。这里的原请求/新宿主编排尚待接通，不能仅凭 ready 自动提交纸张设置。

## 2026-10-29：暂存宿主的内部 context 与精确卸载许可

`WordRoomStages` 为每个文档登记独立暂存许可，固定房间名、文档身份、事务类型/完整 identity、gate、日志 binding、lease 及源 owner 检查回调。登记要求 exact held gate 且宿主没有同名文档、加载或卸载任务；同一文档不能通过另一房间名同时登记。内部 context 只比较对象身份，JSON 复制或客户端传入的同形对象不能使用它。

实际侧车已接暂存的加载、绑定和卸载生命周期分支：受控加载沿用现有 lease 和 journal，不重新申请所有权；暂存 owner 必须是相同日志的布局正式模式，自动保存保持关闭。普通客户端的认证和逐包 gate 未绕过。正常退役许可和暂存回滚许可各自独立，不能把正在安装的候选当成普通空闲房间自动卸载。

回滚只对确切登记的 Document 和 owner、零连接且已无加载工作的宿主发出卸载。Hocuspocus 的 before/after hook 都核对许可；完成前不遗忘候选，不释放准入。超时表示停止等待，不表示卸载已取消：重试观察同一宿主 in-flight 卸载任务，不能以超时为由创建新房间。卸载无动作、注册表清理失败、部分初始化和异步证明均保留可核对状态。返回给安装器的 owner 在宿主清理证明之后才由安装器销毁；工厂在返回之前自行失败时仍负责收尾。

安装器释放 gate 后，宿主可以同步核验已登记文档和仍有效的所有权，再启用自动保存并消耗暂存许可。源 owner 的检查由持有原事务/退役记录的宿主提供；它必须核对同一日志和原 owner/retirement，不能用单独的布尔值代替生产来源检查。测试宿主当前使用真实 journal 和 retirement 核验这一回调。

## 2026-10-29：正式保存模式的房间替换基础

`installLayoutDraftRoom` 保留默认实验草稿模式，新增显式 `mode: 'layout-live'`。正式模式要求前一个协调器已是布局感知活动模式，替换副本同属一个版本 3 签名日志，且其自动保存必须关闭；不能把旧区域或实验草稿默认为正式房间。原有 owner、成员、固定版本、文档字节、日志链和宿主安装证明检查继续执行。安装失败时副本冻结；回滚结果未知会保留原副本和清理操作，先确认卸载完成，再创建另一副本，不能提前放开输入。

## 当前约束

- `FlowDocumentLayout` 是版本化资源，节、story、纸张和链接都进入内容哈希和历史。缺少某变体的绑定表示继承上一节同变体；缺少来源并不等价于直接用默认变体。
- 区域房间的 `WordRegionStore` 以规范布局哈希和区域 fence 固定区域集合；`hcd-patch/6` 与签名 checkpoint 也核验原布局和全部区域。当前客户端只允许正文内容更新并在规范回执中接受 section-end ID 的变化，不能直接在 UI 中改本地布局后假装已保存。
- 用户的未提交文字、图片和节点附件可同时存在；布局变化不能通过重建房间、替换整个 Y.Doc 或直接覆盖资产来丢弃这些内容。旧客户端、离线副本和迟到的原请求必须明确拒绝、继续核对或进入恢复流程。

1. 将纸张尺寸、方向、页边距及首页/奇偶选项定义为可验证的分节字段意图，记录基础布局 hash、分节身份和逐字段前置值。相同字段并发修改需要可见冲突；不同字段可在明确验证后合并。范围和单位按 DOCX/现有布局校验，不把 UI 默认值静默写成来源设置。

## 原生签名回执查询

新增只读 `POST /word/layout-receipt`，供协作服务查询已提交布局事务。服务检查成员凭证、区域协议和当前代次、活跃 owner 租约、租约登记的日志 hash、作者当前访问策略，并核对不可变版本中的请求摘要、作者和根哈希；签名绑定文档、代次、协调器、日志 hash、版本、事务 ID、请求摘要及根哈希。TypeScript 日志核验相同字段及 HMAC，且要求调用方另行验证所有权、权限和最终布局后才能处理草稿。

隔离原生 HTTP 用 r7 文件验证签名可被 Python 与 TypeScript 独立核验，错误请求和日志 hash 返回 409，普通成员返回 403、未认证返回 401；文档未改变且导出仍可用。证据见 `docs/assets/hcd-word-layout-server-fence-2026-10-27/http.json`。原生处理函数专项与 TypeScript 测试、原生构建和 Clippy 通过。

owner 登记的日志 hash 是协调器对其日志链的声明，原生服务并不读取或验证日志内容；隔离 HTTP 测试使用合成 hash，不是实际签名日志恢复验收。回执接口只查询已有版本，不提供在线布局写入，也未接入协调器的响应丢失恢复、真实成员连接、布局内容验证或清除待处理记录。

## 布局内容逐字段核验

区域 store 接受布局回执时，除了检查文档、基础 hash 和区域拓扑，还按原始请求逐项核对旧值与目标值，并比较整个新布局；额外改变任何未请求字段会被拒绝。核验在修改 Yjs 之前完成，避免部分更新。实际隔离文档 r4→r5 和 r6→r7 的原生投影及请求通过对照；额外改动纸张高度被拒绝。原生版本与文件验证见 `docs/assets/hcd-word-layout-transition-2026-10-27/native-and-files.json.receipt.json`。专项测试另核对同伴页眉输入、个人撤销、未知字段与拓扑保护。

该校验只比较传入内容，不鉴定投影来源，也不写入或清除日志；调用方仍须验证签名、权限、租约以及固定版本的原生投影。在线协调器、原子日志推进和多成员验收仍未实现。

## 停止房间时的布局回执恢复

新增显式启用的 `acknowledgeLayout`，用于房间停止后的私有日志恢复：检查当前日志 tip 对应的签名回执、事务和作者，核对前后固定版本的区域内容摘要及布局字段，在独立 Y.Doc 上更新布局 fence，再通过原有不可变日志链 CAS 写入新基线。待提交的区域内容和作者账本保留；旧版本读取器会因历史链中的版本 2 记录而拒绝，不能静默降级。

方法要求调用方在整个过程停止房间、提供可信原生投影，并在发布前检查租约和权限；它本身不从网络获取或认证投影，也不替换活动 Y.Doc。新快照持久保存原请求、原生记录和签名回执，重开时重新验签并确认前一条日志包含同一待处理请求、回执引用真实父节点；旧版本读取器继续拒绝。验证包含错误签名、非预期布局、正文变化、租约失效和把有效签名接到错误日志父节点，均不能清除原请求。

隔离 HTTP 使用真实签名日志 hash 获取原生回执，三个 Node 进程分别准备、确认和重开，保留页眉迟到输入；测试程序还将新 tip 登记到 owner，并重复相同登记，结果一致。见 `docs/assets/hcd-word-layout-server-fence-2026-10-27/http.json`。这些操作尚未接入正式协调器；重复登记是主动重试，不是网络断开后丢响应的实测。停止房间、可信投影、owner 新 tip 确认及恢复完成后接续多人编辑仍由未来协调器负责。

## 停止房间后的协调恢复流程

增加内部 `recoverCommittedWordLayout`：在调用方保证房间停止且持有 owner 租约的前提下，重登记签名日志链、复核当前权限和规范 head，读取固定基线及原生记录，通过只读签名回执获取固定新投影，验证后推进私有日志，再登记新 tip。回执接口现向符合租约的服务附带固定版本投影；回执签名仍绑定规范版本根、请求与日志 hash，调用方还逐字段及正文摘要核对投影。

如果新日志已写入、owner 记录请求已成功但客户端未收到结果，后来的停止房间 owner 可以读取已确认日志链并重新登记同一 tip，不再次提交布局或查询回执。隔离 HTTP 样例实际使用原生服务、租约及独立 Node 进程；测试传输在收到 owner 成功响应后主动抛错以模拟结果未知，重启后保留迟到页眉输入并完成重登记。结果见 `docs/assets/hcd-word-layout-server-fence-2026-10-27/http.json`。这不是实际 TCP 中断测试，也没有接入活动房间或浏览器；停止房间、服务身份和成员授权仍是调用方与原生接口的共同前置条件，页面设置入口保持关闭。

后续补充真实 TCP 断开：本机代理将 owner 记录请求转发到原生服务，读取并核对服务成功返回的新日志 hash 后，直接关闭下游 TCP 连接，不向协调器返回响应。独立回读原生 owner 绑定确认新 tip 已落盘；另一个 Node 进程重新取得 owner、登记同一日志链，无需再次查询布局回执，迟到页眉输入保留。验证命令为 `python3 scripts/hcd-word-layout-fence-http.py`，结果见 `docs/assets/hcd-word-layout-tcp-2026-10-27/http.json`，其中 `ownerRecordResponseTcpDropped` 标记该注入。它验证的是 owner 记录响应丢失，不是布局提交本身断线、进程强杀、活动房间或多成员浏览器验收。

## 布局感知协议的原生提交

原生服务识别独立的 `hcd-word-regions/2` 协议，并提供仅供协调器使用的 `/word/layout-transactions`。提交要求版本 6 协调器、布局能力声明、当前代次、有效 owner 租约及登记日志、作者访问权限和精确基线版本；旧 `/1` 房间、普通写成员和无 owner 请求被拒绝。此协议还没有公开迁移、活动房间或浏览器入口；旧客户端不认识 `/2` 并拒绝加入。当前 `/2` 也拒绝旧版正文 checkpoint，避免假装已经支持完整在线编辑。可信协调器仍必须负责停止或排空房间并保证准备日志真实持久化，原生服务不读取该日志内容。

隔离样例将真实签名布局请求提交到本机 `/2` 原生服务，代理确认提交 r8 后关闭 TCP 响应；相同请求重放只返回 r8，变造请求和过期基线被拒绝。签名回执及实际准备日志随后经过独立进程恢复；owner 记录响应再次经 TCP 注入中断，迟到页眉草稿保留。导出 DOCX 的纸张宽度及 HCDZ 校验通过。详见 `docs/assets/hcd-word-layout-submit-2026-10-27/http.json`。这是显式构造的单机协议和停止房间样例，不代表已有文档可迁移、真实在线多人、跨主机或第三方 Word/WPS 验收。

## 停止房间的已准备请求提交

`submitPreparedWordLayout` 仅供持有租约且已停止、排空房间的内部协调器调用；调用者须串行化日志操作，并通过认证 transport 为布局提交和回执附加当前 owner 的租约及日志 hash。它先加载已签名请求，确认 `/2`、写权限、epoch 和 owner 日志链；规范头仍在基线时核对基线 root 后提交原请求，头已前进一版时只尝试签名回执恢复，其他版本拒绝。提交失败或响应丢失时不清除待处理请求；提交后仍需核对签名回执和实际投影，才推进日志。原生服务仍须在提交时独立检查权限、版本和字段 CAS。

专项测试模拟提交前、提交后连接失败、进程重新打开日志、错误基线、版本变化与活动房间拒绝；该增量尚未接入活动 sidecar、浏览器或多人迁移，且本次网络中断采用模拟 transport，不能当作真实 TCP 验收。

后续独立本机验收直接调用该函数：真实原生服务提交成功后由代理切断 TCP，检查签名日志仍保留原请求，再由另一个 Node 进程接管并以签名回执完成恢复；规范头仍为 r8，页眉迟到草稿保留，DOCX 的纸张宽度和打包后的 HCDZ 校验通过。证据在 `docs/assets/hcd-word-layout-coordinator-2026-10-27/http.json`，可由 `python3 scripts/hcd-word-layout-coordinator-http.py` 复现。当前布局版本的旧 `/editor` 投影入口仍拒绝读取，隔离恢复使用签名回执携带的投影；活动房间、旧文档迁移及浏览器入口均未接通。

后续为 `/2` 协调器开放布局新版本的受保护投影读取：要求协调服务写身份、协调器 6、布局版本 1、当前 epoch 与有效 owner/日志租约。旧客户端和普通成员仍不能读取新 head；历史读取保持现有行为。默认读取先固定检查时的 revision，避免并发提交后能力检查与返回内容指向不同版本。该接口仅提供内部只读投影，不开放正文 checkpoint，也不代表 `/2` 活动房间可用。

后续新增 `/2` 原生正文 checkpoint：仅接受协调器版本 6 和布局版本 1，要求当前 owner 租约、作者权限和布局基线；签名记录使用独立的 `hcdsave6`，旧版本 5 不能向 `/2` 写入。隔离实际 HTTP 测试先提交纸张宽度，再保存正文与页眉页脚，重放不新增版本；DOCX 纸张及各区域文字、HCDZ 校验通过。正文块新增可改变分节末尾锚点和布局哈希，协调器必须使用回执的新投影和哈希。当前测试直接调用原生接口，`hcdsave6` 的客户端签名日志、活动房间和浏览器尚未接通，也未验证 checkpoint 响应丢失恢复；见 `docs/assets/hcd-word-layout-checkpoint-2026-10-27/http.json`。

之后增加显式布局感知日志版本 3：只能由已经核验的布局回执无损转换，原始回执保留在不可变父记录；版本 3 的正文请求须为协调器版本 6，待确认时禁止替换请求或基线、清除请求和降级，同时允许记录迟到输入。旧读取器拒绝新版本。实际本机 HTTP 测试在提交前持久化请求，并用真实原生版本记录核验 `hcdsave6` 签名；测试故意保留待确认记录。当前尚未实现版本 3 的正文回执确认、来源/图片重绑定及丢响应恢复，不能启用在线房间。

进一步增加停止房间的版本 3 正文确认：验证原生签名版本记录、原基线 root、规范内容和分区，再在隔离 Yjs 副本中重绑定来源、接纳新布局锚点，并使用既有图片确认逻辑处理已捕获意图；确认记录绑定其待处理请求和父日志。真实原生 HTTP 的无图片样例验证正文确认、重新加载签名日志和保存捕获后的页眉输入；篡改基线、布局、正文和多余图片回执被拒绝。调用方仍须提供鉴权后的不可变投影、图片和版本记录，并全程保证停止房间、权限、head 和租约；本次未验证含图片的版本 3 确认、正文提交断线重启，活动协调器和浏览器也未接通。

随后新增停止房间的 `recoverPreparedWordCheckpoint`：重新登记完整日志、核对权限和基线，使用原请求提交或精确重放，验证原生签名版本与各图片的固定版本读取，确认后再登记日志。隔离无图片 HTTP 样例在原生提交成功后切断 TCP，另一进程重放并确认，owner 登记成功后的响应再次切断，由第三进程从已确认日志接管；迟到页眉仍保留。活动房间、浏览器、含图片真实样例和跨主机未验收。无实际变更且没有新版本的响应尚不具备可确认回执，恢复会保留 pending 并停止，需后续补齐。

后续补充真实图片场景：隔离 DOCX 页眉图片在成员授权下上传替换资源，并与正文、纸张设置及图片尺寸一起保存；提交和 owner 登记各切断一次 TCP。不同进程恢复后，固定版本图片资源 hash 和已提交尺寸经原生接口、实际 DOCX 媒体字节及尺寸回读，捕获之后的再次缩放保留在未提交草稿中，HCDZ 校验通过。此样例没有将迟到缩放再次保存，也不代表活动房间、跨设备或跨主机完成；证据在 `docs/assets/hcd-word-checkpoint-image-recovery-2026-10-27/http.json`。

随后将上述迟到页眉与图片缩放从恢复草稿再次准备为版本 6 checkpoint，完成独立保存与签名回执确认；实际 DOCX 中回读迟到文字、替换资源和最终尺寸，离线 HCDZ 的最终投影与图片状态与原包一致，已确认图片意图清空。版本 3 日志进一步禁止未持有 checkpoint 回执时更改保存基线。此次由隔离测试协调请求和作者，活动多人协调器、无变更回执、页面及跨主机仍未完成；证据在 `docs/assets/hcd-word-checkpoint-late-save-2026-10-27/http.json`。

后续补充 `/2` 无变更 checkpoint 的签名回执，绑定文档、epoch、日志 hash、版本、root 和原生签名请求。恢复方重新提交同一请求，核验回执、规范内容及当前版本后确认，不生成新 revision；未确认的迟到内容仍保留。隔离本机测试在服务端返回无变更后切断 TCP，由另一个进程重试并恢复，验证篡改签名、root、epoch、日志 hash 和协议均被拒绝。该能力仍依赖可信协调器携带认证的请求/投影，活动房间、多人及浏览器尚未接通。

补充恢复后的作者归属：提取与现有协调器共用的草稿指纹，回执重绑定前后仅在原指纹已认证时更新该指纹，并仅退休已捕获的作者代次；更晚的同一作者或其他作者代次保留。未绑定的内容不因回执获得作者，保留原候选供审阅；引用作者账本根据已提交捕获更新。隔离原生 HTTP 的图片和双 TCP 中断样例分别验证不同作者、同一作者较新代次和未绑定状态；这些作者由测试构造，不能替代真实多人连接的鉴权验收。

## 2026-10-28：绑定完整 checkpoint 请求

原有版本签名验证只比较 checkpoint ID 和内容摘要，不能独立核对同摘要的作者、图片或其他请求字段。新增受租约和权限保护的只读 `/word/checkpoint-receipt`，在核对实际版本记录及其原生签名请求后，对完整传输 JSON 字节、文档、epoch、日志 hash、版本和 root 签名；停止房间恢复必须验证此回执才能确认草稿。无变更回执升级到 `/2`，同样绑定完整请求字节。服务和客户端使用实际发送的 UTF-8 JSON 字节，避免跨语言规范化数字和键排序差异。

旧的实验性版本 3 确认记录没有完整请求证明或使用无变更回执 `/1`，新读取器会拒绝它们；当前没有公开 `/2` 房间迁移或生产入口，旧实验日志需要单独迁移方案，不能直接启用。隔离本机真实 HTTP 验证了作者、区域、引用及图片字段改变后的拒绝、图片保存与两次 TCP 中断恢复，以及无变更请求断线恢复；不代表浏览器或活动多人验收。

接入活动协调器前还发现一个异步窗口：日志硬链接和目录同步期间，所有权或停止房间条件可能发生变化。日志追加现在在文件实际发布并同步后再次检查栅栏；若已失效，明确返回 `word-journal-published-fence-lost`，保留已发布记录并要求后继 owner 重读，不能把它当作未发生后重写旧父节点。定向测试模拟发布后栅栏失效，验证另一个日志读取器能取回请求和草稿、旧父节点不能再写。该检查不能阻止发布期间的在线输入，活动协调器仍需解决消息排队、图片意图合并及持续持久化，不能仅靠一次前置检查接入。


## 2026-10-28：发布后失去所有权的协调器冻结

现有区域保存协调器遇到 `word-journal-published-fence-lost` 时立即进入不可逆冻结状态，停止自动保存和上传；即使后续所有权检查意外再次成功，该实例也不能再执行本地变更、持久化或发起保存。已发布的日志仍保留，拥有者丢失时的恢复快照独立存放。专项在真实本机签名日志发布后注入栅栏失效，同时加入发布期间的迟到页眉输入：旧实例不能续写，恢复快照保留迟到内容，新实例检测到差异并要求恢复审阅。

这是现有 `/1` 协调器及本机测试的保护，不能代替活动 `/2` 房间的消息排队、图片意图合并、租约失效后的真实多人网络验收，也不表示页面设置已经开放。

## 2026-10-28：协作消息应用前的协调器门禁

区域房间在 `beforeSync` 中，在租约检查之后、应用 Yjs 数据之前还检查协调器实例是否已冻结或释放；缺少协调器也拒绝同步。这样，即使消息开始处理时通过了异步成员授权，只要应用前协调器已经冻结，就不能继续通过该入口。正常的租约、只读与协议检查仍保留。

## 链接前一节的影响规划基础

新增独立 story 的只读影响规划：针对尚无直接绑定的节和指定变体，以精确布局 hash 和显式预期继承 story（可为 null）校验当前状态，列出从该节到下一直接绑定之前受影响的全部节。首节或前文缺少同变体时明确报告空来源；默认、首页、偶数页及页眉页脚不互相替代。规划不创建 story 或内容，也不冻结房间；复制继承内容仍须在受保护的协作快照中处理，并分配独立节点与资源身份，完成事务、恢复、导出及界面后才能开放。

进一步增加布局候选规划：在上述前置条件成立后，接收新的 story 身份及来源部件，拒绝与现有节、story 身份或 story 部件冲突、类型不匹配和非法路径；只构造包含新直接绑定和新 story 的候选布局，并重新校验。它不会写入文档、创建空内容或复制继承内容；提交方仍需核对整个文档的资源与节点身份冲突，并原子生成新的区域内容与来源映射。图片、业务节点、人员引用、域及附件不得仅复制原身份后当作新区域。

内容复制增加独立准备函数：清除嵌套文本的旧来源节点 ID，要求人员引用分配新 occurrence ID，并要求调用者提供业务节点复制策略及新实例 ID；拒绝与调用方提供的既有身份、原内容或本次其他新身份冲突。人员目标与显示快照保留，扩展复制结果按现有 schema 校验；调用方必须提供完整文档的身份集合、核对扩展策略及资源可用性。该函数只处理可编辑的结构内容，不处理只读原始块、图片、域和 OOXML 源部件，不写入版本或建立权限，不代表完整页眉复制已可用。

新增版本入口从指定不可变 revision 的完整编辑投影收集现有引用和扩展身份，核对布局 hash 和来源 story，再准备该 story 的内容；来源含只读块、批注或修订时明确拒绝，不会悄悄省略。调用者仍须处理 revision 与活动房间之间的并发/未保存输入、业务扩展策略及资源，不可将准备结果直接视为已提交。投影级测试覆盖来源和 hash 失配、只读内容及批注；当前尚无内容复制事务、真实 DOCX 往返或浏览器入口。

版本入口还读取该版本的独立标注集合：如果标注落在来源 story 的块或文本节点上，拒绝准备副本，避免静默丢失；其他区域的标注不影响。标注复制和身份重建仍需后续事务支持。

实际 DOCX 导入测试在页眉文本上添加节点标注生成 r2，确认 r2 的复制准备被拒绝而未带该标注的历史 r1 仍可准备；同时核对不同节点上的标注不会误判为来源标注。该测试不提交 story 结构变更。

版本入口现要求调用方传入经过源文件摘要核验的补充字体样式，与编辑器投影使用同一字体解析路径；空样式不应被理解为已经核验源文件。使用含页眉图片的隔离 DOCX 实际导入并投影，测试核对可编辑 story 的文字和字体信息、来源身份清除、含图片的只读 story 被拒绝以及规范版本不变。此为复制准备的文件输入测试，并没有生成新 DOCX 或验证外部 Office 显示。

新增只读 `plan_flow_story_link`：要求完整布局摘要和当前直接绑定精确匹配，首节、已链接或错误类型/变体拒绝；按同类型、同变体追溯前节，列出直到下一个直接绑定为止受到内容变化影响的节。前节没有该变体时明确返回空内容；被替换的 story 仍保留在布局目录。首页和奇偶页变体独立处理，即使该变体当前未启用也不混用默认页。此规划不读取内容、不修改文档和协作房间，也不授予覆盖他人修改的权限。

4 项原生单元测试覆盖后续继承范围、原布局和 story 保留、旧摘要/旧绑定、首节、空继承及首页变体。尚未接入持久事务、对被替换 story 的内容和迟到协作修改做确认、撤销、恢复、导出或界面；复制独立 story 和创建缺失区域仍待实现，不能称作用户可用的“链接前一节”。

后续增加独立的布局转换验证：从两个布局重建唯一的直接绑定移除，再重新规划并逐项比较完整布局；混入纸张变化、多个绑定变化、删除原 story 等均拒绝。5 项专项测试通过。验证范围仅为布局对象，不验证正文块、附件、作者或签名回执；原有 model 1 历史仍拒绝绑定变化，不能绕过现有门禁。

### 源文件引用变换基础

新增独立的受限流式 XML 变换器：对调用方已核验的节序号、页眉/页脚变体和关系 ID，只移除指定的自闭合直接引用，保留其他事件和嵌套的历史节属性。节数、位置、ID、重复引用、目标上的未知属性或非自闭合形式不符合预期时拒绝；限制源 XML 字节、事件数和嵌套深度。调用方必须使用可丢弃的暂存输出，发生错误时不得发布部分文件。测试覆盖普通和 Strict 命名空间、不同前缀、冲突及不支持的嵌套；从含图片的真实样本读取 `document.xml` 后，输出与原 XML 仅差目标引用的字节。6 项专项测试通过，新增最后两项前的 `hcd-docx` 全量 65 项通过。

该变换器只处理 XML 引用；源格式导出还必须核验固定版本的源摘要、节映射和关系 ID，确认其他内容未变化后安全写入源包。单独 XML 测试不能证明完整 DOCX 包保真或 Word/WPS 显示结果。

补充受限的只读源核验：在写锁下复制并验证指定历史版本，将原 DOCX 限量复制到私有暂存并核对长度及 SHA-256，再独立导入源文件并投影区域。当前接受导入、区域投影、连续链接的版本序列（最多 4096 次）；逐项比较正文和 story 块、源节点映射、批注、样式及非布局资源，并逐次核对历史转换、原始节布局和关系 ID。成功结果保留两个暂存目录供后续处理，调用方必须始终使用其中的固定输入。源不匹配、样式变动或夹杂其他历史操作会拒绝。

上述核验已接入有源 DOCX 导出：从核验通过的源快照重写选中的节引用，其他 ZIP 条目原样复制，候选包验证通过后以不覆盖已有目标的方式发布。服务端导出选项对这些版本运行相同核验，源缺失或核验失败继续显示不可用。测试比较了其他包部件的字节、连续两次链接与历史版本重新导入后的绑定、已有目标保护，以及样式变化和混合历史时不产生目标文件；仍未做 Word/WPS 桌面打开验收。此能力不覆盖链接前后的正文或其他结构修改、创建或取消链接，也不开放在线协作事务。完整原生协作与更多源格式路径继续待实现。

导出预检还会对固定源文件执行一次不落盘的 XML 重写检查；对于导入器可读取但重写器不能安全移除的未知引用属性或不支持的结构，提前报告不可用。合成 DOCX 测试确认这类属性不会被误报为可导出，实际导出也不生成文件。预检成功不保证后续设备空间、权限或源文件仍可用，正式导出仍会重新核验。

后续增加源关系解析规划：从调用方提供的源包读取并重建布局，将其与事务前布局逐项比对，再从原节属性提取关系 ID，并核对其指向的部件和页眉/页脚类型；完整布局转换也再次验证。测试用真实合成源包定位第二节偶数页眉的 `he`，并验证源布局或事务外纸张变化均被拒绝；7 项引用变换专项通过。调用方仍须先提供经过摘要验证的不可变源快照，并检查固定版本正文、样式、图片和历史；此规划不授权发布文件，也还未接入导出。

### 设备备份文件大小与兼容（后续更新）

区域 Word 的设备备份现导出 `hcd-word-device/5`：文档快照及待归档附件使用 Base64，避免大二进制资源被 JSON 数字数组显著放大；图片和未复核的本地更新继续单独保存。检查入口兼容 `/2`、`/3`、`/4` 和 `/5`，统一限制文件 UTF-8 大小不超过 384 MiB；导出也检查同一限制，超限时保留本地草稿并报告失败。旧版超过该限制的备份仍无法在此入口读取。检查时对 Base64 分块解码并校验分块边界，避免构造整份解码字符串；JSON 解析和输出二进制本身仍需要内存。8 MiB 待归档附件已在自动化测试中验证导出与检查往返，不能据此推断不同设备在上限附近的内存表现。

检查入口目前只提供隔离检查和提取附件，作用域哈希是文件声明而非身份认证；尚不支持将备份直接合并回文档或跨设备自动恢复。保存与恢复的其他格式差异仍需继续处理。

区域 Word 的“查看设备备份”现可在隔离模型中预览快照文字，按段落换行并最多显示 4000 个字符；快照可能包含其他成员内容，不证明作者，也不会写入当前房间。布局不匹配或快照无法投影时显示无法预览，仍保留附件提取入口。专项测试核对隔离、截断和布局不匹配；隔离浏览器用合成区域备份验证正文与页眉页脚文字显示，见[预览截图](../assets/hcd-word-device-preview-2026-10-28/preview.png)。此功能仍不支持将设备备份直接合并或恢复，图片和非文本节点不由文字预览完整表达。

设备备份文字预览进一步按节正文以及独立页眉、页脚区域分组；页眉/页脚数字仅表示快照中的区域顺序，并不声称该区域专属于某一节。总预览仍限制为 4000 个 UTF-16 单位，截断不会拆开代理对。区域模型与备份专项共 36 项通过，独立区域 Word 浏览器检查显示两节正文和各页眉页脚区域，[分区预览截图](../assets/hcd-word-device-preview-2026-10-28/regions.png)。非文字对象和布局外的旧快照仍不能通过此预览完整判断。

设备备份检查增加“下载备份文字”：在可投影的相同布局下生成包含正文、页眉页脚区域标签和可读文本的 UTF-8 文件；超过 8 Mi UTF-16 单位时拒绝生成，避免静默截断。文件仅供文字取回，图片、格式、域及交互节点可能缺失，原备份必须保留；与当前协作房间没有合并。自动化测试检查超过 4000 字的完整输出、区域标签、超限拒绝和当前房间不变；隔离浏览器验证入口与格式损失说明，应用内浏览器未提供下载文件的可靠路径，尚未验证实际下载文件回读。[入口截图](../assets/hcd-word-device-preview-2026-10-28/text-download.png)。

文字提取补充保留段内手动换行，同时继续使用节点的文本降级表示人员提及及自定义行内节点。区域专项测试覆盖换行和 `@Alice 王`；这仍是纯文本降级，不恢复交互或完整排版。Chrome 对文件选择器的自动化受扩展文件访问权限限制，本次没有取得真实浏览器下载文件回读。

区域 Word 设备草稿恢复补充异步竞态保护：比较后在持久化本机恢复更新及绑定日志的两个等待点结束时，重新核对连接、权限状态、所选比较和房间更新代次；期间有同伴更改则冻结旧房间并提示重新连接比较，不应用旧比较结果，也不标记已审阅。本机日志保留供重连后继续检查。受控测试分别在日志追加、日志绑定和选择保留副本时插入同伴页眉修改，验证正文未被旧恢复改写，重连比较保留同伴和本机内容；真实浏览器网络与多设备并发仍待验收。

选择保留设备草稿时，审阅标记写入也受房间变化和会话取消保护：等待本机日志落盘后重新核对比较，标记事务未提交前如收到同伴更新或连接变化则中止，保留未审阅草稿并要求重新比较。受控 IndexedDB 与房间测试分别覆盖正在写入标记时的取消、同伴更新和重新连接；不声称已经提交的事务可以撤销，真实浏览器并发仍需验收。

区域 Word 恢复时，已在应用前持久化的恢复更新不再被文档监听器重复追加；其他本机和同伴更新仍照常记录。专项测试核对应用后只有一份新的本机恢复记录，并覆盖并发修改、重连和备份。此优化不解除单条 8 MiB、本机总量 64 MiB 或 sidecar WebSocket 帧 1 MiB 限制；大型更新合并、传输分片和长文容量仍需专项设计与验收。

区域 Word 从设备恢复到协作房间前，现先在隔离模型中计算实际产生的 Yjs 更新大小；超过 sidecar 1 MiB 帧限制（预留 8 KiB 帧头空间）时不修改房间或覆盖本机记录，并在比较页说明可下载备份。帧限制与 sidecar 使用共享常量。受控测试以超过 1 MiB 的正文更新验证拒绝、房间不变和本机日志保留；当时尚未支持大更新传输；后续 HTTP 恢复见下文。初次全量同步和普通编辑的大消息仍未覆盖，不能据此宣称长文恢复已完成。

恢复计划持久化并发送隔离模型中相对于当前房间实际产生的增量，而非重复携带房间已包含的大段历史；仍先用完整候选执行区域与来源守卫。受控测试核对已同步大段内容只剩小增量，以及纯删除更新不会丢失。当时超过安全帧大小的真实增量无法传输；后续 HTTP 恢复见下文。上述测试不证明生产大文档吞吐。

大更新分片目前只有独立编解码基础：单次最多 8 MiB，按 256 KiB 分片，接收端检查长度和 SHA-256，允许乱序及相同分片重传，拒绝不一致的重复分片，并在完整重组后才交给调用方。专项测试以两个合法区域共超过 1 MiB 的更新验证重组后通过区域守卫、一次应用；也检查缺片、损坏和取消。分片组件尚未接入；后续选择有界 HTTP 正文传输完整更新，不依赖分片组件，具体边界见下文。

区域 Word 超过 WebSocket 安全帧、但不超过 8 MiB 的设备恢复增量现走独立 HTTP 路径：读取正文有 45 秒限制，进程最多同时处理两个请求，校验更新摘要、当前写成员、协作代次及房间快照，重新验证身份和所有权后通过区域守卫一次性应用，并在协作日志持久化后应答。客户端先保留本机更新，无论收到成功还是结果不明确，都断开旧房间并要求重新连接核对；成功应答是协作日志确认，不是规范版本保存回执。权限撤销、错误摘要、过期快照、日志写入失败及旧请求重复发送由受控测试覆盖。分片组件仍未使用；超过 8 MiB 的单次恢复、普通编辑或初次同步的超大消息仍不支持此路径。

隔离浏览器用两节各 60 万字符的合成草稿验证大更新发送、日志确认和原成员重新连接；另一成员连接后，服务端生成 r2，实际导出 DOCX 回读包含两段完整内容。但本轮长文处理期间所有权租约超时，第二成员界面未收到保存成功确认，提示重新连接；因此仍不能宣称完整的长文协作与保存体验已验收。性能、租约续期、结果不明确后的真实网络重试、跨物理设备和生产多实例均需继续处理。[证据](../assets/hcd-word-large-recovery-2026-10-28/evidence.json)。

后续定位到新建空文本载体时逐字符构建和格式化导致初始化阻塞；现按连续文本和格式批量初始化，已存在载体仍沿用保留协同锚点的编辑逻辑。在同一个隔离样本上，带计时的区域模型初始化从约 13 秒降至约 0.27 秒；另一成员重新打开内容、编辑并看到 r3 保存确认，导出 DOCX 回读确认两段大文本及编辑标记。该数据是单次本机测量，并非吞吐基准；普通大编辑、初次同步帧限制、真实网络故障及跨设备生产环境仍需单独验收。[保存截图](../assets/hcd-word-large-init-2026-10-28/saved-r3.png)、[证据](../assets/hcd-word-large-init-2026-10-28/evidence.json)。

行内内容的纯校验也改为按文本段、格式和行内节点检查，不再为每个字符分配临时 token；需要精确协同位置的实际编辑仍使用原有逐字符匹配，不改变锚点语义。受控测试覆盖长文本、表情、格式、非法节点、行内引用、拆分/合并与协同更新；本机对单个 60 万字符文本段连续执行 20 次纯校验约 1 毫秒，仅是局部测量，不代表整篇文档输入延迟或正文懒加载已经完成。

区域 Word 启动时，如果设备草稿已经包含在当前协作房间中，只有当前房间内容和图片摘要均匹配已保存回执，才自动推进设备草稿的审阅水位；房间仍有未保存修改时允许继续编辑，但保留本机未审阅记录。检查和写入期间如果房间、回执或连接变化，会取消尚未提交的标记并重新检查。受控 IndexedDB 测试模拟房间已有本机文字但服务端尚未保存，随后房间退回旧状态，验证重新打开时仍能发现并比较本机文字；另一项测试覆盖写入标记前收到未保存回执。此测试不是断电、真实服务崩溃或跨设备验收，已提交的本机标记也无法通过取消回滚。

区域 Word 备份检查页增加“在本机准备恢复”：仅允许声明的服务、用户、文档和代次与当前会话一致、且当前会话可写的 `/4`、`/5` 备份。经解析和资源摘要核验后，文字快照、本机更新及待处理图片和附件在一个 IndexedDB 事务中暂存，随后重新连接并走已有草稿比较；图片和附件仍需分别检查处理，附件重新回到待归档状态。文件身份和本机更新标记只是声明，不授予服务端权限，最终文字恢复仍需当前房间守卫；重复相同文件不会重新创建任务，并提示已暂存。受控测试覆盖原子冲突、重复导入、文件内容保存，以及重连后仅恢复本机更新、不提交备份中同伴的修改。单条设备日志仍限 8 MiB、日志总量 64 MiB，超限时无法导入；大更新的完整稳定性验收、旧代次迁移、重复备份主动重新审阅和跨物理设备验收尚未完成，原文件应保留；隔离浏览器验证见下文。

补充隔离浏览器验收：用独立 Chrome 配置连接本机原生及协作服务，以应用代码生成包含本机文字和待处理附件的合成备份，经文件选择导入、重新连接并确认文字比较后恢复。附件在“待处理节点文件”中显示为需要恢复；测试显式取消该文件选择后保存文档，导出的 DOCX 回读包含恢复文字。再次选择相同备份显示已暂存提示。[文字比较](../assets/hcd-word-device-import-browser-2026-10-28/comparison.png)、[待处理附件](../assets/hcd-word-device-import-browser-2026-10-28/pending-attachment.png)及[证据范围](../assets/hcd-word-device-import-browser-2026-10-28/evidence.json)。这使用同一设备、同一来源及合成文件；未在应用内浏览器、不同物理设备或断电环境验收，也未把附件实际关联到节点。

进一步使用包含 `example.card` 节点及其待处理文本附件的合成备份，在隔离 Chrome 中导入并恢复节点，用户显式定位节点、重新归档并确认关联后保存 r2。[已关联截图](../assets/hcd-word-device-import-resource-2026-10-28/saved.png)。导出的 HCDZ 解包并通过原生校验，离线编辑投影包含恢复文字、附件名称和 SHA-256，归档包含摘要匹配的附件原始字节；DOCX 回读包含正文和节点降级文字，但不包含这个普通文本附件的原始字节。测试为同机同源、合成节点和附件，未验证不同物理设备、断电或应用内浏览器；[证据范围](../assets/hcd-word-device-import-resource-2026-10-28/evidence.json)。

## 活动房间的纸张设置协调基础

新增停房协调器：阻止新数据包并等待已准入操作完成，排空并持久化房间后冻结共享状态，重新鉴权，记录绑定当前版本和布局的精确请求，最后提交原生事务并核对签名回执。请求可能已经发布后发生错误时保留门禁和旧房间的冻结状态，重试必须使用相同请求；授权在准备前被拒绝则释放门禁。已完成旧布局回执升级后的 version 3 日志也可以通过受控准备操作进入下一次布局事务，拒绝通过普通写入伪造该迁移。

受控测试使用实际协调器和日志、模拟原生服务：已准入成员编辑在关门前完成并保留，模拟原生提交后丢失响应，重试只核对回执而不产生第二次提交；重开日志验证后续布局请求的精确准备和拒绝伪造。这个协调器尚未接入生产侧车、兼容新布局的房间启动或纸张设置界面；无真实双 WebSocket、浏览器或原生 DOCX 验收，不能算作纸张设置已对用户开放。

补充隔离原生联调：真实 `WordSaveCoordinator` 与本机 owner 租约执行布局停房，模拟一个已准入的成员操作在门禁关闭后完成；真实原生服务提交 r8 后，本机 TCP 代理丢弃回执，协调器保持旧房间冻结并以原请求获取签名回执，没有第二次提交。重新读取私有日志保留该成员的草稿；语义 DOCX 回读纸张宽度及原生包校验通过。[证据](../assets/hcd-word-layout-live-2026-10-28/native.json)，复现 `python3 scripts/hcd-word-layout-live-check.py`。初始日志使用该隔离样本的既有投影构造并登记，成员数据包由测试直接驱动；这不是生产侧车迁移、真实 WebSocket 多成员或浏览器编辑，也不证明草稿已进入导出的规范版本。新布局房间启动与版本 6 正文保存接线仍未完成。

纸张设置协调补充真实双 WebSocket 客户端与本机原生服务验证：测试 Hocuspocus 房间使用真实区域守卫、所有权租约和保存协调器。Alice 的文字先同步；Bob 的数据包在准入后被暂挂，布局事务关闭门禁后拒绝 Alice 的后续数据包，再放行并持久化 Bob 已准入的修改。原生提交 r8 后通过 TCP 代理丢弃响应；协调器用同一请求核对签名回执，未重复提交，旧房间仍冻结，私有日志保留 Bob 的修改。导出 DOCX 回读纸张宽度，原生包校验通过。[证据](../assets/hcd-word-layout-live-2026-10-28/websocket.json)，复现 `python3 scripts/hcd-word-layout-live-check.py --ws`。房间和成员认证均为隔离测试，初始日志按样本构造；不是生产侧车、浏览器、多设备、断电或新房间重建验收，也不证明未保存草稿已进入 DOCX。

修正干净文档无法准备纸张设置的问题：布局请求单独记录操作者，不要求该成员先成为正文草稿作者，也不会因此把布局操作者加入未保存正文的作者列表。停房协调器在异步鉴权前复制请求，将单独的请求副本交给宿主进行该具体成员的身份与权限核验，避免等待期间调用方或鉴权函数改写已核验内容；原生提交仍检查布局作者的写入权限。隔离原生服务对没有正文草稿作者的文档提交纸张宽度、模拟丢失响应并恢复签名回执，DOCX 宽度回读成功，正文作者列表保持为空；[证据](../assets/hcd-word-layout-live-2026-10-28/clean.json)，复现 `python3 scripts/hcd-word-layout-live-check.py --clean`。测试使用受控成员和隔离服务，宿主实际身份认证及页面入口仍未接入。
