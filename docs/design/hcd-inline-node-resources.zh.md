# 行内容器属性审阅与设备文件恢复（2026-10-27）

本轮补齐主编辑页模型 3 接入前缺失的属性与附件组件。普通、区域文档继续使用严格的原有模型；行内容器显式使用独立的文件日志和解析器。没有移除主编辑页当前的模型保护提示，也没有把独立宿主的验收当作完整主页面验收。

## 文件和属性链路

`WordNodeResourceDraft`、存储元数据与任务客户端改为按 payload 类型复用。原来的 `WordNodeResourceClient` 保持普通节点/区域模型；`InlineNodeResourceClient` 使用模型 3 的解析器，同时允许同一文档内的普通原子与块节点。两者共用原始字节先落盘、归档、正常命令关联、落盘确认和取消终态的状态机，没有另写一套弱化的上传流程。

行内容器文件日志由端点、成员、文档、epoch、协议决定，使用 `-inlinecontainers1-nodefiles1`，不含 token，不附着在某个正文恢复副本之后。`NodeResourceJournal.openInline` 显式打开它，普通 `open` 不能采用这个命名空间。旧日志和客户端继续拒绝 envelope 3；行内日志拒绝 Word story 区域地址。仅知道某个 occurrence ID 不足以关联，确认结果还必须保留正确的节点模型、类型和真实资源描述。普通 v1 节点通过正常命令升到支持资源的 v2 仍然允许。

重开只读取任务，不自动上传、不自动关联；`ready` 在上传前和命令前重新检查。过期选区、权限失效或正文设备写入失败均保留已归档选择，不能用资源上传响应代替文档保存回执。另一窗口取消后，迟到 staging 与同包重试不能复活原文件选择。新 hook `useInlineNodeResources` 与旧 hook 共用 effect-owned 生命周期、广播刷新和错误门禁，调用方仍须传入协商后的 Session 和资源服务。

`ExtensionProperties` 复用同一个按模型检查的属性组件，新增内部 `InlineContainerProperties`。属性、迁移预览、显式确认、资源下载/移除和冲突选择均校验命令实际返回的 envelope，不把模型 3 断言为旧 payload。文件任务面板也按目标模型校验，并继续要求定位、核对当前内容后确认关联。

新增 `useInlineContainerEdits`，与普通属性 hook 共用受控订阅和派生 materialization。它同时观察 intent 与 materialized 映射；即使当前可见属性值没变，新到的冲突候选也能刷新面板。只读宿主只订阅，不发布派生数据。冲突总览和字段面板复用类型明确的候选组，保留原本的翻译和权限逻辑。

## 实际验证

证据目录：`docs/assets/hcd-inline-node-files-2026-10-27/`。

**代码与构建**：新增 8 项模型/设备测试，43 项文件与恢复专项、完整 **1050 项前端测试**通过；TypeScript、独立与嵌入构建通过。旧测试样例原先将资源直接放进不支持资源的 v1 envelope，现按真实命令结果使用 v2，不放松生产校验。专项覆盖模型隔离、原始字节重开、不自动上传、普通节点兼容、区域地址拒绝、错模型确认、命令/权限失败保留、跨窗口取消及设备落盘失败。

**真实浏览器**：独立 React StrictMode 双编辑器使用真实浏览器 IndexedDB。通过原生文件选择器选取测试文本文件，刷新后任务仍存在、未选择目标时关联按钮不可用。定位后先把属性从“业务字段”改成“设备恢复字段”，面板同时显示原目标与当前目标，再显式关联。任务清除后实际下载文件，与原始字节精确一致；正文不变。属性面板另验证版本 1→2 的预览与确认，原正文和附件保留，旧 codec 的同伴视图转只读。

浏览器附件传输使用本页内存 Blob 测试适配器，刷新后只有 IndexedDB 保留原始字节；确认时重新归档。因此这里证明真实设备日志和面板交互，不宣称主编辑页或真实网络上传。分别断开两份编辑器的本机同步、对同一字段输入两个不同值，再合并，双方字段面板都保留两个候选；可见胜出值未改变的一侧也刷新出冲突。正常命令确认选择后冲突消失，两份正文仍为“文件目标正文😀”，错误区为空。测试桥接与文件控制仅在 fixture 中。

**真实 Socket / 原生服务**：使用生产 `sidecar.ts`、原生 HTTP 及严格的 inline1 Session 归档新附件，保留未完成任务后重启进程。新进程将私有任务字节导入独立的 fake-indexeddb 引擎，不自动上传；显式恢复通过生产 `prepareInlineContainerTransaction('node.resources')` 关联，写入真实协作房间并保存至 r11，正文原字符身份保持。实际读取原生附件字节、四格式导出与 HCDZ unpack/validate 通过；离线已保存版本中的附件与原始文件字节及哈希一致，原始 r8 归档未改变。这是进程重启与客户端文件导入测试，不冒充浏览器恢复包 UI 或跨设备全部任务完成。


## 后续接入边界

主编辑页仍须将模型协商后的 Session、完整 schema/结构绑定/递归 snapshot、属性 hook/选择、文件 hook、删除审阅、保存状态和恢复比较一起接通，再移除兼容宿主提示。当前旧 `SemanticRecoveryTransfer` 编辑页恢复包入口仍只接普通结构模型，不能把已有内部模型 3 归档支持当作行内文件恢复确认 UI 已完成。

含容器的块操作、跨文档附件传输、容器内部 AI、长文分页/容量、Word 追加基础能力与原七阶段开放要求继续实施。当前浏览器还会在部分属性远端投影后将整节点选择映射成文本选区，需要重新点选节点；主页面接入时须处理此选择保持，不能据此宣称全部选区交互完成。管理平台和真实提醒投递继续后置，整体目标未完成。
