# Word 正常页面设置与原请求恢复

后续页面原请求已迁入 IndexedDB，关闭重开、旧标签页队列迁移与取消恢复的当前状态见[页面设备请求](hcd-word-page-device.zh.md)。下文保留该批历史边界。

日期：2026-10-30。范围是显式启用的区域 Word `hcd-word-regions/2`，不是所有旧 Word 文档的自动升级。管理平台和提醒发送不实施。

## 正常操作

“布局 → 页面设置”进入现有纸张设置表单。用户选择节或全文范围，调整纸张、方向和页边距，先核对逐字段前后值，再应用。提交前核对当前布局摘要与版本，完成正文、图片、设备文件任务的保存门禁；基准变化时要求重新核对，不按旧预览提交。

完整请求在发送之前写入并回读当前标签页的 sessionStorage，包括原事务编号、原基准版本、操作人、布局摘要、字段变化及节号。记录按服务、文档、账号、epoch 和协议隔离，不存 token、正文或附件。存储失败不能退回到未持久化的页面提交。

请求状态面板在区域编辑器会话之外保留，因此正常房间替换不会销毁原请求。成功时显示已确认版本，用户关闭后才清除记录；未知结果只允许核对、重试同一次请求，或检查并取消尚未准备的请求。“检查中断的 Word 保存”可暂时收起面板，保留返回请求的提示，避免遮住签名恢复工具。

同一页面事务后，两名写成员与只读成员自动建立新传输，保留原有个人内容历史和设备日志；页面字段自身的撤销仍未实现。正常流程不要求刷新，进程重启验收则明确重新加载各成员页面，不能混称自动跨进程重连。

## 核对、重试与取消

- 刷新后读取完整原请求，不自动提交。用户重试仍使用相同编号和相同内容；取消操作也先持久记录，刷新后不能误重放为应用。
- 进程内状态不存在不能证明未提交。稳定房间可用后，`word-active-layout-check` 读取原生不可变版本与布局签名回执，核验原请求和当前 owner 已验证的日志祖先，不重新加载活动房间共用的日志以免改变保存代次；只确认结果，不重提、不安装房间、不追加日志。尚未稳定准入的房间仍须先经过签名恢复。
- 首次取消排空并暂停成员，在受租约及事务门禁保护的房间中核对完整签名历史；仅未准备的编号可写入签名取消标记并由原生服务封存。已准备或已提交的事务不能通过取消丢弃。
- 已有签名取消标记的重试在普通请求门禁内重新核验当前权限与原生编号封存，不再要求在线成员重新停写。原生响应丢失时保留同一取消身份。
- 延迟应用请求在成员停写前检查签名取消标记，进入排他事务后再次检查，避免重放造成无意义暂停或绕过取消。
- 进程内保留最多 128 项独立的已完成请求结果，按文档、epoch 和编号索引。后续被拒绝的请求或其他轮次不会立即挤掉最近完成的确认，仍在重绑的成员可以查询原轮次。缓存不是持久权威；进程丢失或容量淘汰仍依赖签名核验和恢复。

## 实际验证

前端完整 1874 项测试、32 项页面请求/阶段/取消/回执专项、TypeScript 及独立版/嵌入版构建通过。构建仍有第三方 `use client`、大包及混合静态/动态导入提示；没有重新构建原生二进制或重跑 Rust 全工作区和 Clippy。

隔离 Chrome、实际本机原生服务和侧车的三个流程：

1. 正常操作区预览、核对和应用；两名写成员及只读成员不刷新自动恢复。自己的撤销/重做保留同段落协作者输入，设备备份下载、刷新重开及 DOCX/HCDZ 回读通过。[正常流程证据](../assets/hcd-word-page-controls-2026-10-30/browser.json)、[文件回读](../assets/hcd-word-page-controls-2026-10-30/file-readback.json)。
2. 服务端成功后丢弃浏览器响应，刷新后原请求完全一致，重试不重复追加页面版本；侧车进程重启后以原生签名回执只读确认。篡改请求和只读身份被拒绝，三角色最终收到协作者续存版本。[丢响应证据](../assets/hcd-word-page-retry-2026-10-30/lost/browser.json)、[文件回读](../assets/hcd-word-page-retry-2026-10-30/lost/file-readback.json)。
3. 应用请求在发送前被阻断，取消不追加版本；进程重启后、补回内存缓存之前，延迟原请求返回 `word-topology-cancelled`。同一取消可再次确认；新编号的页面调整成功，旧编号仍拒绝；三角色继续更新至协作者的新保存版本。[取消证据](../assets/hcd-word-page-retry-2026-10-30/cancel/browser.json)、[文件回读](../assets/hcd-word-page-retry-2026-10-30/cancel/file-readback.json)。

文件验证核对真实 DOCX 正文和纸张宽度，页眉页脚未变，固定所选 revision 打包 HCDZ，解包后检查版本及投影一致。测试使用合成文档和受控 CDP 网络故障，不能替代真实网络中断、真实输入法、不同物理设备、Word/WPS 外观、多实例或生产验收。

开发中保留了失败记录：首次丢响应测试等待了错误文案；取消重放先检查成员状态、取消再次确认依赖成员停写、已完成轮次被后来请求挤掉，以及只读回执查询重载活动日志干扰并发保存的问题分别修正。最终流程与早期失败分目录存放；完整来源摘要和命令见[验证清单](../assets/hcd-word-page-controls-2026-10-30/validation.json)。

## 复现

在已有匹配原生二进制、编辑器及 XLSX 依赖的环境中，从仓库根执行：

```bash
python3 scripts/hcd-word-layout-browser.py --clean --allow-restart
# 使用上一步打印的隔离 root；依次运行，等待每一步退出。
node scripts/hcd-word-page-controls-browser.mjs ROOT OUTPUT_NORMAL
python3 scripts/hcd-word-live-rebind-files.py ROOT OUTPUT_NORMAL
node scripts/hcd-word-page-retry-browser.mjs ROOT OUTPUT_LOST lost
python3 scripts/hcd-word-page-retry-files.py ROOT OUTPUT_LOST
node scripts/hcd-word-page-retry-browser.mjs ROOT OUTPUT_CANCEL cancel
python3 scripts/hcd-word-page-retry-files.py ROOT OUTPUT_CANCEL
```

`--allow-restart` 仅让隔离测试父进程接受自己目录中的重启信号，默认关闭，不是产品 HTTP 操作。配置凭证只在私有 fixture 中使用，不进入验证归档。

## 保持开放

sessionStorage 只覆盖当前标签页刷新，不保证关闭标签页、清理存储或跨设备后的完整请求恢复。缓存、设备草稿和签名服务日志不是同一种保障。旧 epoch、旧协议和旧文档不自动迁移；两个区域开关仍默认关闭。

正常协作入口的 story 创建/链接、页面字段自身历史、精确分页和跨节连续排版、页码/计算域、自动目录及正文分段加载继续。此增量不改变 Excel、PPT、PDF、字体/国际化、扩展复杂往返、真实 AI、跨设备及多实例的剩余范围。
