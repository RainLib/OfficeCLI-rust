## 交付顺序

```text
A 保存/协同底座 → B 统一命令 → C Notion 式交互
       ↓ 身份/权限                    ↓
       D 服务端引用契约 + 版本化节点 → @ 人员端到端 + 自定义内容 SDK
                                     ↓
                     E 通用 AI 接口 → 建议改写 → 可选自动补全
```

字体、国际化、无障碍、导出和长文性能是各阶段的验收条件，不留到最后补。PPT/PDF/Word 共享基础协议，各自明确编辑能力范围；不宣称 fixed-layout 已拥有 Word 相同的逐字协同。管理平台、字体运营后台、插件市场、提醒渠道另行安排。

## D：默认 @、服务端人员与关联模型

### 默认入口与分期

将 `@` 作为默认内置入口，首批端到端交付人员提及；文档和日期作为同一引用系统的类型扩展。没有人员服务配置时显示明确不可用/空状态，不把在线头像列表伪装为组织人员库。

| 类型 | 行为 | 分期 |
|---|---|---|
| `@人员` | 无查询时返回当前用户可见的推荐/最近/文档成员；输入姓名筛选；同名显示最小必要的区分信息 | 首批 |
| `@文档/页面` | 搜索当前用户可读的文档，保存稳定引用，支持打开/定位 | 预留同一接口，后续启用 |
| `@日期`、今天/明天 | 保存实际日期或带时区的时间值，静态显示；日期与提醒分离 | 预留，后续启用；按宿主/用户时区解析 |
| `@团队/@所有人` | 有权限和范围限制，未来涉及批量关联与提醒 | 默认不启用，不将其当普通人员 id |
| 自定义引用 | 客户、任务、项目等由宿主注册候选源和解析器 | D 的扩展协议稳定后接入 |

输入邮箱或 URL 中的 `@` 不应任意弹菜单；触发边界可配置，代码块/链接等不适合位置按能力禁用。异步候选支持有界分页、加载/失败/空状态、取消与过期响应丢弃。选择结果以一次事务插入行内原子节点，Backspace/方向键/复制粘贴有明确行为；Esc 保留原输入。

### 身份与权限边界

当前服务 token 含 doc/scope/sub/name/exp，尚无完整组织成员目录。`sub` 是人员关联的基础，displayName、浏览器 clientId、在线状态都不能作为稳定人员主键。组织/工作区范围须由服务端可信会话或配置的宿主访问策略确定，不能信任请求参数自行指定 tenant。

人员目录与文档在线状态分开：`PeopleDirectory` 提供人员身份/搜索，`DocumentAccessPolicy` 决定候选可见与可提及范围，`Presence` 只补充在线标记。默认只推荐允许被当前用户提及且有适当文档访问关系的成员。不自动邀请、不自动分享；若未来允许提及非成员，必须单独展示其访问状态，并通过独立授权的分享流程处理。

人员被禁用/删除后，已保存显示快照仍可读，解析状态显示“已失效”或受限；不得把同名新人解析为原人。改名不改变 targetId；正文离线快照和当前在线显示分别有规则，不能因展示名刷新不断制造正文 revision。对无权解析的引用只返回受限占位，不泄露邮箱、部门、文档标题、候选数量或私有头像地址。

### 服务端接口契约（D1/D2 已接入本机首版，D 阶段未全部验收）

| 接口/服务 | 输入输出 | 约束 |
|---|---|---|
| `GET /v1/documents/{id}/mention-options?kind=person&q=&cursor=&limit=` | 返回 `items/nextCursor`；条目含稳定 id、显示名、允许的辅助标签和可用状态 | 文档鉴权，服务端推导人员范围；有界查询和分页，不返回全组织数据 |
| `POST /v1/documents/{id}/references/resolve` | 批量解析 type/targetId，返回可见快照、状态与允许的跳转 | 有界批次；逐条授权，避免 ID 枚举；不接受客户端提交跳转 URL 作为权威 |
| `GET /v1/documents/{id}/references?revision=N` | 当前有权读取的规范引用及定位信息 | 从已提交版本读取，草稿不算已关联；历史定位不能错误跳到另一个块 |
| `PeopleDirectory` | `search/resolve` | 可接宿主用户中心或本地配置适配器；无需管理平台，也不绑定某个账号服务 |
| `ReferenceProjector` | 从规范版本提取和比较引用 | 兼容浏览器、CLI、导入及恢复路径；派生索引可从 HCD 重建 |
| `ReferenceEventSink` | 接收已提交关联变化 | 先定义契约/空实现，实际提醒关闭；失败不能伪装为“已提醒” |

建议缓存按服务端身份范围/文档/权限版本/query 分开，短期有效；权限变化清理，旧结果选择时重新校验。头像可选、懒加载，失败不影响插入。前端接收的最小人员数据不包含访问令牌或目录凭证。

### 规范内容与派生数据

人员提及不是 `@张三` 普通字符串，拟议载荷如下；需要 D 阶段内容协议升级才能写入当前固定类型 schema：

```json
{
  "type": "hcd.mention",
  "version": 1,
  "mentionId": "<stable-occurrence-id>",
  "target": { "kind": "person", "id": "<server-person-id>" },
  "snapshot": { "label": "张三" }
}
```

`mentionId` 标识一次出现，target.id 标识人；两个位置提及同一人是不同 occurrence。块移动保留 occurrence，复制/粘贴生成新 occurrence；撤销、恢复历史版本和跨文档粘贴需显式策略。服务端验证目标和范围，执行人取鉴权上下文；不能信任节点里的任意 actor/tenant/收件人。网页和 Office 粘贴均走 codec，保留不了业务身份时降级为显示文字并报告。

HCD 节点是规范来源；人员解析状态、按人/文档查关联、未来通知记录是派生服务数据，不能要求核心 bundle 依赖用户中心才能离线读取。索引至少包括 scope、documentId、mentionId、target kind/id、block/shape/page 锚点、首次/最新出现 revision、当前是否存在。展示名不是关联键。删除/失效不直接物理清空历史规范内容。

### 关联提醒预留（本轮不发送）

预留事件 `reference.created / reference.retargeted / reference.removed`，只在规范保存成功后产生；打字、打开候选、Yjs 增量、本机备份、请求重试不直接发送提醒。未来服务可按人员权限与订阅把这些事件映射到站内提醒等渠道。

事件携带 schemaVersion、eventId、scope、documentId、revision、mentionId、目标、变更类型、服务端执行人、来源（交互/导入/恢复/AI 接受等）和发生时间；不携带整篇正文、token 或无需访问的人员信息。事件与内容提交的可靠衔接采用可恢复提交记录/outbox 或等价机制，不能先发提醒再保存；规范事务成功但事件投递失败可重试和按版本补齐。

去重以同一次关联状态转换的稳定身份为基础，而不是每次 HTTP 请求或每次新 revision。修改另一段正文、改显示名、移动块、幂等重放都不新增“被提及”事件。新 occurrence / 更换目标 / 保存后删除再新增按清晰的状态转换处理；历史导入和恢复默认不批量提醒。将来启用前确定事件起始位置，不把今天保留的历史关联全部补发。

后续提醒对象另建：referenceId、recipientId、trigger、计划时间、IANA timeZone、状态、幂等键及取消原因。日期提及不自动创建提醒；用户另行设置。未来调度器发送前重新检查文档访问、目标是否仍存在、是否已取消和收件人有效性；恢复/撤销不能复活已取消的老任务。渠道接入、通知偏好、批量 fanout、定时调度和已读中心均不在本轮实现。

### @ 首批验收

1. 两个用户看到不同权限范围的候选；离线人员也能在有权目录中找到，在线陌生人不会自动成为候选；同名不混淆。
2. 搜索取消/慢响应不串结果，中文 IME 不误选；只读和保护区不能插入；插入不改变文档 ACL。
3. 两窗口协同、复制/移动、撤销重做、关页恢复、保存重放保持 occurrence 与 target 身份正确。
4. 保存前没有已提交关联；保存后可查询；普通正文再次保存不重复新增关联事件；删除/改目标正确更新。
5. 无目录配置、人员禁用、改名、权限撤销、跨文档粘贴有明确降级；导出后不依赖在线目录才能读出名字。
6. 实际提醒始终关闭，不产生邮件、IM 或站内提醒；相关接口不能返回“已发送”。
