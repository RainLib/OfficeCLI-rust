# 可编辑行内容器：精确 PM 事务绑定（2026-10-27）

本批把已有永久正文载体接入真实 ProseMirror 事务路径，解决“可显示、结构存储可写，但内部输入仍依赖整段 diff”的缺口。管理平台和实际提醒发送继续后置；原七阶段目标没有缩减或标为全部完成。

## 行为和约束

重复字符不能用最终可见字符串推断原动作。例如先删除一个 A 再插回 A，最终仍是 AAAA，但第一个字符应具有新的操作身份，其余字符及同伴书签应保持。父段落中的容器只占一个永久 embed；PM 展开子正文后的尺寸不能直接作为父载体偏移。

- `structureTextEdits` 在显式内部模式下，按每个 PM step 当时的文档提取文字替换。记录根结构 key、可选容器 occurrence ID 和原始步骤序列；父/子正文分别分组。非叶子引用折算为一个存储单位，嵌套正文先增长也不会影响父正文后续步骤的位置。
- `SemanticBlockStore` 将同根的父/子批次一起预检。现有容器定义、所有作用域和完整结果均须匹配，才允许进入用户事务；错误的后续作用域不能让前面的输入先写入。
- `SemanticInlineContainers` 校验每份永久正文：未提供文字步骤的作用域只允许格式变化。新增 wrapper、未知/重复作用域、未声明的正文变化和越界操作拒绝，不偷偷回退为属性覆盖或新载体。
- 实际写入沿原 PM 步骤执行；来源/格式沿用原机制。空正文、嵌套正文和原始 Unicode 字符身份保留，定义和分配元数据不进入个人撤销。
- 普通旧文字路径和序列化不变。旧调用仍拒绝空批次，默认投影和旧 wire guard 仍拒绝未协商的行内容器模型；未升级公开 envelope、SDK、HTTP 能力头或活动房间。
- 删除整个 wrapper 的专门审阅仍未完成，从保留根直接删除继续明确拒绝。属性变化、复制和迁移也不能借精确文字批次绕过原有保护。

文字与拆段、wrapper 插入或 atom 替换混合时，不生成部分位置提示，继续既有结构路径；本批不承诺这些混合结构动作的精确字符身份。同位置并发插入由 Yjs 定序，验收要求两端收敛、原字符身份和个人历史正确，不擅自固定两位作者的插入先后。

## 验证

11 项新增 PM/Yjs 回归与完整 930 项前端检查通过，TypeScript、独立/嵌入构建及差异检查通过。覆盖：

1. 嵌套正文增长后父/子步骤坐标、重复字符及“文字相同但字符已替换”的真实操作。
2. 两种复制顺序下的并发输入收敛、原字符身份、内部相对光标和个人撤销/重做保留同伴输入。
3. 多根、空正文、composition 形状的多步替换、同批格式更新与来源修复。
4. 迟到非法作用域、未声明正文变化、只读和 wrapper 删除在共享修改前拒绝。
5. 新 Y.Doc 从编码状态重建后继续按精确步骤写入。

实际浏览器使用隔离测试入口，加载两份真实 Tiptap/PM 视图及独立 Y.Doc。本机交换真实 Yjs 更新，分别输入 AA 和“同伴😀”，同步后两端一致；撤销 Alice 保留同伴文字，重做恢复，原始 8 个 UTF-16 字符身份始终 8/8，错误区为空。此处不是 WebSocket/签名房间或真实操作系统输入法验收。行内边界的浏览器光标行为仍需公开节点视图交互设计，测试通过直接点击内部文字完成。

另从自有无源 `inline-native-r8.hcdz` 创建新副本，经真实 PM 插件批次输入“精确绑定😀”、主动清空一个已有字段，验证个人历史和原始字符身份后写入 `.yjs`。原生 CLI 保存 r9，再应用完整递归来源回执，重新从文件创建 Doc；完整规范快照含来源 ID 精确相等，回执不改变语义摘要或个人历史。HCDZ 打包重开、资源哈希/字节数和 DOCX/PPTX/PDF/Markdown 实际文本回读通过；DOCX 另核对原粗体/斜体 XML，原输入归档字节不变。
