# HCD 字体、字号与国际化接入设计

状态：Word 已接通选区字号、保存重开、协同同步与语义 DOCX 字体字段导出；字体选择、原稿完整样式保真、统一字体服务及 PPT/PDF 同等能力未完成。云管理平台继续后置。

## 当前证据

- `pdf-handler::fonts` 已提供基于字体文件 SHA-256 和集合 faceIndex 的身份，包含 family/style/weight；目前只解释默认实例，没有可变字体轴选择。
- PDF 无源重绘按完整字素簇选择内置 Noto Sans SC / Noto Emoji，经 Rustybuzz 排版。缺字、换行、RTL 控制或超限不被当作空白或完整重绘处理。
- 页面图保存 `data-hcd-raster-font-ids`，作为当前 bitmap 的已知字体依赖。基于旧页面图再次绘制时保守继承背景依赖；这不是整份文档的完整字体清单。原生源 PDF 重绘暂不提供该清单。
- 已修复嵌入字体的 Unicode 别名映射：每个标量使用独立 CID，允许多个 CID 指向同一字形。连字/字素簇的 ToUnicode 序列不作为逐字符反向映射；单字节/组合字体按各自编码宽度写入，范围超限不截断。
- PDF 强制嵌入的字体复用同时检查源文件身份和字符覆盖，使用真实 PostScript 名称。配置字体文件读取上限 64 MiB；当前嵌入器要求 TrueType glyf 轮廓。
- 固定版式属性仍只展示原文字体/字号。Word 完整模式已有选区字号（1–1638 pt，半磅）、粗斜体、下划线、删除线、颜色等；字体选择、字体文件依赖与全部原稿样式尚未贯通。
- 当前样例和回归见 [优化进度](../hcd-optimization-progress.zh.md)。上述能力不代表浏览器、Word/PPT 源导出和 HTML/CSS 打印已经统一字体解析。

## 统一的字体模型

后续实现需区分以下身份，不能用显示名称充当唯一键：

| 对象 | 必要信息 | 用途 |
| --- | --- | --- |
| 字体文件 | 完整字节 hash、格式、字节数 | 固定文件版本、校验和缓存 |
| 字体 face | 文件 hash、faceIndex | 区分 TTC/OTC 中的 face |
| 字体实例 | face、支持的轴及归一化轴值 | 可变字体实例；尚未实现 |
| 文字格式 | 实例引用、字号 pt、字重/斜体等 | canonical 内容和属性编辑 |
| 回退结果 | 请求 face、实际 face、覆盖簇与原因 | 显示缺失字体和可追踪的替代 |
| 预览子集 | 原 face/实例、字形集合、子集 bytes hash | 页面按需加载，保留原文件身份 |

原文的字体名称、主题字体、语言字体映射要保留。字体缺失时，界面应能显示原请求与实际回退，保存不能把回退名写成原作者的选择。默认实例以外的变量轴、合成粗斜体必须有明确支持范围。

字体文件及使用中的版本需要跟随文档 revision 保留。管理平台后续移除目录项时，旧版本依赖的文件仍需可读；对象回收也要计算字体引用。

## 属性栏与保存协议

选中文字后，文字属性提供可用字体、字号、字重/斜体、颜色及段落设置；页面属性显示尺寸/方向/背景，图片属性显示位置/尺寸/替换。能力依据格式和对象决定。混合选区显示“混合”，不把一个值误用到整个对象。

字体/字号修改要成为结构化格式操作，携带目标 node/range、baseRevision、文本及格式前置条件；不能只改浏览器 CSS。纯字体修改通常不改变文字 hash，所以还需要格式 hash 或等价的样式版本校验。现有核心会追踪 `node.style` 的 dirty 节点，但当前 style schema 只含颜色/高亮/边框，不能直接拿它当作完整字体协议。

属性草稿应与文字草稿一样跨页面挂载保存，跟踪请求期间的新输入。远端同一对象格式变化需要显式冲突处理；撤销、重做、历史恢复也必须包含格式。选区输入法组合期间不重建文字节点或强制替换字体；完成组合后再提交格式校验。

提交顺序：

1. 解析目标对象、原格式及字体实例；确认字体文件可用、字符/字素簇与排版能力满足需求。
2. 构建临时候选，校验文字、格式、页面几何及导出结果。超出文本区域时让用户调整区域/字号，完整正文保留。
3. 在版本与前置条件校验下追加 revision，再通知协作者。失败保留草稿，不能推进一个只在预览中生效的版本。
4. 属性面板读取已保存格式；重新打开、源文件导出、语义导出各自按实际支持报告结果。

## 格式接入约束

| 格式 | 要贯通的内容 | 验收重点 |
| --- | --- | --- |
| Word/语义流 | projection、Tiptap marks、checkpoint、HTML、DOCX runs | 文本修改不丢已有字体；字号/字体编辑保存重开一致；ASCII/eastAsia/复杂文字字体映射 |
| PPT | theme/placeholder 继承、shape 内的 rich runs、文本区域几何、PPTX 写回 | 修改一个 run 不覆盖相邻 run；字体/字号变化后的换行和溢出可见；不丢主题引用 |
| PDF | 实际嵌入 face、字形整形、ToUnicode、文本矩阵、裁剪/旋转、候选重绘 | 预览与原生导出共用候选；复杂簇的文本映射正确；无法完成时不发布部分文字 |

PDF 当前的无源近似重绘只是一条兼容路径。单行绘制不能代替多行布局、双向文本或复杂脚本排版。源 PDF 的简单文字替换和 HTML/CSS 打印也需分别验证 emoji、连字、RTL 与回退，不能用无源 mask 的测试证明它们已完成。

## 长文与预览字体

字体面板打开时只需当前选区与字体依赖元数据，不应拉取全文或为每段正文创建字体副本。字体文件、整形和子集缓存按字体身份与实例区分，并保持有界、可取消和可释放。

固定版式 frame 当前禁止脚本和任意网络资源，字体允许 data URL。后续优先验证按页/按需的字体子集，通过已鉴权的数据请求取得字节，再提供给预览；保持现有 frame 隔离。子集必须保留整形所需的字形/表以及原字体身份，并控制 CSS 数据和缓存大小。不能把整套 CJK 字体在每个缩略图重复展开。

Word 完整模式仍是全文 Yjs 模型。字体资源按需加载不等于 Word 正文已经完成数据分页，这两项需要独立验收。

## 国际化约束

- 界面 locale、文档语言、段落方向和字体覆盖是独立状态。切换界面语言不应改变正文、字体选择或 PPT/PDF 页面坐标。
- 服务端返回稳定错误码与参数，客户端本地化缺字、字体不可用、版本冲突和不支持的排版；避免依赖匹配英文报错句子。
- 字体名称可有本地化别名，但 ID、文件版本和实际使用的 face 保持一致。
- Unicode 内容不做隐式归一化或截断。API 字符偏移、浏览器 UTF-16、字素簇选区需要明确转换；emoji/组合字符不能被切开。
- RTL 需要双向段落布局、选区/光标、混合数字与标点测试；仅有字形覆盖或文字反转不构成 RTL 支持。

## 后续实施顺序与验收

1. 补齐原生 PDF 和 HTML/CSS 打印的字体回退、字体不可用错误及多语排版边界；继续防止部分文字被接受为完整输出。
2. 增加 canonical 字体/字号格式与依赖模型，贯通 Word/PPT/PDF 的保存、历史和导出。以各格式实际能力提供属性控件。
3. 接入预览字体解析/子集缓存，验证缺少本机字体时的重开与导出。覆盖长文和多个编辑窗口。
4. 完善字体草稿、撤销重做、同节点格式冲突、断线恢复和授权变化；保持已有文字草稿保障。
5. 上述能力稳定后，再做字体上传/目录、成员权限及文档管理平台。

验收至少包含：中文/拉丁混排、音标和组合附加符、emoji 变体/肤色/ZWJ、RTL 混合文本；不支持的输入要有保留正文的明确结果。检查保存重开、源/语义导出、历史不可变、异步保存期间继续输入、跨页草稿、同节点冲突、只读权限，以及 Windows/macOS/Linux 缺少系统字体时的行为。每项验收要对应自己的路径，不能用一张页面图覆盖所有格式和导出模式。

## Word 字号链路当前实现

见 [优化进度](../hcd-optimization-progress.zh.md) 的“局部字号的原稿保存与导出”和“字符来源与联合修改保存”。`text.runs` 保留原 canonical 节点、source anchor 和外层原稿样式；独立的 `hcdSource` mark 让相邻同样式源节点、中文/emoji 改字及局部字号分段保持可区分。原生 DOCX 按范围复制原 run 属性，只改明确选中的字号；语义 DOCX 使用 native runs。继承与显式字号分别记录，未编辑的原稿 `szCs=16pt` 不会被基础字号 14pt 覆盖。

协同字体元数据协议为 2，来源元数据为 1，保存协议为 4，语义房间后缀为 `:typography2:save4`。API、sidecar 和浏览器须同步更新；旧保存请求返回 426。旧 CRDT 的版本 1/2/3 签名回执先与对应不可变版本核对，再迁移来源与显式字号，保持 Yjs 对象和待保存内容。格式或单一统一来源文字可确定对应时保留迁移；多个来源间无法确定文字归属时保留副本进入恢复流程。迁移不增加内容 revision、不重置 epoch。

完整原稿保真仍未完成：粗斜体、颜色、字体族和结构等变化仍可能重建块；嵌套来源标记和修订 run 需要专门支持。语义视图也未完整表达命名样式中的颜色、间距等属性。完整 Word 的图片位置/尺寸与替换资源意图已和正文同批保存；图片意图元数据为 2。完整 Word 已新增本机磁盘日志与恢复选择，本地关页重开/合并/导出验证见进度记录。外部编辑选择性合并、离线资源完整包、磁盘副本生命周期、权限主动撤销、生产多实例验收、图片撤销重做仍未完成。固定/分段换图联合事务已接通，后续仍需未知请求结果与磁盘恢复验收。字体选择与管理平台不在本轮实现范围。
