# 行内容器的 Notion 交互、拖动互斥与 Markdown 格式（2026-10-27）

本轮补齐此前明确缺少的主页面浏览器验收，并修复实际截图和文件回读暴露的三个问题：拖动时文字浮层遮挡、整张纸悬停触发末尾按钮、Markdown 丢失已保存的行内格式。管理平台与提醒发送继续暂缓。

## 产品行为

- `useBlockControls` 的活动状态同时包含菜单和拖动。拖动时斜杠、提及、引用检查和 AI 候选按既有互斥规则暂停；文字选区浮层也立即从可见布局和可访问树隐藏。结束或取消拖动后恢复正常选区工具。
- 保留目标区域高亮、三像素插入线、前后位置提示，以及不可放置位置的反馈。Esc 取消会移除反馈，不提交结构变更。
- 末尾添加段落入口仅在自身悬停或键盘 `focus-visible` 时显示。移除整张纸 `:hover` 触发；触屏显示规则和键盘入口保留。实际鼠标在纸内但不在入口时 opacity=0，悬停入口时 opacity=1；本轮键盘 Tab 实测被控制超时打断，不将该项算作已完成的可访问性验收。
- 行内容器内部 `/` 可插入已注册的行内扩展，块类型转换保持不可用。默认 `@` 向服务端查询人员，尚未在线的 Bob 也可推荐、按姓名筛选并通过 Enter 插入。

## Markdown 兼容修复

浏览器的选区浮层只把嵌套正文 `NestedUI` 中的 `es` 加粗，原生 r23 已正确保存。但首次实际导出发现 Markdown 仍是纯文本，缺少格式。现在源无关 HTML→Markdown 转换沿用原有文字样式区间，同时保留链接和表格单元格偏移：

- 加粗、斜体、下划线、删除线使用受限的 CommonMark 行内 HTML 标签，词内格式不依赖有歧义的强调分隔符。
- 行内代码使用比正文所有反引号串更长的围栏，保留需要的边缘空格；普通文字继续做 Markdown 字面转义。
- 表格中的样式和链接共用字节范围，竖线仅转义一次，明确换行转为 `<br>`。
- 样式区间在文档转换开始时按块/单元格建立索引，避免每段重新扫描全篇格式。
- Markdown 导入允许不带属性的 `<strong>`/`<em>`，与已有安全行内标签规则一致；带属性的原始 HTML 没有因此获得放行。

实际导出的 r24 Markdown 再导入新 HCD 后，`es` 的 bold 标记仍存在。DOCX/PDF/PPTX 本轮验证可读正文和人员姓名，未据此声称所有目标格式都实现了全部字体、颜色和业务关联。Markdown 的这些标签需要支持 CommonMark 行内 HTML 的阅读器；任意阅读器设置、原格式主题和精确布局没有被本轮证明。

## 实际浏览器与原生版本

使用上一轮还原验收后的独立副本，不修改用户原文档。

| 版本 | 实际动作与回读 |
| --- | --- |
| r15 / r16 | `/` 插入外层业务字段，正文内部再次打开菜单，经方向键和 Enter 插入内层字段 |
| r17 | 嵌套正文中输入 `@`，默认列表含 Alice 与未在线的 Bob，搜索 Bob 后 Enter 插入，服务端索引递归位置 `[0,1]` |
| r18 | Bob 从第二个浏览器窗口保存独立段落 `Bob UI retained` |
| r19 / r20 | Alice 个人撤销恢复字面查询 `@Bob`，重做恢复同一个 mentionId；Bob 正文始终保留 |
| r21 | 实际块菜单复制：两个包装器均有新 occurrence 身份，副本提及也有独立 mentionId |
| r22 | 拖动副本，在目标段落高亮与插入线下松开，实际移动到 Bob 段落前面；块内容和身份保持 |
| r23 | 在内层正文用键盘选中 `es`，通过浮层加粗并保存 |
| r24 | 浮层互斥修复后，再次实际拖动并保存到 Bob 段落后面；只改变顺序 |

服务端回读 r17–r24：新增、移除、重做和复制的关联事件操作者均为 Alice；Bob 独立输入、移动和格式变化不产生重复关联事件。所有查询的提醒状态为 disabled，未发送提醒。

最终 r14–r24 的原三个源块完全一致，个人撤销保留同伴内容，移动前后按 blockId 比较的完整块内容一致，副本身份与原节点分离。实际 DOCX/PPTX/PDF/Markdown 回读包含嵌套正文、Bob 姓名与同伴段落；HCDZ 离线逐版本投影一致，附件原始字节和 SHA256 保留。
