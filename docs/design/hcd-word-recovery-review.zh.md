# Word 区域草稿恢复审阅

2026-10-26。承接[区域房间所有权](hcd-word-room-ownership.zh.md)，补齐不同恢复内容的服务端比较、选择与独立审阅组件。`HCD_WORD_ROOMS` 仍默认关闭；旧用户文档迁移和主纸张编辑器的区域富文本绑定尚未开放。此组件通过隔离入口验证，没有把未提交的区域草稿交给旧映射编辑器显示或保存。

## 用户可审阅的结果

- “比较恢复副本”并排显示当前草稿与恢复副本，以增加/删除、格式和移动标记表达变化。
- “预览合并结果”展示真正按共享字符身份合并后的结果，保留同伴输入；不会用恢复副本本身冒充合并结果。
- “保留当前草稿”保持当前完整 Yjs 状态、作者、准备请求和资源选择；记录审阅者的明确选择。
- “合并恢复内容”保留原作者及人员提及的独立身份/作者证明。确认者记录为审阅者，不能借此成为其他成员输入的作者。
- 两项选择都有说明不同后果的确认框，默认聚焦取消；Esc 取消后返回原按钮。请求尚未结束时禁止重复确认；未知结果只重试原 requestId，不建立新选择。
- 原恢复文件不删除。审阅后仍可展开恢复副本列表并下载，读成员也可以查看/下载，确认选择必须具有当前写权限。
- 提供英文、简体和繁体文案。浏览器实际复核简体/英文、只读禁用、两种确认、取消焦点、合并及审阅后下载。

比较窗口每次返回 25 条差异，每条文字最多展示 16000 个字符并明确标记截取；完整内容留在恢复副本。服务端仍需校验完整有界签名快照，不能把此窗口机制称为整个编辑器的长文数据虚拟化。图片/上传差异单独提示；图片可视比较、逐项属性选择仍待接入。

## 接口与并发约束

sidecar 增加 `POST /v1/documents/{id}/collaboration/word-recovery`，操作为 `list`、`preview`、`download`、`resolve`。请求必须带当前成员 token、区域协议对应的 epoch；不使用在线头像代替服务端身份。

`preview` 的 reviewHash 同时绑定当前私有日志 tip 和完整恢复记录集合。收到新草稿或新恢复记录后，旧比较不可确认。确认时先排空本 sidecar 已准入的数据包，拒绝仍活跃的区域房间，再取得原生独占租约。另一 sidecar 的竞争仍由原生 OS 锁及日志祖先约束拒绝。成员权限在异步规划后、写入前再次核验。

确认结果作为 `decisions` 附在新签名日志记录中，包含 requestId、archiveId、reviewHash、action 和服务端审阅者身份；相同 requestId 只能按同一人员/副本/比较/动作重试。先 fsync 私有记录，再由原生确认日志 hash。写入或确认结果未知时返回 503 / `word-recovery-result-pending`；重试先查已经落盘的决定，不重复合并。

审阅本身不创建规范文档版本。之后由正常 `WordSaveCoordinator` 队列处理精确请求、原作者权限、图片基线、签名回执和保存期间输入。真实验证在选择后加入同一签名房间，再保存为 r2。

## 合并门槛与资源保全

自动合并仅在两份草稿具有相同、经不可变原生版本核验的保存基线时开放。先在影子文档中通过区域 guard 检查，不能修改服务端 schema/区域边界、规范身份、只读节点或其他区域来源。未绑定作者、人员引用证明不足、图片意图冲突或上传记录冲突时拒绝合并。

上传预留按原 ID 保留，仍在进行的状态恢复为 interrupted，归原上传成员处理。不会由审阅者直接套用未确认上传，也不会把 token 或原始文件字节写入审阅记录。相同提及的稳定身份和原关联作者保留，后续保存继续走原生关联/权限检查；不发送提醒。

不同基线及尚有 prepared checkpoint 的副本仍可查看、下载和明确选择保留当前，但自动合并禁用。不能丢弃未知的原保存结果再制造新请求；跨版本恢复/重新绑定及未确认保存的专门恢复流程还需继续。

下载的 `.hcd-word-draft` 是同一文档/服务的恢复副本，保留完整 capsule 和资源引用，**不是包含全部图片字节、历史和扩展资源的 HCDZ**，也不是可信自动导入指令。完整离线交付仍需正常保存后导出 HCDZ；未来导入恢复文件必须重新校验其来源、权限及内容。

## 复现与验证

```bash
cd examples/hdoc/editor
npm test
npm run build
# 仓库根目录：
python3 scripts/hcd-word-room.py --recovery
python3 scripts/hcd-word-room.py --owners
python3 scripts/hcd-word-room.py
python3 scripts/hcd-word-room.py --preview
```

`--preview` 创建独立前端副本、原生根目录、sidecar 和仅含合成数据的两个审阅页面，不修改用户现有预览。通过浏览器确认合并后，可验证同一文档：

```bash
python3 scripts/hcd-word-recovery-browser-files.py <preview-root>
# 已完成 Socket 保存，仅需重跑文件校验：
python3 scripts/hcd-word-recovery-browser-files.py <preview-root> --verify-saved
```

新增 18 项前端回归，完整 865 项通过。覆盖保留当前的精确状态、共同字符合并/真正合并预览、原作者与提及、上传预留、权限复核、过期比较、迟到恢复副本、未知结果重试、服务端 metadata 防篡改、分页/长文字截取、跨基线及 prepared 请求保护。TypeScript、生产/嵌入构建通过；独立审阅入口也单独做生产打包，避免仅检查了未引用的 TSX 文件。

真实服务检查：未审阅房间拒绝加入、只读确认 403、过期比较 409、活跃房间确认 409、同 requestId 精确重试；合并后正文、页眉页脚及图片尺寸经正常区域房间保存。实际浏览器选择随后接真实 Socket 保存，DOCX 精确保留同伴前缀和恢复后缀，未重复其他段落，图片字节不变；HCDZ 的 r1/r2 精确回读并 validate。原生二进制沿用已验收版本，本批没有 Rust 修改。

## 仍需继续

恢复审阅组件尚未自动插入主纸张编辑器，也未开放新的公共 SDK。下一步需把浏览器区域 binding、layout/来源回执、上传恢复/关闭选择接入同一房间，再组合本组件及旧文档 epoch 迁移。跨保存基线的恢复合并、未知 prepared 请求的专门选择、图片可视审阅、日志压缩/GC、远端多主机适配和长文仍是独立开放项。

统一命令、Notion 交互、@ 与扩展节点、AI 接受事务在区域路径中的组合仍继续，不能据此标记原七阶段目标完成。管理平台和实际提醒发送保持后置。
