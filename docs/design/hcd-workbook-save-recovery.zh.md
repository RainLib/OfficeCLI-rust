# Excel 草稿、保存回执与附件恢复一致性

日期：2026-10-27。承接[当前能力矩阵](hcd-current-capabilities.zh.md)的第二步。管理平台和真实提醒仍暂缓；Word 基础排版、各格式创作能力、长文和生产验收等完整目标继续开放。

## Excel 入口

`UniverViewer` 现在进入 `WorkbookEditor`，先经过已有 `FixedDraftBootstrap`，再建立网格。复用 `TextDraftStore`、`FixedDraftJournal`、`FixedSaveController` 及原生 `/edits`、`/edits/receipt`；没有引入第二套服务端保存协议。独立 XLSX 适配器未配置 draft port 时仍保留原 `hcd-patch` 事件契约。

- 草稿按已鉴权成员、文档、端点和不可变源 hash 隔离，token 不入库；窗口独立分支、明确比较恢复、旧副本保留及备份下载沿用原有门禁。恢复不直接写规范文档。
- 已完成的单元格输入先成为工作区草稿，完整快照落盘；600ms 停顿触发正常保存，手动保存和快捷键共用协调器。保存前持久化精确请求，结果未知时先查询同一请求的不可变回执。CAS 明确拒绝后，才允许基于当前版本重新保存。
- 捕获提交后的继续输入保留为下一批草稿。远端更新不覆盖本机草稿，同格冲突需明确选择；未知原请求未核对时不允许先改写冲突决策。
- 多格输入先预检可编辑目标并按一次动作记录个人历史。包含受保护或未映射单元格的粘贴会整体拒绝；详细能力及验证边界见[输入缓冲与批量历史](hcd-workbook-input-batch.zh.md)。
- 保存、导出、撤销和重做进入紧凑操作区；关闭/导出先结束当前单元格输入，检查草稿、请求、历史和本机落盘。未保存或结果未知时不能把旧文件作为本次编辑结果下载。
- 原生网格元数据、样式和分片绑定打开时的 revision，避免滚动延迟读取混入后来版本。已加载远端单元格经事件更新；缺失对象/重置重新建立视图，工作区草稿保持。
- 本机历史共用 `FixedHistory`，其反向修改要读取当前对象并核验。网格外层撤销快捷键走该历史，单元格内部仍使用私有输入历史；不能拿第三方内核的程序化重绘历史恢复整个工作表。
- 重绘只处理有草稿覆盖的单元格；清除覆盖时恢复原单元格数据和样式，不把未触碰的公式或数值批量改成字符串。

## 跨窗口副本保留

实际多窗口检查发现旧分支在收到远端更新后，会因新快照丢失 retained 标记。现在以本机文字、图片意图和精确请求判断是否有新本机内容：仅远端观察/冲突状态刷新保持“已审阅保留”；旧窗口真正新增文字/图片意图时重新成为可发现副本。记录仍完整保留，不删除其他窗口内容。审阅指纹独立存放，避免旧分支重写清除标记；存储升级为 version 2，保留旧分支并通过 versionchange 关闭旧连接。写入按顺序排队，flush 等待异步指纹和事务全部完成。专项覆盖旧格式迁移、旧写入覆盖、比较后新输入及写入顺序；真实浏览器的全部交错时序仍未覆盖。

## 附件恢复

`stageRecoveryResource` 校验待恢复字节，再让服务端核验并重新固定当前文档已有规范或暂存资源；404（资源缺失或旧服务不支持）才回退上传。403、网络错误、损坏字节及取消不能通过重新上传绕过。重新固定建立暂存记录，使资源即使在恢复比较后从当前版本移除，也不只依赖旧的读取结果；没有长期“已上传”布尔缓存。详见[后续附件固定](hcd-inline-resource-recovery-ui.zh.md#2026-10-28附件重试的服务端重新固定)。

属性表单仅在节点的资源字段变化时自动刷新 expected envelope，保留本机未提交的属性输入。数据、fallback、版本或节点身份变化仍保留原来的比较/重新载入要求。属性规则有三项模型测试；该增量没有补做附件主页面全部操作的浏览器验收，原附件选区/定位慢的问题也没有据此宣称已修复。

## 2026-10-28：多附件恢复请求

普通语义恢复确认时，对已经去重的资源按最多四项一批并行核验或暂存；每批结束重新检查当前文档和写权限，全部处理完成后再次向服务端核验权限，再执行恢复事务。每个资源仍校验字节摘要和长度；规范资源读取失败不能降级为上传，尚未发布的资源仍需暂存。某项失败时等待本批其他请求结束，不启动下一批，也不合并文档；暂存本身不等于建立节点引用。

新增测试覆盖并发上限、处理中有协作者修改、单个资源失败和完整批次完成。该改动减少多附件场景下串行网络等待及每个资源一次全文编码的次数，未对定位/选区交互慢的根因作判断，也未完成真实浏览器多附件耗时测量、取消慢请求或跨设备验收。

## 2026-10-28：恢复比较过期时取消资源工作

确认恢复期间监听当前协作 Y.Doc；其他更新使比较过期时，中止本次权限和资源请求，停止后续批次，并在最终合并前再次检查中止状态、写权限和快照。接收到中止信号的传输会尽早退出；若自定义传输不响应中止，仍等待当前批次结束，再拒绝合并。恢复合并自己的 Yjs 更新不触发此取消，结束后移除监听器。

受控测试验证四个在途请求因同伴编辑被中止且不合并；若变化发生在本机待处理文件已经写入之后，文件任务保留以便恢复，文档仍不合并。请求已经发到服务端时，取消不保证服务端没有完成暂存；资源仍需显式关联及正常保存。该测试不代表真实慢网浏览器或跨设备验收，也不代表附件定位缓慢已修复。

## 2026-10-28：固定版式与 Excel 草稿备份导入

PPT/PDF 固定版式和 Excel 的备份区新增“导入草稿备份”。文件先校验格式、文档、源文件哈希及大小，随后重新核对当前成员写权限和源文件；合格内容写成独立的本机分支，不替换正在编辑的窗口。重新打开文档后，需要通过已有的服务端版本比较和明确恢复流程；结果未知的保存请求继续使用原请求身份核对回执。

新下载的 `hcd-fixed-recovery/2` 附带成员 ID 与规范 API 地址，不包含 token；导入时要求两者与当前会话一致。旧 `/1` 文件没有成员和服务信息，只有不存在待确认请求时才允许导入，并仍需比较；包含未知请求的旧备份必须保留原文件，当前无法安全导入。文件不具备签名，声明身份不是可信凭证；权限与保存前置条件仍由服务端核验。相同文件重复导入会产生独立分支，尚无跨分支去重。备份最多导入 8 MiB，不包含上传未完成的图片原始文件或完整 HCD 文档；暂存图片资源仍依赖服务端可用性。

隔离 Excel 浏览器阻断保存及回执，输入 `跨设备恢复😀`，实际下载带未知请求的备份并通过文件选择器导入；当前窗口的输入和待核对状态保留。新窗口看到本机草稿与 r0 服务端值，明确恢复后核对并重试原请求，保存为 r1。独立回读确认 r1 版本记录的 patch ID 与备份一致、导出 XLSX 的单元格文本及既有公式均正确。截图见 [导入后状态](../assets/hcd-fixed-portable-backup-2026-10-28/import.png)。该验证是同一浏览器的两个窗口与合成数据，不代表跨物理设备、PPT/PDF 实际浏览器验收，或无网络时完成身份初始化。

## 2026-10-28：展示待确认请求并补验 PPT

恢复比较现同时展示“待核对的原保存请求”和“当前本机草稿”，包含只存在于原请求的文字、图片及几何；这些对象也参与分页和固定版本的服务端读取。若原请求之后又有输入，用户可以在恢复前看清两者。原请求仍先走回执核对，随后新草稿单独保存。

隔离 PPT 浏览器通过真实下载和文件选择器导入备份，比较页分别显示原请求 `原请求内容`、后续文字及服务端原文；恢复后原请求保存为 r1，后续文字另存 r2。对图片尺寸也做了同样操作：比较显示服务端 100 pt、原请求 120 pt、本机后续 140 pt；分别保存为 r3/r4。独立回读确认 r1 和 r3 使用各自备份中的原 patch ID，后续请求身份不同；r0–r2 的源格式 PPTX 文字及图片字节保留，r2–r4 的语义重建 PPTX 图片尺寸及字节一致。图片更改的源格式 PPTX 导出目前明确返回不支持，不能称为原稿保真。证据见[文字比较](../assets/hcd-fixed-backup-pptx-2026-10-28/compare.png)、[图片比较](../assets/hcd-fixed-backup-pptx-2026-10-28/image-compare.png)和[文件回读](../assets/hcd-fixed-backup-pptx-2026-10-28/readback.json)。原生打包 HCDZ 解包后，除运行时锁文件外 27 个规范文件逐字节相同，原包和解包均通过校验。测试为同机合成样例，不覆盖 PDF、不同物理设备或图片上传失败后的原始字节。

下载或导入草稿备份时，现在明确提示备份不包含图片文件，恢复替换图片依赖服务端资源仍然可用；这同时适用于已经上传但尚未纳入规范版本的暂存资源。浏览器实际检查了恢复页的下载提示。此次使用单页合成 PDF、同一浏览器和 ASCII 文字；未验证复杂字体/多页、PDF 图片替换备份、存储驱逐、不同物理设备或生产部署。

## 2026-10-28：固定版式图片选择日志基础

新增独立的本机图片选择日志和显式重试客户端：记录原始字节、SHA-256、图片对象基线、版本和页码；上传失败时保留选择，返回的资源 hash 必须与原文件一致。跨窗口取消后，迟到的暂存结果不能把任务重新变成待处理；正常关联后必须先由调用方持久化草稿，才能结束任务。同一客户端在关联阶段拒绝取消。日志不保存临时预览或凭据，并限制单文件和总容量。

补充重试关联前的核对组件：重新验证用户、写权限和源文件身份，以服务端固定版本读取图片；目标被修改或删除、已有不同图片草稿时拒绝覆盖。前次关联成功但草稿持久化失败时，相同资源的重试不会重复添加操作；关闭时取消尚在进行的目标核对并保留暂存任务。

受控 IndexedDB 测试覆盖重开字节、损坏、容量、迟到结果、错误 hash 和草稿持久化失败。最初版本未连接产品入口，后续接入情况见下文。

与上述未接线日志分开，共用图片面板已经接入所选文件的 SHA-256 校验：上传响应返回不同资源 hash 时不关联草稿，并给出明确提示；空文件及超过 8 MiB 的文件在上传前拒绝。隔离 PPT 浏览器实际选中红色 PNG、上传并保存 r1，语义重建 PPTX 的媒体字节与所选文件一致；错误 hash 使用组件测试模拟，没有做真实故障代理验收。这项校验不保存上传失败的原始文件，也不表示本机图片选择日志已经接入。

## 2026-10-28：固定版式图片任务接入

PPT/PDF 固定版式图片面板选择文件后，先把原始文件和目标基线写入本机日志，再上传；失败的任务显示文件名、目标和核对重试、下载原文件、取消操作。重新打开不会自动上传。重试时核对写权限、源文件身份与服务端目标版本，写入草稿并确认本机草稿持久化后才移除任务。保存、导出、关闭、PDF 布局升级和切换完整编辑器前会检查任务；使用同源浏览器 Web Locks 串行化任务关联、取消以及这些操作，其他标签页通过广播和重新读取发现任务。浏览器缺少 Web Locks 时不能创建或恢复图片任务，已有任务仍可下载；其他正常编辑在确认本机任务为空时可继续。存储不可读时保存等操作保持阻断，避免忽略可能存在的任务。

隔离 PPT 实验用故障代理阻断图片上传：所选红色 PNG 的任务在第二个同账号窗口打开后可见；该窗口的文字保存被禁用，导出被阻断。恢复连接并显式重试后，图片草稿保存到 r1；从原生服务导出语义重建 PPTX 并读取 ZIP，媒体文件 SHA-256 与原 PNG 一致。[保存结果截图](../assets/hcd-fixed-image-recovery-2026-10-28/saved.png)。另有自动测试验证跨窗口锁阻止在上传期间保存、重开后重试和冲突保护。

验收限于同一浏览器、同一设备和合成单页 PPT；尚未完成 Word 区域模式的同等浏览器验收、跨浏览器/跨设备恢复、存储驱逐以及移动端兼容。固定版式 `.hcd-draft` 仍不包含本机原始图片字节，待处理任务只能从当前设备重试或单独下载原图；这不是跨设备可携带恢复包。

## 2026-10-28：固定版式可携带恢复包基础

新增独立编码器 `hcd-fixed-portable/1`：固定快照包含现有草稿和未确认请求、待处理图片选择以及草稿所引用的暂存图片字节；资源按 SHA-256 去重并逐份验证，校验账号、服务、文档、格式与源文件身份。已暂存但尚未关联的选择在打开后回到待核对状态，不会自动上传或写入文档；缺失、篡改、重复或额外资源均拒绝。遇到当前格式无法表达的协作冲突候选或无法辨认原文件的中断上传时拒绝生成，避免静默丢弃。文件和资源数量、总大小受限；读取资源期间的后续编辑不混入已捕获的快照。

资源读取与重新暂存也已提供独立适配：读取先查文档暂存资源，仅在不存在时回退到文档规范资源，限制响应大小并校验字节哈希；重新暂存从图片魔数判定类型，检查文件哈希和服务端返回的哈希、长度，支持取消。暂存只准备资源，不提交文档编辑。模拟服务覆盖错误回执、权限错误、截断与取消；隔离原生服务上还实际完成红色 PNG 暂存、读取、打包、打开和重新暂存，文档版本保持 r0。尚未接入真实导入流程。

## 2026-10-28：固定版式可携带恢复流程

后续修正图片资源固定：读取已有规范或暂存图片只能证明当时可读，不能防止之后资源被回收。确认导入时先核验恢复包字节，再调用服务端重新固定接口，由服务端在文档锁内验证并建立暂存记录；仅在资源不存在或旧服务不支持接口时（404）上传已核验的包内字节。权限错误、资源损坏或其他服务失败不会通过上传绕过。重复导入会重新固定但不会重复创建草稿或图片任务；文档版本和权限仍在提交前复核。

20 项固定恢复包和资源专项通过。隔离原生 PPTX 服务实测已有图片重新固定、缺失图片首次上传后重复固定、只读成员拒绝以及版本和 root 不变，见[原生验证](../assets/hcd-fixed-recovery-repin-2026-10-28/native.json)。本次尚未验证真实浏览器恢复包上传、资源回收竞态和跨设备。

多张图片的恢复固定改为每批最多四项并发，每批结束重新核对用户权限、来源及版本；任何失败先等待已启动请求结束，不导入草稿，已写入的恢复包仍可重试。原生服务首次并发实测发现文档锁忙会立即返回 409：服务端现将明确的本地资源锁竞争标记为 `HCD_RESOURCE_BUSY`，客户端只对此结果进行有限次数、可取消的短暂重试；其他冲突、权限和完整性错误不自动重试。单次固定请求设置 45 秒上限。此改动不把暂存等同于修改文档，也未证明任何吞吐提升或生产大规模性能。

普通语义附件的资源重固定和上传复用相同的锁忙重试，避免此前多附件并发也遇到相同锁冲突；未知 409 不重试，旧服务没有明确错误码时保持失败并保留恢复文件。63 项资源与恢复专项、服务端错误码测试通过。隔离原生 PPTX 服务的六个不同图片资源分两批完成，实际遇到 11 次锁忙响应后安全重试，两次批次版本检查均通过、规范版本未增加，见[验证结果](../assets/hcd-fixed-recovery-batch-2026-10-28/native.json)。该样例不是浏览器文件导入或生产并发压测，锁长期占用会在有限重试后停止。

补充取消边界：普通附件重固定或上传的响应读取结束后再次检查合并的取消/超时信号，即使测试传输忽略中止并迟到返回成功，也不会把该结果报告为成功。完整前端 1277 项以及随后更新后的 32 项资源专项通过；完整回归运行期间又补充了该取消测试，因此单独专项覆盖最终代码。

普通图片替换入口也统一使用相同的锁忙重试：固定版式图片任务、语义文档图片任务和旧图片面板均共用一次 45 秒期限，取消后不会采纳迟到响应；仅对明确的 `HCD_RESOURCE_BUSY` 重试。固定版式任务测试覆盖上传失败后重新打开、锁忙一次后恢复成功和原图字节保留；语义图片任务沿用其现有本机日志和明确恢复流程。

区域 Word 的独立服务端上传协调器也只对明确的锁忙响应进行有限重试，重试前重新检查成员权限，并遵守原有任务超时、取消和持久化状态；其他冲突保留中断任务供处理。定向测试覆盖重试后只应用一次、未知冲突、取消及重试时权限撤销；尚未针对区域 Word 实际服务并发上传做浏览器验收。

补充隔离服务验证：真实区域协作服务和原生服务上，由两个成员并发上传六个图片选择（共三种图片字节），协作文档中每个选择各出现一次，规范版本未增加；详细结果见[并发验证](../assets/hcd-word-upload-concurrency-2026-10-28/concurrent.json)。这是 HTTP 与 WebSocket 验证，并未监测原生锁忙响应，也没有在浏览器中解决这些同一图片的并发选择或保存该冲突。

固定版式编辑器增加 `.hcd-recovery` 下载、文件选择、隔离比较与确认导入。比较展示服务端版本、草稿与原请求、图片预览及目标变化；按每批 12 项加载，切换批次或确认时重新核对版本。导入不直接保存文档，而是创建独立本机草稿分支，图片选择保留为待核对任务；用户需重新打开并走原有草稿比较、恢复和保存流程。

确认后先把完整恢复文件写入本机待处理日志，再暂存草稿需要的图片，核对服务端身份和版本，分别写入图片任务与确定性草稿分支，最后记录完成。各数据库之间不属于同一事务：中断后原文件仍在待处理日志，重新打开必须再次比较、由用户显式重试；重复导入复用原分支和任务，已完成或取消的任务不复活。用户可下载保留文件，也可在说明后确认放弃中断导入；已经写入的草稿和图片任务不会因此删除。最近的完成记录有限量保留，极旧记录淘汰后的重复导入不作无限期幂等保证。

恢复前会绕过浏览器缓存核验服务端资源：资源仍在时不重复暂存；已丢失时从恢复文件重新暂存，重复导入也会核验并补齐资源。停止等待不会提交文档修改；如果导入已经开始，其待处理文件保留供再次审阅。浏览器故障代理实际模拟暂存资源缺失及上传失败，确认缓存不会掩盖故障；资源存在时避免重复上传、资源缺失后重新暂存由自动测试验证。

隔离 PPT 浏览器实际下载包含未提交文字和暂存图片的恢复文件，阻断图片暂存后确认导入，重新打开文档并比较保留的中断文件，恢复网络后确认导入，再重开、恢复草稿并保存 r1。实际导出的 PPTX 回读包含原文字修改和所选图片；请求记录显示一次初始暂存、一次故障暂存和一次用户确认后的重试，文档只提交一次。[比较界面截图](../assets/hcd-fixed-portable-recovery-2026-10-28/review.png)。另一个图片选择尚未上传的样例验证了恢复文件包含原始图片并且重复导入显示已导入。自动测试覆盖存储中断、重复导入、撤权、版本改变和比较分页。

最初验证限于同一浏览器、同一设备和合成单页 PPT，后续 PDF 与 Excel 验收见下文。文件不包含完整 HCD 文档，恢复仍需访问同一服务及匹配的文档、账号和源文件，因此不能视为完整离线编辑包。原始下载文件应由用户保留。

## 2026-10-28：共用恢复资源批次的失败取消
