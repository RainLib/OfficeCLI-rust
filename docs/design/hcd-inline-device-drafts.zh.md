# 行内容器共享客户端与设备草稿（2026-10-27）

本轮补齐主编辑页接入前的协议和本机恢复路径，未移除主编辑页对 Inline1 的保护提示。节点属性、资源面板和默认命令还需与模型一起接入，不能只扩大 schema 就开启编辑。管理平台和提醒发送保持后置。

## 共享客户端

- `api` 根据已确认的 `hcd-semantic-inline/1` 会话发送 inline 1、envelope 3 和 wire 7 的请求头；旧会话保持原模型。
- 内部 `negotiateSession` 需要宿主显式提供 `{inlineContainers: true}`，同时验证返回的协议、inline 1 与 wire 7。缺少确认、模型不符和降级返回在连接前拒绝；已取消的请求不打开网络连接。
- 普通文档被误带行内容器确认头时，sidecar 在发起任何迁移前拒绝。实际独立普通文档保持 r1、原协议和 epoch，协作状态仍为 404，正文未改变。
- 删除审阅的 `restoreInlineDeletion` 已支持 Inline1 的准确 epoch 与模型请求头。整版本还原继续保持未开放。

这些是共享内部客户端接口，尚未作为独立 SDK 的新导出声明。

## 设备副本隔离

本机 IndexedDB 身份保留原端点、文档、用户、epoch 的隔离，并新增 `-inlinecontainers1` 后缀。原 `-structure3` 与无后缀旧协议副本仍可查找、下载，不能跨协议自动合并。访问凭证不进入数据库名称。

区域 Word 与固定布局日志复用中性的端点/成员散列，继续添加各自的模型后缀，不借用普通语义草稿的协议准入。已有日志库名称保持兼容；全量检查发现并修正了区域 Word 被新协议检查误拦截的问题。

识别本机文档需要结构元数据和 schema 的两处 inline 1 确认。未来正文、属性载体或 v2 删除记录不能被误判成普通结构文档。恢复预览使用支持嵌套正文的 schema，以有界纯文本展示，不执行缓存 HTML。

Inline1 的网络加载、设备日志加载、恢复候选和空草稿都从创建起使用 `gc: false`。日志仍沿用原子 append/compact，不以当前窗口的旧 snapshot 覆盖其他窗口；已删除正文字符的永久 Yjs 内容与身份在 compact、重新加载后保留。

## 恢复的权威边界

`restoreLocalDraft` 在隔离文档中合并缓存与当前服务器副本。保存回执、schema、图片回执、结构和文字流元数据、规范块身份及已有正文的来源默认值以服务器为准。

递归行内正文沿用当前有效来源标识；退休来源只移除标识，保留文字、格式、独立正文与同伴新输入。新增离线行内容器仍保留自己的永久分配。合并完成后，用与实际 sidecar 相同的 `inlineRoomGuard` 验证增量，确认没有替换已有正文、定义或服务端元数据，才返回恢复候选。

不合法副本不能修改服务器或擦掉原设备日志。原设备原始字节仍可保留；候选失败时销毁隔离文档，不把缓存的元数据当成保存授权。

恢复候选不兼容时，主恢复入口沿用 `HCD-DOC-4002` 的明确错误页与描述，不误报为磁盘不可用或网络故障。

原始恢复下载独立于 schema 解释：已知模型记录准确的协议，未知或损坏的模型仍导出精确 Yjs 字节，不猜成旧协议，也不因增加模型说明而阻断备份。

后续继续主编辑页的 inline 注册表、属性/资源面板、命令、历史保护、保存状态与导出能力接入，以及已有旧协议草稿的审阅迁移。总体实施清单保持完整，不因本轮共享客户端通过而将全部阶段标为完成。

主页面接入时还需同时处理以下边界：

- 模型 3 的初次协商不能先创建旧协议房间；已有旧草稿必须先审阅，不能借初始化绕过保护。
- 协商后的有效 Session 必须传给扩展资源服务，不能让上层注册表继续用升级前的请求头归档文件。
- 模型 3 不能按 chunk 数量自动落到只懂普通分段文字的编辑路径。正文 schema、结构绑定、snapshot、历史和保存回执都需要同一模型确认。
- 原子节点与富文本块的旧注册接口保持兼容，行内容器使用独立定义与解析；属性冲突、资源任务、删除审阅和迁移不能通过类型断言冒充旧 payload。
- 最后使用主编辑页进行真实浏览器恢复选择、节点操作、缺失扩展只读、协同和导出复验，再移除当前保护提示。
