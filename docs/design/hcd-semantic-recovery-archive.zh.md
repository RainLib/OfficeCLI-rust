# 语义协作离线恢复包内核（2026-10-27）

上一轮确认规范 HCDZ 不包含待处理的 Yjs 协作状态。本轮新增独立 `hcd-semantic-recovery/1` 文件内核，将规范归档、未保存协作状态和恢复需要的资源带到同一个文件。原 HCDZ 保持规范版本归档语义，没有把协作回执、ACL 或服务密钥塞入原格式。

## 文件内容与读取边界

`semanticRecoveryArchive.ts` 提供创建和读取接口，支持既有结构模型以及显式内部行内容器模型：

- 作用域为文档 ID、epoch、正文模型、规范版本和根摘要。字段顺序不影响作用域比较，不推测旧模型或跨 epoch 合并。
- 规范 HCDZ 和完整 Yjs 状态各有长度、SHA256 与严格 Base64。完整状态保留独立正文、属性候选、删除回执、来源捕获和签名未知提交记录。
- 资源清单包含可见和隐藏内容、永久容器定义、保留正文、行内墓碑以及各属性候选的原始/修改前/修改后资源。不能只扫描当前可见段落，否则会漏掉迟到或撤销相关附件。
- 资源字节按内容摘要去重。未完成节点文件选择保留目标、阶段、描述和原始字节；字节复用同一资源表，不重复嵌入。已取消/已完成选择不能冒充待处理任务，读取后不自动上传或关联。
- 创建先捕获一份独立 Yjs 副本，再异步读取字节；用户在打包中继续输入，不会得到混合时刻的正文和资源。
- 每项字节核对摘要与长度；缺项、多余项、重复项、格式损坏或资源读取失败均拒绝产生可用候选。上限为文件 96 MiB、规范 HCDZ 48 MiB、Yjs 8 MiB、资源表 16 MiB/256 个、未完成选择 16 个，单资源沿用 8 MiB 限制；总文件上限仍是最终约束。

创建和读取均要求显式 `verifyCanonical`，核对规范归档与所声明的文档/版本/根摘要。实际文件验收使用原生 `hdoc unpack`、`validate`、`get-revision`，复用其 ZIP、路径、历史、资源和完整性校验，不以扩展名或客户端摘要代替原生校验。

SHA256 只证明文件内部一致性，不授予写权限。读取结果类型明确标记 `isolated-recovery-candidate`，使用新的 Y.Doc，没有自动加入房间、覆盖当前文档或执行保存。文件中的旧签名回执也不能自行成为当前授权；在实际在线恢复验收中，仍由协调器校验签名谱系、当前版本、epoch、真实操作人和 CAS。包中不包含 Bearer token、服务密钥或权限配置。

## 验证

证据目录：`docs/assets/hcd-semantic-recovery-2026-10-27/`。

12 项新增测试覆盖普通与内部模型、隐藏正文/删除回执、未完成文件原始字节、打包期间继续输入、字节损坏、清单缺失/重复/多余、作用域不符、必须执行规范验证、错误 UTF8/Base64/长度/字段、终态选择不可复活，仅存在于保留属性候选中的未提交资源，以及图片任务不会被静默遗漏。完整前端 **978 项通过**，standalone/embed 双构建及最终 TypeScript 检查通过。

实际文件链路扩展既有原生丢响应场景：

1. Alice 删除容器并提交 r9 后，测试代理断开真实 TCP 响应；离线同伴对被隐藏正文输入并修改属性。
2. Bob 以真实成员授权上传一个尚未提交的附件，并将描述写入迟到属性。协调器服务身份不能代替成员调用此上传路由。确认该附件字节不在规范 r9 HCDZ 的 ZIP 清单内。
3. 新进程打包 r9 HCDZ、待处理 Yjs、原有资源、已上传未提交附件和另一个未完成文件选择。资源通过原文档的授权接口读取，未发布资源走 staging，已发布资源按保存版本回读；最终逐字节验证。
4. 另一进程从恢复包而不是另存的裸 Yjs 文件读取候选，验证规范归档，并通过原协调器的签名恢复流程确认未知提交为 r9。删除审阅中的正文、属性和附件仍在。
5. 两个并发恢复请求仍只插入一次，r10 实际保存成功。DOCX/PPTX/PDF/Markdown 共八份导出，以及 r8/r9/r10 HCDZ 和实际资源回读继续通过。新增附件随恢复后的规范节点归档；未完成文件选择没有自动进入正文或导出。
6. 原生服务与代理停止后，再启动独立进程。只使用恢复包和本地原生读取器，验证 r9 规范归档、隐藏正文/属性的一条删除审阅、三个资源的完整性和两类未提交原始字节；没有网络请求或房间连接。

规范归档可单独使用，恢复包则额外保留待处理状态。两者不是同一种文件。恢复包中的未保存内容不会凭打包动作进入规范版本，也不会被当作已保存内容显示。

## 尚待接入

本专题最初交付恢复包内核与实际文件验收；后续普通 `structure3` 编辑页已接通导出、导入比较、确认合并与未完成节点文件的私有日志。实际双人浏览器、个人撤销和原生 r4/八种文件验证见[编辑页恢复包](hcd-semantic-recovery-ui.zh.md)。其他模型与旧 epoch 的协调迁移仍未开放，不能把隔离候选读取等同于所有活动房间导入成功。

目前未统一固定布局/区域 Word 恢复包，也未纳入原生图片上传中的全部本机任务。若 Yjs 中仍有图片任务，内核明确拒绝本包，而不生成缺少图片字节的伪完整备份；调用方仍须保留现有设备草稿。创建者必须显式提供节点文件日志快照（没有任务时传空数组），不从正文状态猜测外部文件选择。公开行内容器 SDK、缺 codec 只读视图、活动房间协商/迁移、复制/迁移、结构恢复冲突与原七阶段其余目标仍继续。管理平台和提醒投递后置。
