## 模型

复用 `hcd.extension/2` 的行内 atom，而不是给现有快照、设备文件和协作协议增加可被旧客户端静默丢弃的新 Inline 字段。内置业务类型是 `officecli.word.numeric_field`、版本 1；`data` 只包含 `kind` 和 `format`：

- kind：PAGE、NUMPAGES、SECTIONPAGES。
- format：inherit、arabic、upperRoman、lowerRoman、upperLetter、lowerLetter。
- 实例身份仍为 `x_` 加 32 位小写十六进制，复用复制重映射、字段协作、个人历史和资源包中的现有扩展身份机制。
- display 必须 inline；不接受子内容或资源。规范 fallback 分别为 `[PAGE]`、`[NUMPAGES]`、`[SECTIONPAGES]`，表示尚未计算的占位，不填写虚构的页码。
- 七种目标都保存有界的便携快照。DOCX 声明语义适配，其他格式明确为静态文字。版本 1 的 fallback 和快照必须与数据完全一致，不能以业务 JSON 或快照注入指令、任意格式或外部文件引用。
- 不认识的未来版本保持普通、不执行的扩展信封，通过可读回退保留数据；原生层不会按已知页码版本解释它。

`WordNumericField` 根据枚举生成指令，客户端不能直接提供任意 instruction。已有导入域的 `hcd-word-field/1`、缓存和整块只读保护保持原表示，新建节点不授权改写那些缓存。

## 原生适配路径

核心便携适配器在 DOCX 目标为已知内置节点生成专用的开始/结束标记，并附有受限的类型数据。HTML、Markdown、TXT、PDF 等不产生这些动态标记。普通 HTML 快照仍保留可读节点信封，不能把静态占位称为已计算页码。

DOCX 转换器只在对应目标显式启用该类型通道，重新检查类型数据、身份唯一、嵌套上限和开始/结束匹配，生成 typed rich-run 控制。域指令由枚举导出；普通 HTML 中的旧 opaque 指令标记仍不因这一通道获得执行或保留权限。

区域 Word 在适配前清点原有域及新建节点，适配后核对控制数量，防止静默丢失。普通语义 HCD 的 DOCX 导出也使用同一便携适配及解析通道。生成文件请求目标应用更新域；普通新建 DOCX 缺少 settings 时补齐部件、内容类型和文档关联，重复请求不叠加 updateFields。整个过程在私有生成文件中完成，再按既有规则发布，不改规范版本。

## 当前验证与准确边界

最终核心 **126 项**、DOCX 导入/区域 **80 项**和转换器 **57 项**通过；原生构建、修改文件的 Rust 格式检查和核心库严格 Clippy 通过。前一批阻断 Clippy 的区域索引布尔表达式作了等价简化；全目标严格检查继续被已有的五个核心测试写法及 `story_link_verification.rs` 的布尔表达式告警阻断，日志保留。本批没有前端实现变更、前端全量或浏览器构建新结果。

原生专项和 CLI 文件结果以[验证汇总](../assets/hcd-word-field-insert-2026-10-30/validation.json)为准；[文件结果](../assets/hcd-word-field-insert-2026-10-30/files.json)和[实际命令](../assets/hcd-word-field-insert-2026-10-30/commands.json)记录本机合成样本的范围。没有浏览器插入、实时协作、真实设备、外部 Word/WPS 重算或生产验收。

初次通用转换测试发现普通空白 DOCX 没有 settings 部件，三个测试失败；已补齐部件及关系后复查。原失败日志 `native-field-final.log` 与后续日志均保留，不能只记录最后一次通过。

CLI 验证在真实文件中创建正文 PAGE/NUMPAGES 和页眉 SECTIONPAGES，拒绝任意指令及重复身份，删除页眉节点后再还原为新版本。r2/r3/r4 DOCX 核对指令、部件位置、纸张尺寸、原图片及更新设置，重新导入识别为受保护原生域。HCDZ 完整回读 r0–r4，并从离线包导出 DOCX；普通 HTML 来源的语义 HCD 另验证相同的 DOCX 适配链路。DOCX 再导入采用原生只读域表示，不自动恢复原内置扩展实例身份；HCDZ 保留原节点和规范历史。

最终样本在导入/投影后删除本批自己的 DOCX 和 HTML 原文件，再执行修改、导出和离线回读；HCDZ 的 56 个规范文件与当前包逐字节一致。不是仅仅省略 `--source` 参数后假设原文件不可用，仓库中的原始测试夹具没有删除。

复验脚本的初始操作标签误写为 `type`，已按实际 DTO 改为 `op`；节末插入会更新 canonicalEndBlockId，验证现在比较其余布局设置而不要求这个收据身份不变；归档输出不允许覆盖，脚本改为每次在自己的全新目录打包，再复制已验证产物。相应初始日志保留。这些是验证器修正，不是放宽域类型、改变产品保护或伪造浏览器步骤。

## 仍需接通的同一工作包

1. 服务端声明该内置节点的确切版本，客户端只在已确认支持的 Word 入口注册。旧服务和未知声明不开放创建，但保留已有数据及只读回退。
2. 注册统一命令和 Notion 风格 `/` 项目；光标插入、空块、块后插入、保护选区和只读门禁使用现有命令状态。页眉页脚可选已有区域；缺少区域沿用现有创建/链接流程，不写入错误的节或变体。
3. 右侧属性使用有限选项切换页码种类与格式，并复用字段冲突、过期选择和个人撤销。该内置节点没有附件，属性面板及 SDK 应按节点能力禁用附件操作。
4. 真实双成员操作涵盖插入、同伴输入、个人撤销/重做、字段冲突、删除、保存中继续输入、关闭重开和设备备份恢复。不能用原生历史还原代替浏览器个人撤销验收。
5. 浏览器下载 DOCX/HCDZ、离线解包和再导入需要保留节点、域、原内容及资源；静态目标明确说明占位降级。未完成分页时界面不得把占位当作真实页数。
6. 继续实现浏览器分页与域重算、自动目录，以及整个目标中的其他格式创作和运行条件。该内置 atom 不代替分页引擎，也不将整个 Word 基础能力缩减为导出兼容。
