# 无源 XLSX 的公式保护缺口与实现要求

2026-10-28。此文记录待实现问题，不表示已有无源公式安全证明或迁移。

## 当前证据

`apply_editor_edits` 在 XLSX 最新版本保存时，仅在 `sources/<documentId>.xlsx` 存在时调用 `validate_xlsx_source_text_edits`。该函数核对原文件摘要和大小，并扫描目标所在工作表的公式单元格及数组、数据表结果范围；文件缺失时服务端继续依赖现有源映射。旧导入器产生的映射可能将公式结果误标为可编辑，因此无源的旧 bundle 存在把结果当普通文字保存的风险。已有源码级测试覆盖有源旧映射的拒绝、普通单元格保存及幂等回执；没有证明无源旧映射安全。现有版本中已经保存的错误内容也不会因此自动修复。

不能简单把所有无源 XLSX 都判为不可编辑：HCDZ 和离线工作流允许只携带规范文档。反过来，不能仅凭来源格式、当前节点 `editable`、schema 版本、文件名或客户端自报的标志认定映射经过新版公式扫描。现有 manifest 对未知字段严格拒绝，新增能力字段还会影响旧读取器，需要版本协商及兼容设计。

## 需要实现和验收的闭环

1. 定义可信的导入证明：覆盖整个工作簿所有工作表、独立公式、共享公式从属单元格，以及数组和数据表结果范围；证明与源摘要、规范映射和导入算法版本绑定。验证成功前不颁发证明。对外部导入的 bundle，明确证明的真实性边界，不能把任意可修改的清单标记当成服务端认证。
2. 新导入与可携带归档保留该证明；证明能在源文件不随包提供时校验。未知版本、损坏、不完整或不匹配时禁止依赖它授权编辑。需要保证已有历史版本、下载和旧读取器的兼容或明确阻断，不能静默降级。
3. 保存前优先使用已验证的原 XLSX 校验目标；无源但证明可信时使用证明保护公式范围；无源且无法验证时保留用户草稿并明确说明需要原始文件或安全迁移，不能报告保存成功。原请求已提交但回执丢失时仍须先完成幂等回执查询，不能误判为未提交。
4. 提供旧文档迁移：核对原文件摘要、完整重扫并验证现有映射，产生有版本和并发保护的迁移结果；发现已有错误版本时报告差异，不自动覆盖历史或草稿。迁移、同格冲突、用户撤权和中断后的重试均需独立验证。
5. 验证新版及旧版、有源/无源、恶意或过期证明、共享/数组/数据表公式、普通单元格、重复请求、并发修改、源文件变化和保存中断；实际下载 HCDZ、在独立存储恢复、保存并回读 XLSX，同时验证大表扫描开销。浏览器测试应检查提示、草稿留存及修复后的重试；本机合成样例不能替代跨设备或生产验收。

在以上闭环完成前，能力矩阵继续将“旧错误映射无源时无法借源文件验证”列为开放项；不要把新版导入的公式只读映射扩大解释为所有历史文件的保证。

## 导入源身份复核增量

XLSX 导入原先只在读取工作簿之前计算源摘要；导入期间如果源路径被替换，可能完成一个与当前源文件不匹配的清单。现在发布清单前重新计算摘要和大小，发现变化时发出失败事件、不发布完成清单。测试在首个 `ChunkReady` 事件期间原子替换源路径，验证失败、无完成事件及无 manifest；XLSX 的 14 项源码测试通过。

后续导入改为先复制一份私有临时快照，核对快照与起始源摘要、大小一致后，仅从快照解析；复制量按起始文件大小加一字节限制。最终仍复核原路径。新增测试在解析首个分块后原地覆盖源文件，在后续分块恢复原字节，确认导入内容仍来自快照；永久替换源文件则拒绝发布。XLSX 15 项源码测试通过。

快照保证本次解析不受随后原文件写入干扰，但最终复核与发布之间仍不是文件系统原子操作，不能保证原路径此后不会改变；后续有源操作仍必须检查摘要。临时快照占用最多约一份源文件的额外磁盘空间，复制和多次完整读取尚未进行大文件性能验收。它不提供可信公式扫描证明，不修复旧映射，也不改变当前无源保存行为。

保存端的有源公式检查随后也改用同一快照机制：先核对清单源身份和快照字节，再扫描快照中的公式和结果范围，避免对原文件做摘要校验后又扫描到另一份内容。非文字操作不创建快照；源文件与清单不匹配仍返回原有 `XLSX_SOURCE_CHANGED`，草稿与回执处理保持原协议。格式层 16 项 XLSX 测试、服务端旧映射公式拒绝/普通格保存/幂等回放专项测试通过。此机制每次有源文字保存会复制并读取源文件，增加磁盘空间及 I/O，尚无大表或高并发性能验收；它不能保护无源旧映射，也不能保证之后原路径不被替换。

共用源身份读取现按实际读取的字节计算大小和 SHA-256，超出 256 MiB 即拒绝；实际长度与读取前元数据不一致也拒绝。此检查覆盖文件在读取中增长导致原先只靠元数据的上限失效，以及旧长度与摘要不匹配的情形；同长度并发修改仍需各格式的快照或其他一致性保障。受控测试覆盖实际字节摘要、边界和超限，`hcd-formats` 59 项测试通过。

## 旧映射的只读核对基础

新增格式库接口 `audit_xlsx_editable_formula_map`：校验当前 HCD、读取经过摘要验证的映射，限定最多 100 万个可编辑单元格，使用与清单身份匹配的源文件快照检查公式及公式结果范围；重复可编辑坐标、非法映射、超限和不匹配源均拒绝。测试构造旧映射将数组公式结果标成可编辑，核对拒绝该映射和错误源；另验证正常公式映射通过以及共享、数组结果保护。XLSX 17 项测试及修改文件格式检查通过。

此只读库接口不修改映射、创建证明或授权无源保存；它只检查当前版本映射，不证明历史版本或未映射内容的业务正确性。直接调用库时核对和并发修改未形成事务，内存随可编辑单元格增加，上限之内的大表耗时及内存尚未验收。真正迁移仍需固定版本、可信证明、回执和失败恢复。

随后接入 `officecli hdoc audit-xlsx-formulas workbook.hcd --source workbook.xlsx --json`。命令先在文档写锁内创建并验证带历史资源的固定快照，随后对该快照和原工作簿执行核对；结果返回文档 ID、版本、检查数以及 `sourceFreeEditsAuthorized: false`。这是只读诊断，不创建迁移或授权；另一进程持锁时会失败，需稍后重试。快照包含历史资源，受离线归档数量和容量限制，且会额外占用临时磁盘空间。无源旧文档仍不能由该命令直接核对。

服务增加只读 `GET /v1/documents/{id}/xlsx/formula-audit`，可选 `revision`；按文档读取权限验证，返回固定快照版本、检查数和 `sourceFreeEditsAuthorized: false`，使用 `private, no-store`。缺少源、源不匹配和公式冲突分别返回明确错误。处理使用阻塞线程，返回前重新核对访问权限；现有访问门禁持有读锁期间，权限变更会等待处理结束。该接口不上传源文件、不修改版本，也不创建可信证明。服务函数测试覆盖成功、未授权、缺少源、源不匹配和公式冲突。

工作簿操作区新增手动“检查公式保护”，请求用户当前看到的保存版本；结果说明不覆盖未保存草稿、不授权无源编辑，版本变更后提示重查。隔离服务实际 HTTP 测试覆盖读取成功、未授权、源缺失及源不匹配；浏览器实际显示 r0 的 5 个可编辑单元格检查结果和源缺失提示，见[检查截图](../assets/hcd-xlsx-formula-audit-2026-10-28/passed.png)及[缺失提示](../assets/hcd-xlsx-formula-audit-2026-10-28/missing.png)。这不是旧映射自动修复，耗时期间的版本和权限竞争、跨设备和大表并发压力仍待验收。

后续在独立合成样本中，将源工作簿 A1:B1 设置为数组公式范围并保留模拟的旧可编辑映射，实际 HTTP 核对返回 422 `XLSX_FORMULA_READ_ONLY`，浏览器显示冲突且 r0 未变化。阻断保存后编辑普通 B2，再次核对仍保留可见草稿；恢复连接并核对原请求后保存 r1，旧核对结果提示版本变化。重新检查 r1 仍显示冲突。实际源格式 XLSX 回读确认 B2 的新值、数组公式范围和另一个原公式均保留，见[冲突与草稿截图](../assets/hcd-xlsx-formula-audit-2026-10-28/conflict-draft.png)。该样本通过测试代码构造旧映射并改写清单的源身份，不是生产旧文件或安全迁移；此次验证是结果显示后版本变化，不覆盖检查正在运行时的精确并发和权限变更。

## 固定版本映射身份基础

新增只读 `audit_xlsx_formula_mapping_snapshot`：先在文档锁内制作并验证固定版本，核对源 XLSX 后，对文档 ID、源摘要和长度、每个节点的源映射及其网格窗口生成确定性摘要。摘要包括只读节点和可编辑标志，拒绝重复节点 ID，并设有节点数上限；不包括文字值，因此普通文字保存后映射未变化时摘要保持一致。测试覆盖指定历史版本、普通文字编辑、不同文档身份、错误源以及旧数组公式映射冲突。

后续摘要计算还读取并校验固定版本的网格 HTML，将每个显示单元格的位置、节点映射和工作表身份交叉核对；重复位置、节点缺失、位置不一致、异常标签或可能被浏览器修复的非规范结构均拒绝。位置和节点数量受限。受控测试覆盖错位、跨工作表、重复、缺失、异常标签及普通文字修改后摘要稳定。

单独的摘要并不是可信证明。

## 本服务的签名证明与无源保存门禁

编辑器在检查通过后为有写权限的成员提供“启用无源保护”：服务端对指定保存版本重新执行完整核验，以独立用途密钥签名文档身份、原始 XLSX 摘要和映射摘要，并将证明保存在本服务私有目录。服务端不会接受客户端提供的证明。原文件缺失时，当前版本的单元格文字保存需要本服务证明及当前映射再次核对；缺失、损坏、密钥变化或映射变化时返回 `XLSX_FORMULA_PROOF_REQUIRED`，界面保留草稿并说明需要恢复原文件。原请求结果未知时仍先查询回执；已提交旧请求的重放不因后续源文件或证明缺失而被拦截。

受控服务测试覆盖只读用户无法启用、旧公式冲突不能签发、源文件缺失时未证明版本拒绝、有效证明支持两次文字保存、密钥变更拒绝以及旧回执重放；前端草稿测试覆盖明确拒绝后的回执检查和草稿保留。常规有源保存仍按目标重新扫描原文件。签名证明不修复已经误存的历史版本，也不赋予公式编辑能力。

隔离工作簿的实际浏览器测试中，写成员检查 r0 并启用证明后，临时移走源文件，A1 修改保存为 r1；再移走证明，B1 修改保持为草稿并显示保护提示，规范版本仍为 r1。恢复证明后点击保存得到 r2；恢复原始 XLSX 后导出，回读 A1、B1 的修改及 C1 原公式 `1+2` 均保留。见[启用证明](../assets/hcd-xlsx-source-proof-2026-10-28/enabled.png)、[无证明保护](../assets/hcd-xlsx-source-proof-2026-10-28/blocked.png)及[文件回读](../assets/hcd-xlsx-source-proof-2026-10-28/readback.json)。这是同机合成样例，源文件和证明的移走用于故障模拟。

证明目前仅在本机服务私有存储中有效，不随 HCDZ 或恢复包跨服务迁移；远端存储模式不支持签发或使用此证明。没有原文件也没有本服务证明的旧文档不能直接保存单元格文字，需要先恢复匹配的原文件并完成核验。签名密钥轮换会使旧证明失效。尚未验证跨物理设备、权限在长时间核验期间变化、大表性能与多实例持久证明；不能把完全离线编辑或所有公式特性宣称为已完成。

2026-10-29：工作簿公式检查和启用保护的客户端回执限制为 64 KiB，校验 UTF-8、目标版本、检查数量及授权范围；即使传输不响应取消，等待也可结束。启用请求的响应丢失或无效时，界面提示结果未确认、服务端可能已经启用，要求重新检查；它不会修改单元格草稿。10 项公式检查、源恢复和有界响应专项及 TypeScript 检查通过。使用实际客户端函数与隔离原生服务的[合成 XLSX 样本](../assets/hcd-xlsx-audit-client-2026-10-29/native.json)，验证 r0 检查 5 个单元格、启用保护、只读成员被拒绝且文档根和版本不变。测试不是浏览器故障注入、跨设备或生产服务验收，仍需重新检查才能重试启用。

## 命令行写入边界

`hdoc apply` 对 XLSX 单元格文字修改也要求原工作簿：可使用 `--source <原始.xlsx>`，或由文档同级 `sources/<documentId>.xlsx` 提供。写入前核对源文件身份并检查目标公式及结果范围；无源、源不匹配或公式冲突均不提交版本。已提交请求使用原请求和原 `--expected-revision` 重试时，可在源文件缺失后返回同一回执。命令行目前不读取服务私有签名证明，也不修复已有历史；直接调用底层 `hcd-core` 的库使用者仍须自行实施相同来源校验。

CLI 端到端测试使用模拟旧映射：缺少源、错误源和公式单元格均拒绝，普通单元格在核对源后保存，随后无源重放原请求不新增版本；原生 XLSX 导入、保护和导出回归也通过。

## 从原文件恢复服务端源

工作簿在源文件缺失、身份不符或未证明时，提供“恢复原始工作簿”。写成员选择文件后，服务端流式校验实际长度和 SHA-256，只有与当前文档的导入源完全一致才写入私有源目录；上传和检查不会保存或清除本机草稿，也不会自动签发证明。用户可随后检查公式保护，或按已有流程重试保存。上传按导入源长度及 256 MiB 限制，并限制并发与等待时间。

重复恢复同一文件会复用已有源；如果目标路径已经存在不同文件，返回冲突而不覆盖，需先由服务管理员处理。中途失败保留草稿，不发布临时文件。服务器重新检查写权限和文档源身份；远端存储模式暂不支持此入口。受控服务测试覆盖只读权限拒绝、错误文件、成功及重复恢复、同时恢复、现有冲突和原文件字节保留；这些测试不代表跨主机存储或真实移动网络验收。

隔离本机 HTTP 实测覆盖只读成员拒绝、错误源拒绝、正确源恢复、重复请求复用、恢复文件 SHA-256 一致、公式核验及证明签发；结果见 [HTTP 摘要](../assets/hcd-xlsx-source-restore-2026-10-28/http.json)，复现脚本为 `scripts/hcd-xlsx-source-restore-http.mjs`。浏览器在缺少源文件时显示[恢复入口](../assets/hcd-xlsx-source-restore-2026-10-28/restore-entry.png)；本次没有通过文件选择器执行上传或验证浏览器上传中断。
