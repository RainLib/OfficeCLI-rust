## 设计结论

保留现有 Tiptap/ProseMirror + Yjs 基础，把菜单、节点、格式和 AI 能力从页面组件中抽出。日常写作采用 Notion 式就地操作，页面、文字、图片和幻灯片属性沿用紧凑 Office/PS 工作区。保存、导出继续放在操作区。Word、PPT、PDF 共用命令发现、权限、建议和属性协议，各自保留适合文档类型的编辑适配器。

“支持自定义节点”必须同时满足：可编辑、可协同、可撤销、可持久保存、可恢复、可查找，以及对目标文件有明确转换结果。只提供 React NodeView 或 Tiptap Extension 不算完整支持。

参考依据：Tiptap 的 [Extension API](https://tiptap.dev/docs/editor/extensions/custom-extensions/create-new/extension) 提供 commands、keyboard shortcuts 和插件扩展点，[Suggestion utility](https://tiptap.dev/docs/editor/api/utilities/suggestion) 可组织触发字符和候选列表；Notion 的 [写作与编辑](https://www.notion.com/help/writing-and-editing-basics) 和 [快捷键说明](https://www.notion.com/en-gb/help/keyboard-shortcuts) 提供块操作、选区格式与 `/` 内容插入的交互参考。以下架构是本项目设计，不是这些产品的内部实现说明。

## Notion 式交互要求

| 入口 | 行为与边界 |
|---|---|
| `/` 插入菜单 | 在允许的文字位置打开；中文/英文关键字与别名过滤；分组、图标、简短说明、上下键/Enter/Esc。选择成功才在同一事务删除触发串并插入，取消保留原文 |
| 块旁 `+` | 显示与 `/` 相同的可插入命令，操作指定块的前后位置，不跳到文末 |
| 块手柄/菜单 | 转换类型、复制、删除、移动、颜色、链接、评论、AI；根据选区、父容器和文档权限过滤。拖动限制在合法结构，保留块身份 |
| 选区浮层 | 常用行内格式、链接、颜色、块类型与“询问 AI”；复杂属性进入右侧栏。浮层靠近选区且不遮住输入 |
| 命令面板 | 首批已用 Mod+Shift+P；Mod+K 保留链接语义。支持宿主重绑定和平台按键显示；后续与 slash/块菜单协调优先级 |
| 行内候选 | `@` / 其他已注册触发符打开异步候选；加载、空结果、失败明确可见；过期查询取消，候选可由业务服务供给 |
| AI 补全 | 采用灰字预览；显式启用后在停顿时触发，Tab 接受、Esc 关闭，冲突场景让位给列表缩进和其他菜单 |

中文输入法组合期间不触发菜单提交、自动格式和 AI 请求；完成输入后再判断。空格保留正常输入，不默认占用空行空格作为 AI 入口。菜单拥有焦点时先处理菜单导航；普通文本和操作系统保留键不能被全局抢占。支持滚动容器、缩放、边缘避让、屏幕阅读器、RTL 和触屏替代按钮。只读状态可查看，写操作必须同时通过服务端鉴权。

## 扩展分层与注册协议（待实施）

1. **能力层**：文档 profile、选区、可编辑区域、角色、节点版本、导出目标决定当前允许的行为。UI 隐藏/禁用原因与服务端校验一致。
2. **命令层**：一个命令定义 id、翻译键、别名、分组、顺序、快捷键、适用上下文、canExecute、isActive 和 execute。菜单、工具栏、右键、属性和 AI 工具调用同一命令。
3. **内容层**：节点/mark 扩展定义 schema、验证、codec、视图、文本提取、导入导出和迁移。界面状态（折叠展开、浮层位置、AI 灰字）不混入规范正文。
4. **事务层**：命令经文档适配器生成结构化事务，保留 source identity、协作相对位置、撤销边界和保存前置条件，不能绕开既有 coordinator 直接覆盖文件。
5. **服务层**：AI、提及搜索、资源上传等能力通过接口注入；NodeView 不直接绑定外部厂商 SDK、凭证或存储。

当前 `EmbeddedHcdEditor` 使用 `commandExtensions`、`nodeExtensions`、`aiExtensions`；下述更广的组合扩展接口仍为后续设计，不是可直接传入的 props。Tiptap 原生扩展只作为内部适配，不能任意注入未经 codec/服务端支持的 schema。

以下为接口轮廓，不是已交付 SDK：

```ts
interface EditorExtension {
  id: string                    // 例如 acme.callout，命名空间避免冲突
  version: number
  requires: string[]
  commands: CommandDefinition[] // 同一命令的多入口呈现
  nodes: ContentDefinition[]    // block / inline-atom / mark
  aiTools?: AiToolDefinition[]
  dispose?: () => void
}

interface ContentDefinition {
  type: string
  version: number
  kind: 'block' | 'inline-atom' | 'mark'
  schema: JsonSchema
  codec: HcdContentCodec
  migrations: ContentMigration[]
  toPlainText: PlainTextSerializer
  exporters: Partial<Record<ExportFormat, ExportAdapter>>
  fallback: ExportFallbackPolicy
}
```

注册时检查重复 id、依赖缺失、循环依赖、快捷键冲突、不可用 codec 和导出策略缺失；错误在挂载/启用时报告，不等用户保存才发现。菜单排序稳定，宿主可增加、隐藏、重排和替换显示，执行仍经过统一授权。扩展按需加载；schema 集合须在协同文档挂载前确定，改变节点集合要走版本协商，不能在活动房间中直接热换 schema。

自定义菜单执行已有命令可先开放；自定义节点必须等待前后端内容协议扩展。建议新增版本化扩展载荷（type/version/受限 JSON attrs/合法 children/资源引用/静态 fallback），具体 schema 与当前固定枚举的升级另作原子变更。未知类型需原样保留并显示只读占位，旧客户端缺失 codec 时禁止结构性写入，不能静默丢节点或把它转成空段落。后端、sidecar、浏览器、CLI 和导出器必须按同一兼容清单验证。

动态加载任意第三方脚本不属于第一阶段。优先支持宿主打包的可信扩展与配置驱动的业务节点；真正的插件市场、远程安装和租户分发留待管理平台阶段。

示例：增加“风险提示”块应只需一个扩展包声明菜单 `insert-risk-callout`、节点 `acme.risk`、属性面板、可搜索纯文本和导出适配；不应在六处 UI 分别补按钮。增加“客户提及”应声明 inline atom、稳定业务 id、显示文字、异步候选来源与离线快照；导出后的显示不能依赖临时 URL 或在线鉴权。

## 通用 AI 能力（首版与后续）

实际协议、宿主接入、状态与权限校验、测试和剩余边界见 [AI 首版契约](hcd-editor-ai.zh.md)。下文仍保留完整目标，不以首版替代自动补全、结构化工具或固定布局验收。

AI 核心独立于 React、Tiptap 和模型厂商，复用同一能力目录：续写、自动补全、改写、缩短/扩写、纠错、翻译、总结、结构化生成及自定义业务动作。长文按选区/块/页取有界上下文，受预算控制，不能每次发送整篇文档。

建议拆为：`ai-core`（请求、任务、流事件、取消、建议模型）→ `editor-ai-adapter`（选区/块身份与事务）→ `ai-ui`（灰字、选区指令、差异预览、接受拒绝）→ `ai-provider`（服务端模型适配）。首版请求携带 action、documentId、源版本、源摘要与有界纯文本上下文；CRDT 锚点只留在编辑适配器，权限通过宿主服务的可信会话检查。允许节点/工具与逐格式约束需随后续结构化生成扩展。流事件包含 requestId/顺序号和 delta/done/error；旧请求不能覆盖新请求。

AI 建议生命周期：

```text
idle → requesting → streaming → ready → applying → accepted
                    ↘ canceled / failed     ↘ stale（内容已改变，重新确认）
ready → dismissed
```

灰字与未接受建议是临时建议状态，不进入规范正文、不触发协作逐 token 正文写入，也不进入导出。接受时重新校验节点 schema、权限、当前相对位置与原范围内容摘要；目标已被别人修改时允许用户对照重试，不能用旧偏移覆盖他人文字。CRDT 相对位置解决定位，不能代替内容前置条件。接受操作作为一次可撤销事务，进入共享文档与当前联合保存链路。AI 的建议范围/模型内部标识不写进导出的正文。

先实现“明确触发的选区改写/续写”，再做可开关的停顿自动补全。补全仅作用于当前可写文字位置；快速输入、移动光标、切换文档、失焦、IME、只读、离线、菜单打开时取消或暂停。Tab 只在可见有效建议且无更高优先级菜单时接受；默认不拦截正常 Tab。支持整段/部分接受前，分别明确 undo 边界和每次内容前置条件。

协作中的 AI 建议第一阶段为发起人私有；接受后的实际内容才共享。执行人沿用已有用户历史；AI 辅助动作目前仅通过 onAccepted 回调给宿主，原生持久来源台账尚待实现。共享建议/审阅线程另建持久对象，带作者、目标、状态、版本、去重键及处理权限，避免两个用户重复接受。多人同时请求互不串流，服务端接收/应用重试需幂等；明确取消后迟到结果不得写入。

模型响应只能提出白名单结构化操作，不能直接运行脚本或任意修改 HCD 文件。服务端负责凭证、配额、权限和中止；发送上下文遵循宿主明确配置的服务及数据范围。尚无 AI 服务配置时入口给出不可用状态，手工编辑和本机备份继续工作。离线不承诺云端 AI 可用；未来本地模型可接入同一 Provider 接口。

Tiptap 的 [suggestions 文档](https://tiptap.dev/docs/ai/ai-toolkit/client/api-reference/suggestions) 可参考预览/审阅交互；是否采用其 AI 产品另行评估，本设计不依赖已购买授权，也不声称已经安装相关能力。

## 离线文件与转换能力

需区分三件事：`.hcd` 是规范文档打包，`.hcd-draft` 是 CRDT 恢复副本，`.docx/.pptx/.pdf/.xlsx` 是目标文件。草稿含资源哈希不等于已经包含图片字节；当前离线备份不能替代完整可离线打开的自包含文档。

当前导出分为同格式、带不可变源的受支持增量回写，以及无源/跨格式语义重建。CLI `semantic_export` 明确告知版式、分页、opaque 与交互元数据的转换限制；DOCX 源图片替换等不支持的回写会拒绝，不能把“语义导出成功”称为“原稿完全保真”。`export-options` 当前主要检查源可用性和 DOCX 是否需重建，尚非逐扩展能力矩阵。

下面是拟采用的映射策略，**不是所有单元格已经实现或测试通过**。每项需补实际文件测试后才能标为已支持。

每个扩展按目标格式声明 `native / semantic / flattened / unsupported` 与版本；导出服务对固定 revision 遍历实际使用的节点、mark、字体与资源，生成逐项报告（节点 id、转换方式、原因、丢失的交互/语义）。导出前展示有意义的降级；无可读 fallback 时阻止导出。不能对未实现适配的内容默默删除。只声明策略不等于保真，须回读生成文件并核对实际引用资源。

导入时保留可识别的业务元数据；无法跨目标格式可靠表达的业务关系不承诺回转还原。若目标只保存静态显示，重新导入后不应凭显示文字猜测原业务 id。完整 HCD 便携导出还需包含扩展描述/版本、资源和可离线 fallback；缺少扩展时能只读打开。AI 流缓存和访问令牌不进入文件。

## 实施顺序与验收

1. 完成当前保存/恢复正确性验证，继续处理固定/分段工作区、统一撤销和全文分段模型缺口。
2. 抽取统一命令注册表，以现有支持节点接通 `/`、块菜单、选区浮层、快捷键和命令面板；UI 翻译、IME、键盘访问随此阶段完成。先不开放任意 schema 注入。
3. 扩展内容协议和版本协商，选“提示块 + 行内业务提及”作为端到端样例，贯通协同、重开、搜索、资源、迁移和导出报告；之后开放宿主节点 SDK。
4. 通用 AI 服务 + 选区改写/续写的私有建议与接受事务；再接可关闭的自动补全。PPT/PDF 分别适配定位和容纳约束。
5. 扩展字体、各格式的完整转换矩阵及共享审阅能力；以上稳定后再做管理平台、插件分发和管理入口。

每阶段最低验收：

- 同一命令在 slash/工具栏/右键/快捷键得到同样结果；增加业务命令无需修改 App 的固定菜单数组。
- IME 不误提交；Esc 不丢文字；只读、受保护区域和不合法嵌套拒绝写入；菜单在缩放/滚动时定位正确。
- 自定义块与行内原子节点两窗口协同、撤销重做、本机恢复、规范保存、重新打开后内容和资源完整；缺失/旧版扩展不删除数据。
- 每个声明支持的目标生成实际文件，回读正文、节点、字体请求与图片引用；静态化/不支持项在报告中准确列出。PDF 另做渲染检查。
- AI 有取消、失败、离线、过期范围、权限变化和多人输入用例；未接受不进导出；接受只形成一次可撤销写入；重复请求/迟到流不能重复插入。
