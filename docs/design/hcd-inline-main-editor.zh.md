# 行内容器主编辑页接入与首次投影保护（2026-10-27）

本轮从独立宿主进入生产 `Workspace / EmbeddedHcdEditor`，接通已声明模型 3 文档的协商、编辑器、属性/文件、保存状态与恢复包组件。仍在主页面验收阶段，不能把下面不同层次的证据合并成全部流程已完成；整体七阶段目标保持开放。

## 接入范围

- 先读取 manifest 的 `capabilities.extensionNodes`。模型 3 不按 chunk 数量进入普通固定分段编辑器，也不提供退回该模型的按钮。真正的协议、epoch、权限由鉴权与 inline1 协商确认后才打开设备日志和连接；不能先创建旧协议房间。普通文档不会因注册了行内容器就自动迁移成模型 3。已有旧协议/epoch 的私有副本继续保留，不自动混入当前文档。
- 按有效会话建立 `inlinecontainers1:save4` 房间、显式 wire/inline acknowledgement、完整 schema、永久正文结构绑定及递归 snapshot。普通模型保持原有 schema 和协议。
- 资源注册器移到有效会话作用域，防止文件服务继续使用升级前的请求头。普通/区域/固定/表格入口保留各自的节点 provider；注册生命周期仍由组件拥有。
- 统一命令上下文、节点选择和定位支持两种 payload；属性、冲突组、文件任务与候选选择按真实模型分派。默认人员提及沿用服务端候选；模型 3 主页面不再因旧协议条件禁用已支持的默认入口。
- 保存基线及手动回执必须同时匹配 wire7 和当前 inline 模型，正文摘要使用相同的模型参数。保存状态检查读取实际编辑器绑定的 store，避免独立创建的 schema 与编辑器 schema 不同而误报失败。上传/设备日志门禁继续保留。
- 恢复包 core、传输与比较组件显式支持 inline1 scope，携带模型 3 文件目标和原字节；比较使用模型 3 store、未知 codec 历史保护和 `inlineRoomGuard`，不采用文件中的授权元数据。普通恢复包仍拒绝模型 3 文件目标。主页面连接该组件，实际浏览器导入/导出/确认流程仍待完成。
- 删除确认可显式接收行内容器 codec；所有嵌套未知节点继续保护。恢复沿用协调器端 inline restore。主页面行内容器的整节点选择按 occurrence ID 恢复，远端改属性、改正文、插入前缀均保留选择，真实删除才回退。

## 联调发现并处理的问题

第一份独立主页面测试文档完成了 `/` 插入、正文输入、属性及真实附件关联，另一成员与只读成员均能进入。但继续输入再保存时，原生 checkpoint 返回 **400 / `invalid HCD patch: duplicate canonical node ID`**。这个失败不是丢响应，不允许以“已保存”结束，也没有更改原始 r8 归档。

诊断发现开头出现了额外的空根，旧第一段来源身份成为跨段别名，下一次原生保存被拒绝。结构 binding 在首次投影前可能接收 Tiptap 的本机占位事务。现增加首次投影门禁：占位内容不能创建共享根；已经与规范投影精确相等的宿主可立即开始，其他宿主等待投影完成。原先只等待测试微任务的 headless 测试不足以发现此生命周期边界。

专项测试确认启动占位事务不会改变共享字节，投影后只保留规范段落。新建第二份原始 r8 测试副本后，实际浏览器初始三段保持，末尾添加段落及输入查询连续保存到 r10；原始首段来源 ID 未转移给额外空段。仍须在最终源码主页面重跑完整的“新容器输入 → 保存回执 → 多人续改 → 再保存”操作，不能仅依赖这段局部证据宣布主页面验收完成。

联调时内置浏览器服务中断，随后 Chrome 的输入控制也多次在派发前超时。保留同一标签观察，没有因观察超时重新创建服务或重复输入。读取 DOM、截图和原生文件仍可用。测试服务自身的 160 秒聚合时限也曾到期；确认该运行终止后，保留失败记录，将聚合上限增至 300 秒重跑，各具体同步等待的门禁没有放松。
