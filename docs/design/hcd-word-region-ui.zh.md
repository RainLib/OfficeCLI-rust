# Word 区域的浏览器分段编辑、属性与协作定位

2026-10-26，承接[区域结构核心](hcd-flow-regions.zh.md)和[无源 DOCX 导出](hcd-word-region-export.zh.md)。本增量接通已有 Word 区域模型的浏览器路径，管理平台和提醒发送仍后置。

## 本轮行为

普通语义文档沿用原有完整编辑器。带 `capabilities.flowLayout: 1/2` 的 DOCX 自动进入区域分段模式：正文、页眉、页脚在左侧有明确标签，正文及图片按分段加载，已有资源缓存和索引边界继续复用。客户端从服务端 manifest 识别模型并在请求中声明版本；未知版本或错误来源/配置拒绝打开，不把区域当成普通正文提交旧快照。

这一模式支持映射文字和图片编辑。正文、页眉、页脚的草稿共用保存控制器、版本前提、回执恢复、本机备份与个人历史。空区域的真实空文字载体也能选中并输入。计算域缓存、只读祖先和未加载 codec 的业务节点不提供文字修改入口；保留显示及原生归档数据。区域结构、`/` 菜单和完整富文本协作尚未在这个模式开放，不能把分段文字编辑记成完整 Word 区域产品已完成。

属性面板从所选保存版本读取节设置与 story 绑定，显示首页不同、奇偶页不同、起始页码、纸张尺寸及链接前节。共享页眉可以选择预览所属分节，画布宽度使用该节纸张宽度；这个选项只改变本地预览，不修改布局或版本。设置读取有取消、过期响应保护、超时及重试。未绑定 story 明确说明，模型 1 缺少正文区域身份时不猜测分节。短 story 顶部对齐，避免在画布中间留下无意义的大块空白。

在线成员、节点内容摘要、定位、跟随统一留在右侧在线协作面板。跟随会切换到成员所在正文、页眉或页脚分段；自己操作会退出跟随。画布内以独立覆盖层显示所选节点高亮与姓名，同一节点的多名成员并排显示名字。存在状态仍走只读 `fixed:` Awareness 房间，文本通过版本校验接口提交，并由持久版本通知刷新其他窗口；并未把区域文档接到旧的完整 Tiptap 快照房间。未保存文字不会作为远端正文广播，高亮是节点级操作位置，不是字符级光标。

导出操作区只提供目前支持的 DOCX 和 HCD 离线归档。DOCX 模式直接说明计算域结果转为静态文字、浮动图片转为行内，完整资源和历史使用 HCDZ；只读成员也可以下载。保留源文件回写仍由原有能力判断，不能因打开分段模式就承诺原格式回写。

## 元数据接口

`GET /v1/documents/{id}/word/layout?revision=N` 返回所选版本的 `revision`、`layout`、`layoutHash`，要求文档读取权限和对应 `X-HCD-Flow-Layout-Version`。响应使用 `private, no-store`。接口只读取有界的版本布局资产，不遍历或投影正文；原生测试删除正文分片后仍能读取设置，以验证这一边界。读取历史模型 1 时须声明版本 1，当前模型 2 则声明版本 2。

客户端身份由 manifest 识别；区域模型改变时暂停当前分段加载，保留草稿备份并要求重新打开，不把旧区域模型继续写回。此路径不新增分节、创建 story、解除/链接前节或开放旧签名快照。

## 实际验证链

本地真实浏览器使用独立临时 DOCX、140 段长正文、映射页眉图片、空页脚及 PAGE 缓存，由 Alice、Bob 和只读成员操作：

| 保存版本 | 浏览器动作及实际结果 |
| --- | --- |
| r2 | Alice 一次提交正文、页眉、页脚；三处来源在同一版本中变更 |
| r3 | Bob 修改另一节正文，Alice 可读到新版本 |
| r4 / r5 | Alice 撤销、重做自己的页脚，Bob 的正文修改保留 |
| r6 | 空页脚输入新文字并保存 |
| r7 | Bob 修改同一页眉；Alice 未保存候选保留，保存暂停并显示远端候选 |
| r8 | Alice 显式审阅远端内容后合并，保存新页眉 |

实际界面验证了共享页眉的第 1/2 节预览宽度、同节点两名成员的姓名、跟随切换到页眉、只读输入框和只读 DOCX 下载成功。PAGE 结果“7”仍显示，但不进入可编辑列表。实际 DOCX 按正文/页眉/页脚 part 检查内容；HCDZ 解包后 r1–r8 投影与原版本逐一一致，字段来源仍不可编辑。实际 HTTP 验证当前/历史布局读取、缺失/错误模型 426、只读写入 403、只读下载 200。

原先打开的另一份文档没有用于测试：集成更新使其旧测试凭证重新鉴权并发现过期，随后仅续期为同一身份的只读凭证；本机可见草稿文字前后相同，原权限策略和原生文档全部规范文件摘要不变。

截图和最终结果见 `docs/assets/hcd-word-region-ui-2026-10-26/`。这里是本地真实 CUA 浏览器、原生文件和鉴权 HTTP 证据，不是 Office 桌面、跨平台或生产验收。

```sh
cargo build -p officecli
python3 scripts/hcd-word-region-preview.py
# 使用上一步打印的独立 root；以下是本轮保留的实际夹具路径。
python3 scripts/hcd-word-region-ui-files.py target/hcd-preview-runtime/word-region-preview-k4udlctq
npm --prefix examples/hdoc/editor test
npm --prefix examples/hdoc/editor run build
cargo test -p officecli --bin officecli hdoc_server::tests
cargo clippy -p officecli --all-targets -- -D warnings
cargo fmt --all -- --check
```

预览脚本只创建自己的文档、短期身份与 loopback 服务；退出只清理自己的子进程。现有普通 HTML/Markdown/TXT 文档的区域建立与迁移、区域富文本 CRDT 保存/撤销、布局编辑、自动目录、页码更新和 PDF 区域导出仍需继续，管理平台和实际提醒不做。

最终检查：759 项前端测试、45 项服务端测试通过，新增分别为 5 项模型/请求契约用例和 1 项原生元数据边界用例；TypeScript、独立及嵌入构建、native debug 构建、clippy（拒绝警告）和 fmt 通过。实际长正文滚动使成员与跟随窗口同步到同一位置；在 frame 内手动向上滚动后跟随停止。修复同一节点多个成员姓名互相覆盖，并复核显示。源码与隔离浏览器所用版本逐文件一致，120 个文本文件/归档成员凭证扫描通过。详细命令、摘要、范围和保留的失败记录见[验证记录](../assets/hcd-word-region-ui-2026-10-26/validation.json)。
