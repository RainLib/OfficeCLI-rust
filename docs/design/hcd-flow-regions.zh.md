# Word 区域结构保存：分节正文、页眉页脚与扩展

2026-10-26，承接 [分节与原生保存基础](hcd-flow-layout.zh.md)。这一增量实现区域结构核心与显式 CLI 预览入口，**尚未接入浏览器区域编辑、签名协作房间或正文自动目录**。管理平台和实际提醒发送仍后置。

后续已补上[无源 DOCX 区域语义导出](hcd-word-region-export.zh.md)：当前和可投影的历史区域版本可以重建正文节与独立页眉页脚；下列导出拒绝记录描述本增量完成时的范围，最新兼容边界以导出专题为准。

## 可观察行为

| 路径 | 当前行为 |
| --- | --- |
| 普通 `hdoc import` / `project-editor` | 默认行为保持，未自动启用区域模型 |
| DOCX 导入加 `--word-regions` | 保存模型 1 的节、story、原始节 XML、域指令及来源身份 |
| `project-editor --word-regions` | 显式升级为模型 2：正文按节分区，页眉页脚按独立 story 分区 |
| `hcd-patch/6` + `hdoc apply` | 多个区域的富文本块插入、替换、删除、区域内移动及映射图片操作共用原子结构保存引擎 |
| 已有映射文字接口 | 仍可联合保存正文、页眉、页脚；模型 2 需声明版本 2，版本 1 客户端被拒绝 |
| HCDZ 当前/历史/还原 | 带区域元数据、资源和完整保存版本；跨模型还原后可再次显式升级 |
| 已编辑区域的 DOCX/PDF 等语义导出 | 尚未完成，明确拒绝；当前可用离线 HCD。未编辑原始历史版本可按自己的能力使用源 DOCX 导出 |

这里的“区域内移动”不允许把正文块直接移进页眉、跨节移动或让一个 story 的文字来源落入另一个 story。切换节关系、新建/删除 story、链接前节及跨区域复制粘贴仍需后续布局命令；本次不是完整页眉页脚产品交付。

## 保存契约

模型 2 使用 `capabilities.flowLayout: 2`、`hcd-flow-layout/2` 及版本资产 `word/_hcd/flow-layout-v2.json`。资产仍进入原有内容寻址图，保留模型 1 的节设置、首页/奇偶页关系、共享 story、原始节属性 XML。新增非最终节的 `canonicalEndBlockId`，边界跟随该节实际最后一个根块，不复制正文内容。

规范分片在 wrapper 上声明稳定的 `data-hcd-flow-region` 和 `data-hcd-source-part`；块投影返回 `flowRegionId`，文档投影返回 `flowLayoutHash`。空 story 不再靠相邻文字猜来源，完全空的 story 或最终节会建立自己的可编辑空段落。缺失或冲突的根身份在投影时物化为独立身份，不改原文字来源；属性实体、引号和 Unicode 保持语义。

`hcd-patch/6` 在原结构操作外增加区域分组和布局前提：

```json
{
  "schemaVersion": "hcd-patch/6",
  "documentId": "region-test",
  "patchId": "region-edit-unique-id",
  "baseRevision": 1,
  "layoutHash": "从 editor-state.flowLayoutHash 读取的 64 位摘要",
  "regions": [
    {"regionId": "从目标块 flowRegionId 读取", "operations": []}
  ]
}
```

上例仅展示字段，空操作不是有效请求。实际完整请求由验证脚本生成，保存在证据目录 `rich-patch.json`；不要把展示文字当成可提交的 ID/摘要。

前提、来源及目标校验在写入新 head 前完成；任一区域失败，整批失败。图片和扩展仍使用既有资产校验与联合提交路径。整个区域组共享一个 patch ID、actor、版本 CAS 和回执；回执摘要覆盖布局摘要、分组、操作顺序和 actor。精确重试返回原版本，即使后来已保存或还原，也不会再写一次或把 head 改回旧版本。投影意图按 base revision 命名并核对摘要，普通文字补丁不能仅靠相同名字伪装成投影成功。

## 来源、空内容及分节边界

- 新节点的来源使用实际区域的 part，而不是全部写成 `word/document.xml`。同批修改多个区域也不能借用其他区域的文字 ID 或锚点。
- 不同 story 和不同正文节不合并成一个分片。区域不允许重新进入、缺失、换角色、换来源或删除最后一个块；清空可替换为空段落。
- 移动/删除最后一个正文块时，同次提交更新节边界资产。布局摘要随边界更新，旧摘要不能继续写入；同一已提交请求仍可按原回执查询。
- 结构变更允许没有改字 ID：区域 wrapper 的升级通过 `structural_change`、实际分片和来源集合表达；新空段落则有真实的空文字载体，不伪造不存在的改字节点。
- 计算域、表格、未支持的 Office 对象仍遵守原只读边界；普通页眉页脚段落解除因“非正文”而附加的只读限制。域缓存不可改，未知指令不执行、不丢弃。
- 跨分节的复合根目前要求先拆开；不把同一个复合根猜着分给两节。正文段落标记区分主文档直属段落与嵌套文本框，避免把嵌套段落错当分节边界。

模型 2 的全局图校验逐分片进行：校验区域角色/来源、根身份、节顺序与结束边界；根 ID 去重沿用可落盘的跟踪器。验证不额外累积整份正文。离线包还验证每个历史模型 2 的区域图。

## 历史、还原与兼容

历史 manifest 的布局能力从该版本自己的不可变资产索引恢复，不再直接继承当前 head 的布局版本。还原同步采用目标版本的区域模型；模型 1 与模型 2 的历史可同时读取，原始 r0 仍可以按其源 DOCX 关系导出。

已有旧内测模型 1 可能没有空 story/正文段落身份；升级会明确拒绝缺失或歧义的身份，不猜归属。现有用户文档的迁移还未实现，也没有通过重新导入覆盖用户文档。**当前 HTML/Markdown/TXT 语义编辑器尚不因此获得页眉页脚功能**；通用区域建立与既有文档迁移仍需继续。

原 `/patch`、`/project`、旧签名快照继续拒绝区域文档。读取模型 2 及映射写接口要求 `X-HCD-Flow-Layout-Version: 2`，不是权限提升；只读 token 仍不能保存。查看模型 1 历史时按其版本声明。CLI 映射文字/样式写入同样校验必需模型，缺少声明、未来版本、未知保留资产路径或非 Word 来源不能绕过。

新增结构、字段和模型资产不会被旧规范化器写回为正文；旧模型不识别的保存路径先拒绝。当前尚未开放区域感知的 HTTP 结构入口，不能把 CLI 的 `hcd-patch/6` 支持当作签名协作已完成。

## 自定义元素和导出

区域结构操作复用既有行内元素、块、格式标记、引用、扩展信封和资源校验。页眉中的未知业务块、子段落、人员提及与附件能进入同一保存、版本和离线资源图；不会因非正文而变成普通正文来源。缺 codec 时的前端只读保护仍需随区域 UI 一起接通。

完整格式导出尚待区域感知实现：不能用某个节点声明支持 DOCX 来承诺整份含页眉页脚的文档可导出。新区域结构版本会同时拒绝语义导出及无法保留其结构的源 DOCX 导出，并提示使用 HCDZ，避免在两种均不可用的导出方式之间反复引导。当前正文自动目录、页码更新和真实分页也未完成。

## 复现和证据

```sh
cargo build -p officecli
hcd_regions_demo=$(mktemp -d)
target/debug/officecli hdoc import docs/assets/hcd-flow-layout-2026-10-26/source.docx \
  --word-regions --document-id region-test --output "$hcd_regions_demo/region-test.hcd"
target/debug/officecli hdoc project-editor "$hcd_regions_demo/region-test.hcd" \
  --word-regions --expected-revision 0
target/debug/officecli hdoc editor-state "$hcd_regions_demo/region-test.hcd" --json
python3 scripts/hcd-flow-regions-verify.py
```

新增测试仍在 Rust 源目录内。验证器仅操作自己的临时目录和 loopback 服务，凭证留在内存，不改用户当前预览。真实 CLI/HTTP 及文件证据位于 `docs/assets/hcd-flow-regions-2026-10-26/`；最终结果以 `validation.json`、`file-evidence.json` 和对应日志为准。没有将本轮原生证据算作浏览器、真实协作房间、Office 桌面、跨平台或生产验收。

本次新增 13 项用例，原生与现有 CLI 回归共 615 项通过，clippy/fmt/构建通过。文件验证包含 CLI 富文本联合保存 r2、真实鉴权 HTTP 映射文字 r3、页眉业务块/人员提及/图片资源 r4、跨模型还原与再次投影、r0–r4 无源历史和源原始版本导出。另用真实 DrawingML 页眉图片验证换图及几何与正文、页眉、页脚文字联合保存、图片失败整批回滚、r0–r2 离线图片状态及资源字节；旧模型 1 的完整 CLI/HTTP 验证另存于 `model1-regression/`。

HTTP 的直接源导出不支持时沿用现有 400 错误路径，语义区域导出门禁为 422；两者均不下载不完整文件，能力查询已标为不可用。此前验证脚本把前者预期成 422 的失败保留在 `file-first-attempt.log`，不计作通过。
