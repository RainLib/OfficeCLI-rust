# Word 页码域的外部应用兼容性实测

2026-10-30。本批在独立 LibreOffice 配置中打开、打印并重新保存实际 HCD 导出的 DOCX。它补充文件级兼容证据，不代替浏览器协同、编辑器分页、实际 Word/WPS 或生产验收。完整目标、管理平台和提醒后置约定保持。

## 结果：部分通过，SECTIONPAGES 仍未实现兼容重算

本机应用为 **LibreOffice 26.2.1.2**，完整构建号见[实测结果](../assets/hcd-word-field-app-2026-10-30/application.json)。使用之前真实保存的 r8 HCDZ，不改原包；解包副本中经正常原生区域补丁，在首页页眉加入 PAGE 与 SECTIONPAGES，再导出为 DOCX。应用打印为两页 PDF，并另存为 DOCX 后重新导入 HCD。

| 项目 | 实际观察 | 判断 |
| --- | --- | --- |
| PAGE + 罗马数字 | 两页分别为 I、IV | 更新通过；第二节本来显式设置从 4 开始，不能误期待 II |
| NUMPAGES + 罗马数字 | 正文显示 II，与实际两页一致 | 此样例更新通过 |
| SECTIONPAGES | 两页都仍是 `[SECTIONPAGES]` | **未计算，不通过**；不能将支持 DOCX 当成支持每一种域 |
| 外部应用重新保存 | 再导入后 PAGE、NUMPAGES、SECTIONPAGES 三类指令均存在，为受保护原生域 | 指令类型保留通过；不恢复原业务扩展身份 |
| 原文与归档 | 中文同伴文字存在，原 HCDZ 摘要不变 | 样例通过；PDF 提取在拉丁文与中文间插入额外空白，按空白规范化核对 |

应用重写页眉部件后，再导入识别为 7 个只读域；这不是原 4 个业务节点的身份往返。PDF 来自外部应用，不能拿它的页数声明浏览器编辑器已经有分页引擎。`updateFields` 与 dirty 标记是更新请求，不能迫使不支持相应域的阅读器计算结果。

作为定位线索，[LibreOffice 一个公开历史源码版本](https://cgit.freedesktop.org/libreoffice/core/tree/writerfilter/source/dmapper/DomainMapper_Impl.cxx?id=9cca15204af9cc44a8a9528ccf2f36616fb70e69)也有被注释的 SECTIONPAGES 映射；它不是本机版本支持范围的证明。本批结论以真实输出为准，不把官方问题页的访问拒绝当作已读到问题内容。

本机 WPS 另作尝试：确认云同步关闭，但自定义文件对话框未可靠定位测试副本，误打开最近文档后立即关闭，未进行编辑或保存；返回首页已经确认，测试副本摘要不变。没有测试副本在 WPS 中的渲染或保存证据，仍记为未验收，见[尝试记录](../assets/hcd-word-field-app-2026-10-30/wps-attempt.json)。

## 产品接线

页码节点的属性说明补充“本节页数需目标应用支持，部分兼容阅读器可能保留占位”。SECTIONPAGES 节点的浮层/辅助文字也包含这一边界；PAGE 等其他节点保持原有简短浮层。仍保留真实动态 DOCX 指令，没有把本节页数替换为伪造数字，也没有为了让某个阅读器测试通过而降低原生节点类型。

说明采用现有五个 locale 和既有标签长度边界。初次合并两段英文超过注册表允许的说明长度，三项测试拒绝注册；改为有界的简短说明后，最终 **34 项相关检查通过，0 失败**。没有放宽注册校验。首次构建期间文案又有修改，构建后检查发现独立页仍带早期说明、嵌入版已是新说明；因此重新运行最终构建，并分别核对两个产物都包含最终文案，准确结果见[验证汇总](../assets/hcd-word-field-app-2026-10-30/validation.json)。

## 视觉与证据限制

- [第二页](../assets/hcd-word-field-app-2026-10-30/visible-page-2.png)可直接看到 IV 与未计算的 SECTIONPAGES 占位。不同节的纸张和起始页码是原文设置，不能用统一视觉尺寸覆盖它们。
- 初始预期、首轮未通过的应用输出、英文说明注册失败和后续观察均保留在同一证据目录。验证器在部分不通过时仍以 **退出码 2** 结束，并写出逐项结果，不能把执行完毕说成兼容性全部通过。
- 本批没有重新运行完整前端或 Rust 工作区，也没有普通浏览器、Word/WPS 实测、离线应用冷启动、真实设备存储故障或生产证据。
