# 普通语义编辑器的节点文件恢复

2026-10-27。将[区域节点文件恢复](hcd-word-node-resource-recovery.zh.md)的状态机推广到普通 Word/HTML/Markdown/TXT 共用的结构编辑组件。此次真实浏览器验收使用普通 DOCX；其他输入格式使用同一组件，本轮没有逐一执行其浏览器文件恢复验收。管理平台及提醒发送继续暂缓。

## 改动与契约

- `nodeResourceStorage.ts` 抽出有界设备元数据操作。区域编辑器沿用原设备库、原元数据键和已保存文件选择；普通编辑器用独立 `nodeResourceJournal.ts` 存储。两种入口共用原 `WordNodeResourceClient` 状态机，没有新建另一套上传/取消协议。
- 普通正文草稿可能在重开后分叉为新的本机副本，因此文件日志按 API/协同端点、文档、成员和 epoch 固定寻址，不包含正文副本后缀。正文副本切换、归档和压缩不删除文件选择；本机正文副本列表也不把文件数据库当作正文副本。
- 文件先持久保存原始字节、摘要和原节点载荷，再调用原生归档。8 MiB/文件、16 个待处理、64 MiB 总字节限制由同一读写事务检查，两个窗口不能各自绕过容量限制。终态取消防止另一个窗口的慢响应恢复旧选择。
- `useSemanticNodeResources.ts` 在 effect 中拥有数据库、广播通道和客户端，卸载时中止请求并关闭数据库。渲染本身不打开连接，StrictMode 的清理不自动丢弃选择。
- 右侧属性区复用恢复面板，显示原目标和当前目标；定位后可确认关联、继续上传或取消。首次选择可通过普通 `node.resources` 命令直接关联，节点/选区在等待中变化则拒绝旧输入。重开不自动上传、不自动关联、不使用缓存授权写入。
- 关联完成要等当前正文更新落入本机正文日志后，才退休文件选择。正文写入失败，即使编辑命令已经产生文档更新，选择仍保留，重试时可核对已有引用而不重复创建历史动作。
- 归档请求、选择日志加载、未完成文件与读取失败共同进入保存门禁。正常保存、迟到保存回执、关闭、窗口化、旧房间交接、版本还原和导出复用同一个即时检查；不能只检查网络请求数。
- 任务取消或关联完成后重新核对协调器基线，避免文件任务已清空但界面永久停在“编辑中”。标题使用简短的“待处理节点文件”；状态栏入口通过统一 `view.properties` 命令打开面板。
- 当前设备草稿下载包含正文 CRDT 和未完成文件的原始字节。正式导出仍需完成或取消文件选择；业务载荷、已关联资源和历史通过 HCD 归档保留。

本机正文存储不可用并由用户明确选择继续时，不创建新的文件选择；既有文件数据库不删除。文件日志读取失败会显示重试入口，不能据此宣称已处理全部任务。文件日志只供恢复核对，不是服务端权限、作者身份或文档内容来源。

## 真实浏览器与文件链路

隔离 fixture：`target/hcd-preview-runtime/hcd-mention-preview-lmmnv_uy`。前端复制到该目录，生产 sidecar/原生服务使用合成成员；没有编辑用户文档。预览为 `http://127.0.0.1:63946/.hcd-semantic-resource-recovery-writer.html`。

| 步骤 | 观察到的结果 |
|---|---|
| r2 | Alice 插入行内资源标记并保存 |
| r2 后 | PNG 上传被合成代理明确返回 503；文件任务保留、保存禁用 |
| 新窗口 | 正文以新的设备副本打开，仍找到同一文件任务；代理上传计数未增加，没有自动关联 |
| 设备备份 | 浏览器下载的 `.hcd-draft` 同时包含 CRDT 与 PNG 原始字节，摘要与选中文件一致，不包含 token 字段 |
| r3 | Bob 修改资料标题为“同伴更新资料”，独立保存，不被 Alice 的私人文件任务阻止 |
| r4 | Alice 看到原/当前目标并确认，使用已存字节恢复上传和关联，保留 Bob 新标题 |
| r5 | Alice 的个人撤销仅移除自己关联的资源 |
| r6 | 重做恢复资源，稳定节点 ID、同伴标题和源内容保持 |
| r6 后 | 新的慢请求期间取消、释放旧请求后仍为 r6，没有新增绑定；任务清空，界面恢复“已保存” |

919 项前端测试通过；新增 5 项重点覆盖独立作用域、正文副本切换、跨窗口原子容量、关闭/终态防复活，以及正文落盘失败时保留资源。设备/资源 20 项专项通过；最终 TypeScript、standalone/embed 构建通过。

浏览器下载的 DOCX 与原生无源导出逐部件一致，仅排除新生成的 `w:paraId`。HCDZ 解包后 r0–r6 状态逐版一致，资源字节、原生及离线校验通过。

| 格式 | 本次实际校验 |
|---|---|
| DOCX | 可读节点恰好一次；DrawingML 关系实际引用归档 PNG 字节 |
| PPTX、XLSX | 可读节点恰好一次，包中包含归档 PNG 字节 |
| PDF | 可读节点恰好一次，源图片与节点图片均存在 |
| HTML | 浏览器鉴权导出接口返回可读节点一次，内嵌 PNG 摘要与归档资源一致 |
| Markdown、TXT | 保留可读标签及图片说明/名称，不承诺在纯文本中保留完整业务或图片数据 |
| HCDZ | 稳定业务载荷、资源及所有保存版本完整保留 |

实际另查到：CLI `hdoc export --to html` 的无源导出仍明确拒绝，浏览器 HTML 则走已有的 `render_standalone_html_with_transform` 分支。二者证据分别记录，不将浏览器接口成功推断为 CLI 已支持。此项在后续已补齐：CLI 与浏览器共用无源 HTML 导出，见[实现与独立文件验收](hcd-standalone-html-export.zh.md)。普通资源恢复这一轮本身未修改 Rust 导出路径。

## 2026-10-29：独立浏览器存储的恢复包验证

补充普通 DOCX 主页面的跨来源恢复验证：同一合成服务和成员，源页面位于 `127.0.0.1`，目标页面位于 `localhost`，两者使用独立浏览器存储。源页面插入业务节点并保存 r2，代理使附件上传返回 503；待处理文件保留且保存被阻止。用户下载包含该文件的恢复包，在目标页面选择并比较、明确合并到草稿，再逐项核对、重新归档和关联，保存 r3。

实际浏览器下载的 r3 HCDZ 经解包及节点状态回读，文件名、节点资源引用和原始文件 SHA-256 均一致；目标页面重开后仍显示该附件，实际下载字节也与原文件相同。见[保存界面](../assets/hcd-cross-origin-node-recovery-2026-10-29/saved.png)及[文件回读](../assets/hcd-cross-origin-node-recovery-2026-10-29/readback.json)。两个来源的旧设备任务互不自动清理，文件迁移需要用户确认；本测试是同一设备和同一服务的受控 503，不代表不同物理设备、旧 epoch、权限变化或生产服务的完整验收，也不表示普通 DOCX 会保留业务附件身份。

## 2026-10-29：恢复前只读核验的等待与响应限制

普通语义恢复的权限核对、当前文档信息、规范快照检查及 HCDZ 读取现在对响应头和正文设置总时限；权限和清单为 45 秒，规范快照及 HCDZ 为 120 秒。JSON 响应限制为 64 KiB，HCDZ 沿用 48 MiB；调用方取消会停止等待，迟到响应关闭。服务端响应过大、检查超时与恢复文件本身超限使用不同提示；取消等待不证明服务端已停止只读检查。已有附件暂存、正文提交与不确定结果的处理规则不变。

73 项恢复、附件批次和有界读取测试通过，覆盖卡住响应头或正文、迟到响应、取消及超限；TypeScript 检查通过。隔离普通 Word 浏览器中，对规范快照检查定向注入 65,537 字节响应，页面显示服务端响应超限、保留恢复文件；恢复正常后点击重新比较可显示 r1 比较，服务端版本仍为 r1，见[记录](../assets/hcd-recovery-check-bounds-2026-10-29/browser.json)。浏览器样本不含附件或图片，实际超时由缩短时限的受控测试覆盖，真实慢网、超大文档性能与跨设备仍需验收。
