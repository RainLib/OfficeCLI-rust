# Word 写作浮层、斜杠菜单与拖动反馈

2026-10-25。本轮处理用户追加的 Notion 式 AI、`/` 交互及拖动目标不可见问题；完整 HCD 交付范围仍继续，管理平台与提醒发送后置。

## 拖动

原实现依赖原生 HTML 拖放，浏览器操作中没有稳定触发移动；嵌套命中还会先选到覆盖子行的外层容器。现在块手柄使用指针捕获，移动超过 6px 后启动，目标只取同一父级的兄弟块。

| 位置 | 反馈与行为 |
|---|---|
| 可用行的上半区／下半区 | 整行蓝色背景、边框、前／后插入线和目标名称；松手使用此刻同一位置计算提交 |
| 源块内部或紧邻且顺序不变的位置 | 虚线及“此位置无需移动”；不提交、不清空重做 |
| 同级范围内的受保护边界 | 不可用反馈；不允许跨越保护内容 |
| 其他父级、视口之外 | 清除目标，松手不移动 |
| 靠近滚动视口边缘 | 按动画帧滚动并重新计算目标；离开边缘停止 |
| Esc、指针取消、失焦、权限／注册表／文档变化 | 中止拖动，旧目标不再提交 |

命令仍走统一 `block.move`、准备后校验与结构协同。多块选区、已知富文本容器子块沿用原命令限制；未知 codec 的祖先不会暴露可操作子手柄。手柄保留点击菜单与已有键盘移动入口。边缘反馈使用实际屏幕矩形，适应缩放和滚动；反馈状态不写进文档。React 复用块索引，移动过程中只读取命中附近的矩形。

## AI 与 `/`

参考 [Notion 文档 AI](https://www.notion.com/help/guides/notion-ai-for-docs)、[写作与编辑](https://www.notion.com/help/writing-and-editing-basics)及[键盘交互](https://www.notion.com/help/keyboard-shortcuts)：实现文档内写作入口、私有建议、接受／重试／丢弃，以及可搜索的块命令。本轮没有实现工作区搜索 Agent 或所有 Notion 组件。

- AI 助手在选区／光标附近打开，包含需求输入、按当前选区启用的操作、原文、流式建议、停止、接受、重试和丢弃。Enter 生成、Shift+Enter 换行、Esc 关闭；组合输入不提前提交。自动获得输入焦点，避让视口，随映射后的书签移动。
- `/AI` 是单独的写入命令：仅在最终确认成功时消耗触发文字，再打开空白 AI 浮层。取消菜单不删触发文字；异步命令失效也不消耗文字。块侧边的普通插入菜单不会误列此入口。
- 真正空白、允许编辑且有 AI provider 的普通行，单独空格可打开 AI。正文空格、代码、组合输入及修饰键不被接管。
- `/` 复用统一注册表，提供分组、图标、描述、别名搜索、上下键和 Enter。键盘跳过不可用项，全部不可用时不引用不存在的活动选项。自定义命令仍可提供本地化描述。
- 私有输出沿用已有 AI controller；接受前不进入 Yjs、保存或导出。接受仍是一条可撤销的普通内容事务。选区内部并发变化会禁用旧建议；选区外输入不因此被覆盖。编辑器／provider 更换时清理浮层。
- 未增加 AI 节点或离线格式。接受后的内容是普通文本／换行；宿主可继续注册自定义 AI action 和 provider。灰字补全仍由既有独立开关控制。
