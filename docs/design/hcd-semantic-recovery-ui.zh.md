# 结构编辑页恢复包导入与比较（2026-10-27）

承接[恢复包内核](hcd-semantic-recovery-archive.zh.md)，将普通 `structure3` 活动编辑器接到真实文件入口。保存和导出仍在操作区；管理平台与提醒投递未实施。

## 使用流程

1. 在“导出”操作区选择“离线恢复包”，导出当前捕获时刻的规范文档、协作状态、节点资源与私有未完成文件。之后的新输入需要重新导出。
2. 选择 `.hcd-recovery`，先读取为隔离候选，核对文档/epoch、完整性、资源和当前可访问的规范历史。显示当前草稿与因果合并后的内容、节点资料和附件数量。
3. 比较后当前 Y.Doc 发生变化，立即清除旧比较，要求重新比较。确认前再次检查权限、同步状态与当前状态摘要；异步资源归档之后也检查，不能用旧预览覆盖新输入。
4. 确认后以一个个人历史动作进入当前草稿和正常协同/保存。不自动恢复文件里的 ACL、服务回执、旧保存状态或当前规范绑定。个人撤销保留永久分配；导入后他人已修改的新块受既有保护，不能用撤销删除同伴输入。
5. 未完成节点文件作为本机私有选择保留字节，重新定位和核对后才可上传/关联。任务处理前阻止保存；取消是终态，同一恢复包重试不能复活已取消任务。批量写入日志原子化，容量不足不会部分写入。

只读成员可以比较，不能确认合并。文件摘要不是授权。内容预览有长度上限，超过上限明确提示；没有修改或截断实际恢复状态。

## 原生检查接口

`POST /v1/documents/{id}/recovery/canonical/inspect?revision=…&rootHash=…&epoch=…` 接收规范 HCDZ 字节，以当前成员读权限核对当前 epoch 和原文档历史。使用原生有界解包、内容寻址和归档完整性验证，归档的文档/版本/根摘要必须一致；完成后重新授权并核对 epoch。

该接口不采用草稿、不变更规范 head、ACL 或协作状态。48 MiB 路由上限覆盖通用 8 MiB 限制；解包共享导出并发许可，断开请求后许可仍由后台验证工作持有。未改变普通 HCDZ 格式。恢复包内核的其他上限继续有效。

## 实际验证

证据在 `docs/assets/hcd-semantic-recovery-ui-2026-10-27/`，使用独立合成文档和原成员权限，没有修改用户文档。

- 实际浏览器导出 r1 恢复文件，独立离线 Y.Doc 加入段落、行内节点、附件以及另一份未完成文件，再从文件选择器导入。不是直接注入活动房间来代替导入验证。
- 当前窗口已有新增输入；比较后继续输入使旧比较失效，重新比较后两类输入均保留。确认合并在 Bob 窗口可见。Bob 的实际输入前缀 `Bob同` 在 Alice 撤销整个导入后仍在，重做恢复段落与节点。自动保存期间一次自动输入观察超时，按最终正文核对，没有把未输入的后缀计入结果。
- 原生保存为 r4。私有待确认附件导入后阻止保存，重新导出的恢复文件保留 41 字节原文；取消再导入同一文件不复活。只读窗口可以比较，确认按钮禁用。
- DOCX/PDF/PPTX/XLSX/HTML/MD/TXT 七种实际导出保留当前输入和一次节点语义文本。在线成员姓名没有混入文档。HCDZ 离线解包后，结构投影相同、32 字节已提交附件逐字节一致；从解包目录独立原生导出 DOCX 再回读通过。未完成附件未进入规范内容、资源索引或导出。
- 原生 HTTP：读成员验证 200，无凭证 401，错误 epoch 409；9 MiB 非 ZIP 返回 400 而非通用 413，确认路由上限实际生效。验证前后规范 head 不变。
- 前端完整 **987 项通过**；TypeScript、standalone/embed 构建通过。新增原生 **3 项测试通过**，`cargo clippy -p officecli --all-targets -- -D warnings`、`cargo fmt -- --check` 和差异空白检查通过。

## 仍待实现

当前 UI 仅支持相同文档、相同 epoch、公开 `structure3` 协议；内部 `inline-containers3` 包内核已验，但公共 SDK/房间协商/迁移未开放，不能经此入口隐式升级。固定布局、区域 Word、旧 epoch/不同文档的协调迁移，以及图片上传中的全部设备任务尚未统一；仍有图片任务时明确拒绝此包，保留现有设备草稿。

归档打开和导出需要当前授权及原文档历史核验；本轮没有提供浏览器全离线编辑应用或跨设备自动授权。没有生产部署、多主机、真实远端模型服务或桌面 Office 视觉验收。长文分页/虚拟化、旧房间迁移和原七阶段其余未完成要求继续保留。
