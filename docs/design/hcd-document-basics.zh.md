# Word 基础能力：页眉页脚、大纲与正文目录

2026-10-26 用户追加需求。该范围加入当前编辑器目标，不包含管理平台。提醒协议仍仅预留。

## 已修正及现状

- 末尾“添加段落”曾跟在最小高度 450px 的编辑器之后，短文也把按钮推到纸张中间。语义编辑区现在随真实内容伸展，纸张自身仍保持页面高度。新增入口紧跟实际正文末尾，只在纸张悬停、键盘聚焦时显示，触屏保留可发现入口；原统一命令、只读限制和撤销行为不变。
- 已有标题会实时生成左侧导航大纲，点击标题定位原文。本次复核修正紧凑样式覆盖缩进的问题，补齐标题2–6级缩进；这不是已经实现了正文中的自动目录节点。
- 原生 DOCX 导入遍历 `word/header*.xml`、`word/footer*.xml` 并保留区域及原稿内容；当前结构编辑投影将非 body 区域设为只读，结构插入也限制在正文。因此页眉页脚编辑/新建尚未完成，不能用界面上的装饰文本代替。

当前代码依据：`hcd-docx/src/importer.rs::ordered_text_parts`；`hcd-core/src/structure.rs` 的 `descriptor.region != "body"` 只读规则及正文插入门禁；`App.tsx` 从 heading 节点更新导航大纲。

## 接下来优先实现

| 能力 | 编辑和保存要求 | 验收 |
| --- | --- | --- |
| 页眉、页脚 | 作为独立文档区域管理稳定身份、段落、格式和资源；在页边区域进入编辑，不混进正文末尾 | 创建/编辑/删除，协同光标与个人撤销，断线草稿和重开精确 |
| 页面与分节 | 页面尺寸、方向、页边距、页眉/页脚距边；逐节管理，明确默认/首页/奇偶页与链接前节 | 分页显示与 DOCX 节关系一致，不因编辑正文丢失原稿设置 |
| 页码域 | 保存页码/总页数的字段语义，不能保存为某一次渲染得到的普通数字 | DOCX 字段、实际分页 PDF 中的位置和数量正确 |
| 导航大纲 | 标题1–6级，实时生成与分级缩进、定位；补当前项与搜索 | 修改/移动/协作后更新，长文分段时不丢标题 |
| 正文自动目录 | 独立目录节点与稳定标题引用，选择收录级别、插入和更新；单次操作可撤销 | 保存/协同/离线恢复；导出保留可读目录和导航关系 |

连续编辑视图没有可靠分页时，不虚构目录页码。分页模式与导出计算完成后再显示真实页码。正文自动目录和左侧导航大纲应共用标题索引，但分别保存用户设置和展示状态。

页眉/页脚必须进入同一次联合保存及带版本的协作模型；不能把独立固定区域补丁与正文 checkpoint 分开提交后显示“全部已保存”。跨区域的人员提及、资源、未知扩展、权限失效和历史还原也使用既有保护和恢复流程。先对齐 Word/语义文档的区域模型，再明确 PDF/PPTX 的页级对象和导出语义。

## 本次验证边界

使用新的隔离预览核对短文末尾入口、添加后撤销、保存仍为 r1，以及两级标题导航。未修改用户正在使用的 `.hcd-text-edits-check-writer.html` 文档内容或主动刷新该页；其源样式通过 CSS 热更新生效。截图和页面几何见 `docs/assets/hcd-document-basics-2026-10-26/`。

页眉页脚、页码域和正文自动目录在上述表中均是继续项，不因完成按钮位置或已有导航验证而标记完成。

## 原生保存基础增量

分节与独立页眉页脚 story 已进入版本化模型。默认关闭区域模式；DOCX 可通过 `import --word-regions` 和 `project-editor --word-regions` 显式预览区域结构保存，正文、已有页眉页脚的富文本/映射图片可联合提交。HCDZ 保留布局、资源和历史，计算域缓存只读。原始模型仍可按能力使用源 DOCX；区域结构改写后的完整导出尚未完成，当前使用 HCDZ。浏览器编辑、签名区域协作、既有 HTML 等文档的迁移、页码更新和正文自动目录仍需继续。详见[模型 1 基础](hcd-flow-layout.zh.md)与[模型 2、真实文件证据和开放边界](hcd-flow-regions.zh.md)。
