# 区域 Word 工作区命令一致性

2026-10-27。属于原计划阶段 3 的增量，使用既有命令 ID 和嵌入 SDK，不改正文模型、保存协议或授权范围。管理平台和实际提醒仍不做。

## 已确认的问题

区域入口的 `view.zoom.set` 原先读取 `{value}`，而嵌入 SDK、其他工作区与文档约定使用 `{percent}`。底部滑块还直接调用 React setter，绕开了统一命令路径。面板命令忽略 `{enabled}`，导致宿主明确要求打开时，重复调用反而关闭；属性面板的 active 状态也漏掉自定义节点属性这一类。

本增量将区域 Word 的视图动作与状态集中在 `wordWorkspaceCommands.ts`，复用 `toggleInput`、`panelTarget` 和 `zoomInput`。缩放仍是纸张共同适配基准的倍率，允许 25–200 的整数，与固定画布采用同一数值校验；这不表示 Word 精确物理尺寸、分页或 DPI 已实现。底部滑块的范围与命令一致，并提交 `{percent}`。在线协作者入口、侧栏关闭按钮也进入同一命令。

显式打开应幂等，显式关闭只影响目标类别；属性类别包括普通图片和自定义节点属性，专门关闭图片面板不会关闭正在显示的节点属性。未知命令继续交给原来的文档/节点适配器，不扩大写入权限。只读、受保护选区和历史模式可使用已注册的本地视图动作，正文命令仍走注册器的写权限门禁。

## 批次更新保护

第一次提取实现返回了整个视图快照。模型复核发现，在 React 尚未重新渲染时连续调用“打开协作、隐藏属性”，第二个旧快照会清掉第一步的协作面板，并可能覆盖缩放或大纲更新。`batched-before.json` 保留该反例；它是批次模型证据，不是实际浏览器点击。

最终改为接收 React 的局部 setter：大纲和面板使用函数式更新，只读取提交时的对应当前值；缩放只提交已验证的数字。命令调用阶段先校验输入，异常不会延迟到 React 渲染时才抛出。各动作不再携带或覆盖其余字段。新增回归延迟执行整个 setter 队列，组合打开协作、隐藏属性、设置缩放和两次明确打开大纲，验证协作仍显示且其他字段都保留；两次普通切换在同一批次后回到原状态。

5 项新增与既有命令专项共 35 项通过，记录在 `docs/assets/hcd-word-workspace-2026-10-27/command-tests.log`。初版有一项测试把需要 loaded 状态的图片入口放在 loading 夹具中，修正夹具后纳入专项通过；没有降低注册器的 ready 或写权限要求。第一轮 1104 项全量通过、TypeScript 通过，但应用构建为修复已复现的批次问题而主动终止（退出码 143），日志保留为 `frontend-tests-firstpass.log`、`frontend-build-interrupted.log`，不作为最终构建结果。

第二轮 1105 项中有 1 项既有还原测试失败：私有日志读取未能在固定 20 ms 之内到达 freeze，断言时事件为空，之后事件才到达。测试现改为等待明确的 freeze/quiesce 信号，保留 10 秒失败上限，并额外确认在途包排空前没有提交；并发请求用例也改为明确的 quiesce 信号。生产还原实现未修改，没有扩大等待成功条件或放宽 fencing。失败日志保留为 `frontend-tests-timing-failure.log`；还原/本增量专项 19 项通过，最终前端全量 **1105 项通过**。

最终 TypeScript 检查发现新增测试中的断言使控制流错误地把后续状态收窄为 `never`；改为对状态快照断言后，5 项命令专项再次通过，`npm run build` 完整退出 0，应用和嵌入包均构建成功。失败记录保留为 `frontend-build-type-failure.log`，成功记录为 `command-final-tests.log` 和 `frontend-build.log`。全量测试是在这一仅改变测试断言写法的修正之前执行的；产品运行时代码在全量测试后没有更改。
