# 历史查看、差异和版本还原

2026-10-23，默认 Word 结构化协同页已接通主文档历史查看、有界增删差异、应用内确认还原和本机服务的可恢复还原事务。以下验收是隔离本机原生 API、真实 WebSocket 双端、浏览器和导出文件回读；不代表远程存储、多实例及 PPT/PDF 编辑器版本面板已经通过。

## 交互

1. 点击历史列表的“查看版本”，在主文档区显示对应版本的只读正文，顶部固定显示版本、作者、时间和“返回当前编辑”。保留仍在接收协同更新的实时编辑器和本机草稿，不把历史内容写进 Yjs，也不将历史查看广播成当前编辑光标。
2. 查看方式为“版本正文”和“与当前已保存版本对比”。对比两端版本固定，远端保存后提示当前有更新，可重新比较；不能悄悄更换比较基线。另明确提示本机未保存内容不在这次版本比较中。
3. 对比以文档阅读为主：新增为绿色、删除为红色划线，修改可展开前后内容，支持前后变更跳转和数量摘要；并排为可选布局，窄屏使用上下排列。不能仅靠颜色表达变化。
4. 文字、段落类型/层级、字体/字号/样式、列表与对象/图片分别说明变化。图片和保护内容保留对应版本实际预览，无法细分时显示“区域内容变化”，不把纯文本相等当作图片未改。移动块与删除后重新插入尽量区分。
5. “还原为此版本”打开应用内确认对话框，不使用原生 confirm。显示目标/当前版本、作者/时间、变化摘要、其他可写会话及草稿保护状态。说明“将生成新的当前版本，原历史仍可查看”；主按钮使用“保存当前内容并还原到 rN”，次按钮“取消”，可直接返回差异。加载/保存/确认中有明确状态，禁止重复提交。
6. 上传中先完成或取消上传；不允许确认窗口绕过图片上传保护。确认前保存当前内容，落盘本机备份并归档共享草稿。保存失败时保留窗口和草稿；“未确认”和“结果未知”要分开，结果未知禁止新建一次还原，先核对原请求结果。
7. 还原只生成新的 head，目标及中间历史不删除。确认期间规范版本、协同正文或权限变化则要求重新核对。成功后显示新版本并回到实时编辑；同伴进入新协同 epoch。恢复旧内容不会恢复旧权限，也不发送提醒。

## 当前实现与验证

- `showRevision` 同时固定旧版本和当前已保存版本，取消上一读取，校验返回版本；历史内容在主文档区只读展示，实时编辑器仍挂载并接收协同更新。返回时恢复实时滚动位置，历史大纲不指向实时选区。
- manifest、styles、index、chunk 和 assets 都按 `?revision=N` 读取；历史 HTML/图片使用隔离 frame，分段按可见区域加载。历史导出固定选择的版本，并跳过实时保存。
- `revisionDiff.ts` 先按稳定块/语义锚点匹配，再识别移动；区域内按 Unicode 有界比较。支持新增、删除、文字、格式、对象标记，展开前后正文以及前后变更跳转。两端固定后，同伴保存只显示刷新提示。复杂对象的逐属性可视比较、可选并排及超长差异 DOM 窗口化仍需补充。
- 确认窗口显示目标/当前版本、作者及变更数，默认焦点在取消；上传、权限或比较基线变化阻止新提交。先保存当前内容和本机草稿，再向 sidecar 发出稳定请求。未知结果保留原请求，提供核对结果，不能取消锁定后另建一次提交。
- sidecar 向所有可写语义会话发起交接，客户端同步锁定编辑/上传、落盘本机草稿、等待已发出的同步包并确认。未就绪/旧客户端/固定布局可写窗口会阻止本次操作；新连接也在冻结前重新检查。消息屏障排空已接纳包，coordinator 停止自动保存、归档共享状态，正文/图片仍 pending 或 head 不符则恢复会话并要求重新比较。
- `RestoreJournal` 在提交前持久化精确请求（身份、目标、基线、epoch、共享状态 hash）。提交或回执未知时保留冻结；协商入口可在重启后继续同一请求。
- 原生 `/collaboration/restore/N` 仅信任协调服务，重新检查作者权限、head、epoch 和状态 hash。durable pending intent 在规范 head 与 epoch 轮换间阻止其他 HTTP 写入；按恢复后的不可变记录核对重放，只追加一次版本、轮换一次 epoch。成功回执单独留存。结构化房间拒绝旧的直接 `/restore/N` 绕过交接。
- 成功后同伴切换新 epoch；若旧连接先关闭、未收到最终通知，已交接窗口依据 HTTP 权威代数切换。还原不恢复旧权限，不发送提醒。
- StarterKit 自动补在保护对象之后的空段落会造成视图与保存摘要不一致，已关闭。末尾“添加段落”通过统一命令显式创建可保存节点。没有输入的还原文档显示已保存，再次保存不额外追加版本。
- 右侧“在线协作”集中显示人名、正在操作的内容、浏览位置与定位/跟随；当前段落显示同伴姓名和活动高亮。自己滚动或输入停止跟随。这些状态不进入规范历史或导出正文。

验证：364 项前端/服务单测，121 项原生单测，原生 clippy 和格式检查；standalone/embed 构建。`python3 scripts/hcd-revision-restore.py` 覆盖双端交接、未完成操作拒绝、确认后同伴新输入、丢失成功回执、服务重启原请求重放及 7 份真实 DOCX/PDF 回读。证据在 `docs/assets/hcd-workbench-2026-10-23/revision-restore-api-evidence.json`。

浏览器默认 App：取消保持 r2；还原 r0 生成 r3；再次还原 r2 生成 r4，两端均显示已保存且可编辑；Bob 继续输入保存 r5；实际下载 DOCX 回读原图片及新旧正文，姓名浮标不混入文件。确认窗口、差异及协作跟随截图见同目录；`revision-restore-browser-evidence.json` 保留边界。PPT/PDF 对应面板、真实中文输入法、远程存储/多 sidecar、旧 epoch 私有离线合并仍未验收。远程模式不公布 coordinatedRestore 能力，管理平台及提醒投递仍不做。

## 实施约束

先接主文档不可变版本展示和只读命令状态，再完成有界差异算法与可访问变更导航，最后接还原服务事务与确认窗口。差异不对整篇长文建立字符级全矩阵：按稳定块及语义锚点匹配，块内有界计算字符变化；源 ID 等内部回执不算内容变化，未知节点不静默忽略。

还原走 sidecar 的文档消息屏障，先排空当前已接纳写入并保留共享正文，再提交原生 CAS；旧 epoch 拒绝继续写入。若仍有无法确认完成上传/本机操作的可写窗口，应清楚提示等待交接。任务需要稳定 request ID 和可恢复结果；原生规范提交与协同轮换不是一个原子操作，需单独处理两者之间崩溃，不能把一次 5xx 当作“未还原”。

验收包含：初始导入 r0、格式/图片/嵌套正文、历史删除内容、两端明确版本、比较时远端新保存、取消还原、上传阻止、权限失效、并发 head/body 变化、提交后丢回执、重启/重试不多增版本、同伴切代，以及还原后真实 DOCX/PDF 文件回读。管理平台及提醒发送仍不在范围。
