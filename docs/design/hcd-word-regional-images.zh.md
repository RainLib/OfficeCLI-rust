## 行为与不变量

- 正文、各节页眉页脚、图片几何和已上传替换图进入同一个 `word/checkpoints` 请求，原生一次版本提交。只有图片变化时也保存，不依赖文字摘要发生变化。
- 图片归属来自不可变原生 projection 中的 canonical `readOnlyHtml` 映射 ID；再通过不可变 `/images/{id}?revision=N` 验证确为图片。客户端的页号、region 声明和共享 receipt 均不授权归属。原生结构规划器仍独立验证来源 map 与区域身份；无法确定归属时保留草稿并拒绝提交。
- 图片草稿摘要参与可信事务观察与手动保存同步检查，包括异步基线读取后的再次检查。未经服务端身份绑定的图片修改不能借用下一名文字编辑者的身份；图片单独修改也记录作者代次。
- 捕获区域、图片意图 ID 集合、原图、目标几何、替换 hash 和原请求一起进入 HMAC 私有准备日志，先落盘再 POST。日志读取校验请求与捕获逐区域完全一致、意图 ID 唯一、基线和几何有效；旧的纯文字准备日志仍可结算。
- 每次图片基线都从不可变版本读取并验证。离线旧意图的不同字段可合并；同字段不同值变成显式冲突候选。伪造原始几何或跨区域来源不能通过重基线消除。
- 回执后按提交版本重新读取图片，不直接信任客户端共享 receipt。先在副本验证完整图片确认，再重绑真实文字来源并确认图片；无效回执不丢意图，不部分确认文字。
- 只删除捕获的意图。保存期间继续改变尺寸/换图的因果后继保留并按字段更新基线；独立并发的重叠值保留为冲突。原请求恢复不重复发布版本，后续几何保存不重复换图。
- 不可变图片读取最多四个并行，缓存最多 2048 个版本/节点组合。沿用每文档 1000 个图片组、4000 个意图及私有日志大小上限。缓存失败请求会移除，网络未知结果仍保留原请求以便重试。
- 关闭发生在图片回执读取期间，也不能回写来源或广播已保存。仍需由房间宿主在 drain 前冻结远端包，组件本身不是逐包 admission。

## 验证与复现

```bash
cd examples/hdoc/editor
npm test
npm run build
```

```bash
python3 scripts/hcd-word-region-store.py --coordinator --images
```

新增 10 个协调器案例和 1 个私有日志案例，协调器/日志共 34 个专项检查，全部前端共 811 项通过。覆盖图片独立保存、联合替换、作者归属、真实 capture 恢复、迟到因果尺寸修改、旧基线的不同字段合并/相同字段冲突、伪造基线/回执、异步同步检查和关闭期间回执。磁盘失败等旧检查依然是受控注入；没有宣称浏览器/生产验收。

真实验证使用新建的合成文档和受控 Alice/Bob 身份：

1. Bob 通过原生暂存接口上传不同 PNG，并修改页眉图尺寸。Alice/Bob 同时修改正文、标题、页眉页脚和人员提及。
2. r2 原生联合提交成功，代理立即关闭 TCP 响应。Alice 在此期间继续输入页眉文字并再次改变图片宽度。
3. prepare 进程退出，另一个 Node PID 从私有日志恢复原请求，重放返回 r2，后续文字/尺寸仍待保存；再提交为 r3，作者仅 Alice。
4. 按 r2/r3 分别回读不可变图片，替换 hash 不变、宽度分别为 731520/1143000 EMU。r3 请求仅含几何，不重复替换资源。
5. 直接解析实际 DOCX 的页眉关系、嵌入资源和 `wp:extent`，确认引用的是新 PNG 字节和最后尺寸，而不只是“ZIP 中存在某个图片文件”。正文、页眉页脚、人员姓名、原页码缓存仍在正确位置。
6. HCDZ 离线重开 r1/r2/r3 状态完全一致，原生与离线 bundle validate 均通过。Bob 的新增提及事件仍只有一次，Alice 后续文字/图片保存不重复产生事件，提醒关闭。
