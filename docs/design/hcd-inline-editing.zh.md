# 行内容器中的命令、人员提及与 AI 目标

本轮继续原七阶段目标，接通模型 3 真实正文的内部交互。管理平台暂缓；提醒只保留关联事件，未投递任何提醒。

## 编辑上下文

新增共享正文上下文检查，`/`、默认人员提及及语义 AI 适配器使用同一个检查。普通段落和标题沿用既有行为；行内容器必须已有协商模型，并且所有包围当前光标的 codec 均可用。内层已注册而外层未知时仍拒绝操作。

可用性来自当前编辑器的保护插件及宿主注册器，不从文件或共享协作状态读取一个“允许编辑”的标记。扩展注销后，即便文档、光标和已输入查询都没变，已暂存的 `/` 插入也不再提交；未知正文保持原样。正文内容、人员身份及历史仍由原结构/权限/保存门禁保护。

## `/` 与默认 `@人员`

- 容器内支持按边界触发查询、中文和多词搜索，继续排除 URL、邮箱、代码和链接。输入法组合阶段不显示建议，提交后恢复。
- 行内正文允许字面文本、换行、行内业务节点、嵌套行内容器以及 AI 入口。标题、列表、引用、代码块、分隔线等块操作不能通过 PM 的自动适配把内容挪出包装器。普通块扩展的所有命令入口显示不可用；实际事务也独立拒绝，原查询不被提前删除。
- 人员菜单继续使用现有服务端候选和解析流程，没有从在线成员列表生成候选。插入保留独立 `mentionId`、稳定人员 ID 与名称快照；递归正文 snapshot、协同、个人历史、保存及导出保持同一引用。
- 本轮同时修正主页面 `file.recovery` 的动作状态，使已接入恢复组件的 inline1 会话可以打开统一恢复入口。文件选择、比较及确认的实际界面验收仍须继续。

## AI 目标与接受

行内 AI 目标使用容器 occurrence 身份、永久正文载体的相对锚点及当前选区指纹，不使用标签或当前根段落序号。目标前的同伴输入会映射位置；目标文字/格式变化、容器删除、codec 注销会使旧建议失效。自动补全继续要求原光标和边界保持有效。

接受后的字面文字/换行进入正常 PM → Yjs → 协调保存链路，是一条可撤销的个人动作，保留独立同伴输入。选区不得跨越业务包装器或提及原子去覆盖业务身份。已有通用 Provider、流式事件、取消、建议接受和灰字隔离链路保持；本轮没有接入真实外部模型服务，不将接受一段指定测试文字称为外部 AI 生成验收。

## 验证分层

`src/inlineEditing.test.ts` 使用真实 PM schema、保护插件、结构 binding、Yjs 双副本与个人历史，覆盖容器内部插入、块扩展拒绝、嵌套保护、暂存操作失效、输入法、代码/链接、提及身份、AI 定位和失效。

实际服务验证命令：

```sh
python3 scripts/hcd-inline-room-files.py --inline-interactions
```

该命令创建独立合成文档并运行生产 sidecar、原生 HTTP、真实 Socket 和 PM binding，不操作用户文档。它从服务端查询 Bob，在容器内插入提及并保存到 r12；原生关联索引包含递归位置，新增关联事件的实际操作者为 Alice。接受指定测试文字保存到 r13 后，提及身份保持，普通正文变化不再产生关联事件，提醒始终关闭。独立进程重启后继续保存到 r14，DOCX/PDF/PPTX/Markdown 保留姓名和接受文字，HCDZ 离线规范回读精确一致，原始 r8 归档不变。文件与结果在 `docs/assets/hcd-inline-interactions-2026-10-27/`。

前端复核命令：

```sh
cd examples/hdoc/editor
npm test
npm run build
```

## 界面验收限制与开放工作

Chrome 的旧标签焦点控制失败；新标签可以读取已保存 r14 正文和双方姓名，之后输入调用再次超时。复核时原生规范头仍是 r14，未把输入调用当作 `/` 或 `@` 界面成功。本轮没有修改浏览器的文件权限，未重建已有协作房间，也没有把 headless 服务验证替代浏览器弹层位置、键盘操作、选区或文件选择验收。

原主页面的资源/恢复包、只读重入、删除审阅和故障交互仍需复核。整块复制/移动/转换、旧 epoch/旧模型审阅迁移、跨文档资源和全部跨设备任务、长文容量/虚拟化、Word 追加基础能力及原七阶段其他开放项继续保留。不能因本轮内部交互接通就宣布完整目标完成。
