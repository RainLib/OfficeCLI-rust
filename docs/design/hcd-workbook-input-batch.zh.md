# Excel 输入缓冲和批量操作恢复

日期：2026-10-27。此增量承接 [Excel 保存与恢复](hcd-workbook-save-recovery.zh.md)，完整目标及格式范围见[能力矩阵](hcd-current-capabilities.zh.md)。

## 未映射空格创建的只读核验基础

格式库新增 `inspect_xlsx_virtual_blank`，对当前 HCD 验证并计算映射指纹，用清单摘要及长度核对原始 XLSX 的独立快照，定位同一工作表和规范单元格地址；检查公式范围、合并覆盖区域、已有 HCD 映射以及源 XML 中实际存在的单元格。结果带文档、版本、根、映射指纹、源摘要、工作表、地址和稳定节点 ID；末尾重查版本和来源。定向测试覆盖不存在的普通格、无物理单元格的数组公式结果、合并覆盖格、已有映射、源中存在但未映射的格、非法地址、错误工作表和来源变化。

该定向测试通过。`cargo clippy -p hcd-formats --lib -- -D warnings` 未通过：当前工作树另有 PDF 布局的两处类型复杂度和 PPT 图片几何的三处 lint，本次没有修改这些既有代码；未运行全量测试或浏览器验收。

这只是读取时的观察，不是预留、写权限或事务，也未接入页面。要真正编辑任意空格，仍需在文档锁内重新核验来源、身份、目标及版本，以原子操作写入有界网格分片、源映射、历史和幂等回执，并处理并发同格创建、撤销、草稿恢复、公式证明失效和无源边界；有源 XLSX 导出也要安全插入缺失的行与单元格并维护必要的工作表范围。上述能力尚未完成，当前浏览器仍拒绝未映射空格。

后续增加内部工作表插入原型：只接收明确的规范地址和文本，在有序的 `sheetData` 中创建缺失行或单元格，按需扩大已有 dimension、移除受修改行的过时 spans，并保留原有单元格、样式、公式、合并声明及 XML 命名空间；已有目标、无效地址、无效 XML 字符和无序行列拒绝。测试将三个新值写入实际 XLSX 包并重新导入、校验 HCD，另覆盖现有行、空行、新行、空 sheetData、命名空间、文本转义和相邻公式；格式库 XLSX 专项 26 项通过。调用方仍须在独立候选写入前核验来源、公式与合并区域；这一内部函数尚未接到 HCD 导出、保存协议或浏览器，不代表用户已经可以编辑未映射空格。

格式库随后新增只读 `preview_xlsx_virtual_cell`：核验空格和源身份，先按固定版本导出已有 HCD 修改，再在独立候选工作簿中插入新值；发布候选前重新检查规范版本和来源，且不覆盖已有目标文件。测试在已有单元格修改保存为 r1 后生成候选，核对既有修改、新格与数组公式，原 HCD 版本和根不变；公式结果格拒绝且不产生文件。将该合成候选交给本机 LibreOffice 无界面重新保存，再由独立 XLSX 读取器回读，已有修改、新格、公式及两个合并区域均保留。该函数只生成可供检查的文件，不预留单元格、不写 HCD，也没有浏览器入口；一次候选会多次扫描并复制源文件，尚未做大表性能、真实 Excel/WPS 或并发竞态验收。

格式库 Clippy 在显式放宽前述三类既有 lint 后通过；这不是全量严格 Clippy 通过。候选输出通过同目录临时文件及不覆盖目标的硬链接发布，工作表中间文件会显式刷新并检查错误；跨文件系统或不支持硬链接的环境可能拒绝生成候选。

空白格只读核验及候选生成现支持批量和跨工作表：同一批次统一验证 HCD 映射与源文件快照，按工作表收集目标后检查公式、合并和源中已存在的格；同一规范坐标重复出现、任何目标受保护或异常时整批拒绝且不发布文件。上限为 4000 格、总文字 2 MiB；不同工作表的修改在同一候选 XLSX 中输出。格式库测试覆盖同表多格、跨表、已有已保存修改、重复地址、受保护目标及失败无文件，重新导入并校验候选；这仍是只读候选，未接入保存事务、浏览器粘贴或多人协作。源文件和工作表按批次而非每个单元格重复读取，但大工作簿性能、真实 Excel/WPS 和网络竞态尚未验收。

## 输入与恢复

- Univer 单元格尚未确认的文字输入单独写入当前设备的私有快照，附带源、版本、单元格身份、原值和输入值；不会因此发布或自动保存到服务端。取消输入清除未完成缓冲，已经存在的草稿不受影响。编辑器意外卸载后保留缓冲并要求先恢复或放弃，防止新输入覆盖。
- 含输入缓冲的快照使用 v4，旧格式仍可读取；带缓冲的降级格式拒绝读取。恢复时先明确比较，确认后才转为普通文字草稿并按既有保存和冲突协议处理。公式计算和格式不会从该缓冲恢复，界面有提示。
- 比较中的服务端内容固定到显示的版本；确认恢复前重新检查身份、权限和最新版本。版本变化则刷新比较并要求再次确认；读取失败禁用恢复，仍可下载备份或打开服务端副本。文字对象可分批读取和比较，长文本可展开完整内容；图片候选可分批显示。详见[恢复比较分页](hcd-recovery-review-pages.zh.md)。

## 批量历史

映射单元格的多格修改预检目标、数量及历史容量后，作为一次个人撤销/重做动作记录。混合受保护公式或未映射目标的粘贴整体撤回并提示；上限为 4000 格及序列化历史约 419 万个 UTF-16 代码单元。撤销或重做前，读取固定版本的全部目标并再次核对最新版本；任一目标冲突、权限变化或读取失败时整组不变，历史保留。最后一次核对之后仍可能发生竞争，正常保存依靠现有版本前置条件和冲突流程处理。历史当前仅在会话内保存，不跨刷新。

完整前端测试 1136 项通过；TypeScript 和应用、嵌入及独立 XLSX 适配器构建结果见同目录日志。测试覆盖输入取消、两种事件顺序、冲突、授权、比较版本变化、批量竞争及容量门禁。原双成员浏览器验证使用同机合成数据；真实输入法组合、多行与大范围/复杂剪贴板、合并单元格、样式、存储驱逐及多节点部署仍需专项验收。高频输入期间持久化队列的容量和性能也未完成压力验证。附件交互缓慢、Word 分页与页眉页脚、PPT/PDF/Excel 其余创作能力以及原目标继续，管理平台和实际提醒暂缓。

## 2026-10-28：浏览器进程强制终止后的恢复

使用隔离测试工作簿和独立 Chrome 用户目录，向 B1 输入 `崩溃未确认😀` 而不按回车，确认 IndexedDB 中的 v4 缓冲对应 B1 且服务端仍为 r0 后，以 SIGKILL 终止测试 Chrome 进程组。使用同一用户目录重启后，恢复比较展示本机输入及原值 `Original Bob`；确认恢复后通过正常保存得到 r1。独立读取实际 XLSX，验证 B1、其他单元格及公式缓存；HCDZ 通过原生校验，解包文件与该样例规范目录逐字节一致。证据见 `docs/assets/hcd-workbook-browser-crash-2026-10-28/browser.json`、`files.json` 和截图。

复现：先运行 `python3 scripts/hcd-workbook-recovery-preview.py` 保持隔离服务运行，使用其输出的样例根目录依次执行 `node scripts/hcd-workbook-browser-crash.mjs <样例根目录> <证据目录>` 和 `python3 scripts/hcd-workbook-browser-crash-verify.py <样例根目录> <证据目录>`。样例私有配置包含凭据，不应发布；脚本使用 macOS Chrome 独立临时用户目录，不操作现有浏览器。

该结果仅证明缓冲已可从 IndexedDB 读取之后的单次同机进程终止恢复；不证明每次按键即时持久化，也不覆盖系统断电、真实输入法、移动端、存储驱逐或跨设备恢复。

## 2026-10-28：统一独立适配器的批量保护

独立 XLSX 适配器原先在混合操作包含受保护或未映射单元格时，只回退这些单元格，仍可能向外发出其他单元格的部分 patch。现在主编辑器与独立适配器均回退整组操作并报告 `workbookUnsupportedPaste`；主编辑器中已有的私人草稿继续保留。适配器单元测试覆盖两种入口、受保护公式的显示值与样式、已有草稿和不产生 patch。该测试使用模拟网格，不能代替独立入口的真实浏览器与导出验收；公式编辑及未建模空白单元格仍不支持。

直接尝试编辑时，适配器现在对无映射或尚未加载、受保护单元格，以及前一笔修改等待确认分别给出提示；主编辑器支持界面语言，独立查看器也显示说明。已有草稿和保存规则不变。事件测试覆盖拒绝原因与允许编辑的映射单元格，未做本次变更的真实浏览器验收。此提示不是新增空白格或公式编辑：支持它们仍需源映射、公式范围防护、保存与 XLSX 导出完整贯通。

滚动后可见窗口的加载失败现在会显示明确提示和重试入口；重试只加载当前工作表窗口，不重新创建编辑器或清除本机草稿。异步结果按最近一次窗口请求及当前工作表过滤，旧请求迟到不会覆盖当前提示；启动阶段加载失败仍使用原有文档错误界面。组件测试覆盖失败、恢复、草稿保留和旧请求迟到，尚未完成浏览器故障注入验收，也不意味着未映射空格可编辑。

后续隔离浏览器故障注入发现：工作表的旧 `onScroll` 可能在渲染器就绪前注册为空监听，导致滚动到远处不请求数据。现改用 Univer 渲染生命周期管理的全局滚动事件，并按工作簿过滤。600 行工作簿中先阻断保存并编辑 A1，再阻断分片请求、滚动至第 433 行，浏览器显示加载失败及重试；恢复连接并重试后第 433 行显示原文。随后核对保存结果得到 r1，源 XLSX 回读 A1 的原文与新输入均存在，第 433 行不变。[验证摘要](../assets/hcd-workbook-window-retry-2026-10-28/evidence.json)。保存成功后界面仍出现一次“暂时无法连接文档服务”提示，原因尚待定位；本次不把它当作完整异常恢复验收。

后续定位上述提示：规范保存完成时，版本事件可能已触发工作簿重新初始化，新客户端存在但尚未读到 manifest；保存后刷新直接访问其 revision 抛出 TypeError，被界面归类成连接失败。现在仅更新已加载 manifest 的客户端，新初始化客户端从服务读取当前版本。相同隔离浏览器故障流程重测显示 r1 已保存且错误提示消失，导出的 XLSX 回读包含先前输入；浏览器仍记录一次 React 同步卸载警告，且工作簿重建后回到首行，继续需要单独优化，不把这次结果等同于所有保存竞态已解决。

后续修复本人保存回执先于版本通知时的误判：保留最近 128 个本机不可变请求身份，使迟到的本人通知不再被当作其他成员的未知节点更新触发重建；重置通知和其他成员的请求仍按原规则处理。隔离双浏览器中 Alice 从失败恢复并保存 r1 后仍停在第 433 行，Bob 看到 Alice 的输入；Bob 保存 r2 后 Alice 收到其内容，XLSX 回读 A1、A2 均包含两人的修改。[验证摘要](../assets/hcd-workbook-window-retry-2026-10-28/own-revision.json)。当远端更新落在未加载区域时仍会重建并回到首行，React 卸载警告也需继续处理；本次没有覆盖所有并发时序。

后续对远端更新导致的必要重建，在更新前捕获工作表、可见起始单元格、缩放和选择范围；新工作簿渲染完成后恢复视图并加载可见窗口，若工作表不存在则不强行定位。隔离双浏览器中 Alice 停在第 433 行，Bob 修改当前未加载的 A1 并保存；Alice 刷新后仍停在第 433 行，返回首行看到 Bob 的内容，源 XLSX 回读通过。[验证摘要](../assets/hcd-workbook-window-retry-2026-10-28/remote-viewport.json)。当前验证为单工作表，尚未验证不同工作表、进行中的单元格输入和精确像素偏移；React 同步卸载警告仍需处理。

后续验收进行中的输入：Alice 在 A433 输入尚未确认时，独立的 Bob 身份通过实际服务修改 A1；输入保持可见，确认后 Alice 的 A433 保存至 r2，源 XLSX 回读包含双方内容，画面停在第 433 行。验收发现同 revision 的追踪快照可反复触发重建，现保留草稿核对但不再对已经加载的规范 revision 重建；同时在卸载时取消排队的滚动帧，并在 React 提交结束后释放旧 Univer 实例。该次浏览器控制台未出现同步卸载或已销毁注入器错误。[验证摘要](../assets/hcd-workbook-window-retry-2026-10-28/in-cell-remote.json)。本次使用单工作表和不同单元格，没有验证同格冲突、多个工作表或所有重建时序。

补充两个隔离验收：两张各 600 行的工作表中，Alice 停在第二张表第 433 行，另一成员更新第一张表的 A1；刷新后仍处于第二张表第 433 行，切回第一张表显示远端内容，源 XLSX 两张表回读正确。[多表结果](../assets/hcd-workbook-window-retry-2026-10-28/multi-sheet.json)。另在 Alice 正输入 A1 时，由另一成员修改同一单元格，确认输入后界面显示本机和协作内容，选择保留本机内容才提交 r2；源 XLSX 历史 r1 仍为对方内容、r2 为所选本机内容。[同格结果](../assets/hcd-workbook-window-retry-2026-10-28/same-cell.json)。这些样例未覆盖每种跨表编辑、输入法、权限撤销或断电时序。

进一步验收发现，先前的远端更新重建后虽然内容和位置正确，继续输入可能失效。对于普通文字版本事件，现将尚未加载单元格的最新文本与 hash 保存在当前适配器，加载旧快照分片时覆盖成最新内容；已加载单元格继续原位更新。这样一般的远端文字更新无需重建，重置、结构变化及超出 10,000 条缓存仍回退到重建。保护格或公式格若遇到不兼容覆盖会拒绝加载而不是静默改写。隔离双表浏览器验证远端修改第一张表后，在第二张表继续编辑并保存，再切回第一张表看到远端值并继续修改保存；最终源 XLSX 回读两张表均正确。[验证摘要](../assets/hcd-workbook-window-retry-2026-10-28/remote-overlay.json)。编辑中收到远端更新、重置事件或缓存超限仍可能走重建，其重建后继续输入的异常尚未完全解决；不能把此项视作所有协同场景完成。

普通远端事件在单元格输入期间改为有界暂存，等输入确认并被草稿层观察到，或取消输入后，再按顺序核对草稿并应用；未处理的输入缓冲仍阻止应用。重置、队列超过 128 项或约 200 万字符时回退安全刷新。隔离浏览器及独立成员 API 验证不同格并发后可继续输入并保存；同格并发显示双方值，明确选择后可继续编辑下一格。源 XLSX 和历史版本回读结果在[验证摘要](../assets/hcd-workbook-window-retry-2026-10-28/deferred-input.json)。重置或超限导致的重建后输入、真实输入法及跨设备仍需验收。

隔离主编辑器浏览器补验：双击未映射 D1 和公式 C1 分别显示相应提示，规范版本仍为 r0；未在本次检查中实际编辑或导出工作簿。

有源 XLSX 保存核验与源文件导出现在也检查合并范围，拒绝写入被覆盖位置，允许合并区域左上角的锚点。此检查还会影响复用同一来源核验的公式映射审计；其目的是防止旧或错误映射把不可见的合并覆盖格当普通文本修改，并不支持创建新单元格。无源证明的兼容、历史错误修复和真实浏览器保存仍需分别核验。

由于旧版无源公式保护证明没有涵盖合并覆盖格，新证明升级为 `/2`，不接受 `/1` 证明作为无源编辑授权。已有旧证明的工作簿需要先恢复匹配原文件，重新执行检查并启用保护；草稿与已提交请求回执仍走原有恢复流程。该升级不修复此前保存的历史版本，也不改变有源工作簿的正常编辑。

合并覆盖格的保存、公式保护检查及启用保护入口统一返回 `XLSX_MERGED_CELL_READ_ONLY`；工作簿页面分别说明草稿未保存或当前版本映射冲突。客户端在查询原请求回执确认未提交后释放请求，保留原草稿供用户处理。专项以人为构造的旧映射及合成工作簿覆盖三个服务端入口和草稿保留，不能作为生产旧文件或真实设备验收。

### 新导入工作簿的已存空单元格

导入时，原 XLSX 中实际存在且未被合并区域覆盖的空单元格会生成稳定源映射；公式结果范围仍标为只读。它使用已有的单元格草稿、版本前置条件和有源保存校验，原稿导出将原有空 `<c>` 写成文字并保留其他源部件。原文件不存在的网格空位仍没有映射；已导入的旧 HCD 也不会自动补映射，空的共享字符串索引异常仍不作为此能力。样式格数量多的工作簿会生成更多节点，需继续做容量和性能验收。

22 项 XLSX 格式测试通过。隔离浏览器在原文件包含空 D1 的合成工作簿中输入、自动保存至 r1；另一成员重开看到修改，实际下载 XLSX 回读 D1 文字和 C1 原公式，未生成不存在的 E1。见[文件回读摘要](../assets/hcd-xlsx-stored-blank-2026-10-28/evidence.json)。这不是跨设备恢复、全空白格编辑或旧文档迁移验收。

后续验证发现一行包含 16,384 个已存空格时，新增映射会使单行超过 2 MiB 分片上限。现在这种单行会回退到旧的稀疏显示，移除该行可选空格映射并在 manifest 写入 `XLSX_STORED_BLANK_MAPPING_LIMIT` 与数量；源文件字节仍保留，其他已有内容不因空格映射而丢失。受控导入测试覆盖极宽行及警告，并验证数组公式结果保持只读、合并覆盖格不生成映射、空的合并锚点可编辑。此回退并不提供这些空格的编辑能力；跨多行的合并组容量、大表性能和提示在所有入口的可见性仍需验证。

跨行合并组现在也可在仅因可选空格映射超限时，回退组内空格映射并重建同一分片，避免拆开合并区域；被移除的数量加入同一警告。两行合成样例包含 15,998 个可选空格，验证导入、警告数量、锚点内容和 HCD 结构。若移除可选空格后原有内容仍超限，仍按既有限制拒绝。实现会暂存当前分片各行以便回退，增加导入期内存；真实大表性能、浏览器警告展示及原文件不存在的空格编辑仍未完成。

后续主工作簿页面和独立查看器识别该警告并持续显示“部分原有空单元格暂不能编辑”，不直接显示服务端自由文本。隔离浏览器用真实极宽工作簿导入后确认主页面提示；独立查看器本次仅构建验证。

另用原文件存在空 D1 的隔离工作簿，阻断保存和回执后输入文字，新标签页显示本机草稿和待核对原请求；恢复连接、确认比较并核对保存后得到 r1，下载的 XLSX 回读 D1 内容和 C1 公式。见[恢复验证摘要](../assets/hcd-xlsx-stored-blank-recovery-2026-10-28/evidence.json)。这只验证同一浏览器的两个标签页，不代表进程崩溃、系统断电、跨设备或任意空白格已验收。

同一原始空 D1 的双成员隔离浏览器补验：Bob 阻断保存及回执并输入草稿；Alice 修改同一格并保存 r1。Bob 页面列出双方不同内容，原请求核对前禁用冲突选择；连接恢复并核对后，Bob 明确选择保留本机内容，保存为 r2。Alice 再次撤销时显示字段已改变，未覆盖 r2；实际 XLSX 回读 Bob 的 D1 和原有 C1 公式。见[协作验证摘要](../assets/hcd-xlsx-blank-collaboration-2026-10-28/evidence.json)。此样例验证版本与冲突处理，并非逐字 CRDT、跨设备或崩溃恢复。

极宽行与跨行合并组的回退进一步调整为按实际分片空间裁减：优先保留较早行、较靠前的已存空格映射，只有超出预算的部分不开放编辑；警告数量反映实际裁减数量。预算包含真实生成的外层标记和列信息。合成极宽行测试检查保留的空格可经过源校验、保存和 XLSX 导出，未映射的尾部原始格仍留在源导出；合并组测试验证只裁减部分空格、保留锚点和有效 HCD。这些是格式库测试，真实大表交互、导入耗时与内存仍需验收；旧文档和原文件中不存在的空格仍不自动映射。

裁减搜索改为计算候选长度，仅对最终选择重建行，保留稀疏列、合并覆盖和相同的分片预算。新增稀疏列测试核对长度和保留列，23 项 XLSX 格式测试及 Clippy 通过。同一合成测试各运行一次的进程最大 RSS 分别约 107 MB 和 77 MB，测试本体约 12.49 秒和 11.44 秒；后一次与短暂并行的 Clippy 有资源竞争，这些单次数字包含多个导入、校验和导出步骤，不能当作可靠基准或真实大表性能承诺。

进一步发现，保留空格映射直到分片恰好接近 2 MiB 时，输入约 8 KB 即可能触发保存大小限制。新导入对包含可选空格映射的分片尽量预留 128 KiB 编辑空间；若原有内容本身无法达到该预留，移除可选映射后仍允许未超硬上限的原有内容导入。合成测试覆盖极宽行的较长文字保存和原稿导出，以及约 2 MB 已有文字不因可选预留被拒绝。这不是无限扩容：后续累计修改仍可能达到硬上限，动态重分片、大表浏览器性能和真实多设备验收继续开放。

## 2026-10-28：阻止新增公式被误存为计算值

## 2026-10-28：共享公式空标签保护

导入时将自闭合 `<f/>` 识别为公式，包含缓存值和无缓存值的共享公式从属单元格均标记为只读。源 XLSX 导出另检查被替换的原单元格：即便旧 HCD 映射曾错误标为可编辑，遇到公式也拒绝覆盖，避免静默丢失公式。单元测试使用 XLSX 包验证导入映射、服务端 patch 拒绝、相邻文字编辑后的公式保留及旧映射导出防线。

此前导入的 HCD 映射不会自动修复，旧映射仍可能允许保存错误的本地文字草稿，并在源格式导出时被拒绝；需重新导入原文件或设计保留历史与草稿的安全迁移。此保护不提供公式编辑或计算，也不覆盖没有源文件的语义导出，更不代表完整 Excel 浏览器或生产验收。

后续扩展到原生 XML 中由 `array` 和 `dataTable` 公式声明的结果范围：即使结果格没有自己的 `<f>` 标签，新导入映射也标为只读，源格式导出会先检查被修改坐标是否落入这些范围。范围缺失或非法时拒绝导入；源码级测试覆盖共享公式、数组结果、数据表结果和相邻普通单元格。源格式导出为此会额外扫描有修改的工作表，尚未做大表性能验收。旧 HCD 的错误映射仍不会自动修复，保存时的保护仍待补齐。

后续在原生服务的文本编辑保存入口增加有源校验：保留原始 XLSX 时核对源文件哈希和大小，对本次目标检查原公式与结果范围，再进入现有版本 CAS；旧请求的幂等回执仍可重放。服务函数测试构造错误标为可编辑的旧映射，验证公式结果保存被拒绝、普通格可保存及重放。此校验每次会读取源文件并扫描相关工作表，尚未做大表性能验收；缺少源文件时继续使用现有映射，无法据此保证旧映射正确。它没有修复已有错误版本，也不覆盖绕过服务直接调用核心库的写入或浏览器验收。

后续在同一浏览器设备重新打开文档并验证恢复页：旧请求被代理阻断、另一成员保存 r1 后，新标签页显示原请求和输入；选择恢复后核对到旧请求已过期，恢复页选中新设备分支并提示文档状态变化，内容仍在。再次审阅并选择恢复后，输入保存为 r2，导出的 XLSX 保留两位成员的内容及原公式；请求记录只有一次阻断的创建、一次回执查询和一次新的创建，见[回读](../assets/hcd-workbook-single-reopen-superseded-2026-10-29/readback.json)。旧编辑标签页在测试中仍然打开，因此这不是浏览器崩溃、服务器执行中断网、物理断电或跨设备验收。

批量草稿列表与逐格对照的本机文本现在默认最多展示 400 个 UTF-16 单元，并避免在代理对中间截断；用户可按单元格展开完整内容或收起。草稿、备份和提交内容不受预览截断影响。14 项批量保存、比较及预览专项和 TypeScript 检查通过；本机浏览器组件样本验证长文本展开与收起。这尚非完整工作簿页面的大批量性能基准，展开极长单格仍需渲染该格完整内容。
