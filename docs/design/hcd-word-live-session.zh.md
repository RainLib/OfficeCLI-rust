# 区域 Word 正常编辑页的自动会话交接

2026-10-30。本批将[会话桥接基础](hcd-word-session-bridge.zh.md)接到正常 `RegionalWordEditor`，不再仅由测试客户端手动接管。管理平台和实际提醒继续后置。页面设置按钮、完整请求持久化与原请求重试仍是下一阶段。

## 正常入口

`WordLiveSession` 管理一个窗口的连接生命周期。已准备的 `/2` 页面轮次使旧连接关闭时，保留断开事件的确切 transactionId，使用当前成员凭据查询该轮次；只有确认已安装，才让空 Y.Doc 新传输加入并核验不可变投影。未知、超时、权限或基线变化停止自动接管，保留草稿，允许核对同一轮次或进入恢复。普通连接故障和旧 `/1` 协议不会因此获得自动复用旧快照的能力。

原窗口的编辑文档、clientID、图片草稿及个人历史由会话层持有，编辑视图卸载不会销毁历史。历史的可写判断读取当前连接，并在交接过程中保持禁用。新 Provider 的 awareness clientID 与保留文档的 clientID 不相同，浏览位置所有者和跟随循环判断现使用实际 awareness 身份。

切换顺序为：保存界面状态 → 同步卸载旧视图 → 销毁仍存活的旧编辑器 → 再次验证 → 应用服务器状态。旧模型守卫不被放宽。界面代码保留分节、变体、页眉页脚模式、操作页签、侧栏、导航、缩放及滚动状态；本批实际浏览器覆盖第一节和默认工作区，复杂焦点、滚动与所有侧栏组合未逐项验收。

设备库保持打开：交接前排空旧日志，销毁视图期间仍捕获本机输入；桥接验证失败不会丢弃迟到输入。桥接成功后才从确切旧文档解绑，保存已验证状态，再交由新浏览器控制器按原有恢复规则重新检查并绑定。解绑不能作用于另一个文档，不清除日志、附件或审阅水位。新增状态来自服务器时按比较副本记录，后续本机操作仍按本机增量记录。下载、设备恢复和正常保存继续走原入口。

## 实际浏览器发现的问题

首轮完整切换暴露真实的卸载异常：`WordRegionView` 键盘监听清理在编辑器已销毁后读取 `editor.view.dom`。现改为设置监听时保存 DOM，并先同步卸载，再销毁旧编辑器。只读效果亦避开已销毁实例。模型层测试通过不能替代这项浏览器修复。

测试脚本另修复了两个准备问题：Chrome 插入首个文字时的空白表现可能使用 NBSP，标记改为独立唯一文字；保存按钮需等待同步/原生验证完成，自动保存已覆盖时手动保存不要求再增加版本。没有放宽协作内容、个人撤销或导出断言。

## 验证范围

隔离 Chrome 中使用正常嵌入页、实际原生服务与侧车，以及两个可写成员和一个只读成员。页面事务由实际鉴权 API 发起，**不是通过尚未接通的页面设置按钮**。

最终样本：r18 保存自己的输入，r19 页面事务完成后三个窗口自动恢复且 timeOrigin 不变；同伴在同一段落输入并保存 r20，自己的撤销保存 r21、重做保存 r22，同伴文字一直保留。只读成员仍无可编辑区域。下载真实设备备份后，刷新页面重开仍含双方内容，未额外增加版本，最终无浏览器异常。

实际 r21/r22 DOCX 分别检查自己的文字移除/恢复、同伴文字各一次、页面宽度和页眉页脚不变。HCDZ 解包后核对 r17–r22 的完整投影与原版本相同。设备 `/6` 备份按真实会话身份校验并重建区域模型，纸张与双方内容一致。

源码测试覆盖空文档新传输、保留文档/历史、卸载顺序、未知状态不建新连接、迟到输入留在设备库、只读交接、等待中卸载及忽略取消的后端不得继续创建连接。当前完整前端 1856 项，交接/设备库专项 13 项；构建及详细证据见 [validation.json](../assets/hcd-word-live-rebind-2026-10-30/validation.json)。

尚需接通正常页面设置、刷新后的完整请求恢复、未知提交的原请求重试/取消、页面字段自身个人历史、story 创建与链接；真实 IME、复杂焦点/多窗口交错、物理设备、外部 Office 和多实例继续单独验收。Word 正文数据分段、其他格式创作和完整目标没有被本批替代。

复现：先启动 `python3 scripts/hcd-word-layout-browser.py --clean`，再把其输出的隔离 root 传给 `node scripts/hcd-word-live-rebind-browser.mjs ROOT OUTPUT_DIR`，随后运行 `python3 scripts/hcd-word-live-rebind-files.py ROOT OUTPUT_DIR`。测试只修改隔离合成文档；每次浏览器运行使用唯一文字标记。复用已完成的同一版本文件输出目录时，应明确选择新的归档/解包路径，避免把输出已存在误判成格式失败。
