# 附件定位与命令工具栏开销

日期：2026-10-27。承接[附件恢复验证](hcd-inline-resource-recovery-ui.zh.md)中交互超时的调查。

## 发现与调整

在克隆的 r26 样本中，点击行内容器标签曾发生浏览器控制超时，随后选区实际生效。开发模式 CPU 采样显示，命令工具栏为每个按钮调用 `visible`，而每次都重建完整编辑上下文；其中反复计算块操作保护并执行嵌套业务节点 codec/导出适配校验。原始采样中 `visible` 子调用栈有 3967 个采样点（整次 16268 个采样点，包含空闲）；这说明存在可消除的重复工作，但不足以证明它是所有控制超时的唯一原因。

命令列表现在以一次上下文快照按标签页过滤，工具栏复用过滤结果，不再对每个按钮重复请求上下文。菜单隐藏、标签页和格式过滤保持原语义；执行命令仍实时复核当前权限、选区及动作状态，不缓存执行授权。专项测试确认单次列表只读取一次上下文、标签页和隐藏规则保持有效，列出之后撤权仍不能执行。

## 浏览器与文件验证

在单机隔离样本中，通过故障代理让 `recovered-resource.txt` 上传失败；选中另一个节点，再点击“查看并处理属性”，界面返回正确的“附件恢复字段”，并启用针对该节点的关联。该次按钮调用约 1.16 秒（包含自动化调度，并非性能基准）；点击前后的 CPU 采样条件和时长不同，不能据此推算整体提速百分比。调整后的该次采样不再出现工具栏 `visible` 调用栈。

随后通过实际界面继续上传、确认关联、保存到 r27，另一个同机窗口重新打开并看到两个附件。原生只读核对确认 r26→r27 仅目标节点资源引用变化，协作者名称与其余正文不变；离线 HCDZ 解包后的 r26/r27 投影和两份资源字节匹配。见 `docs/assets/hcd-resource-performance-2026-10-27/native-readback.json` 和截图 `reopened-r27.png`；核对脚本为 `scripts/hcd-resource-performance-readback.py`。这些文件均为合成测试数据。

完整前端测试 1137 项通过；应用与嵌入构建结果见证据目录。未做生产规模长文、多浏览器/设备、性能基准或整个附件生命周期压力测试，也不能仅凭这次样例宣称所有页面超时都已解决。管理平台及实际提醒继续暂缓。
