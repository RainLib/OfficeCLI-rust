# Word 页面调整后的会话保留与事务查询

后续已将已知页面轮次的自动交接、设备日志重绑和个人内容历史接到正常编辑页，见[正常入口验收](hcd-word-live-session.zh.md)。下文保留桥接基础批次的实现与证据范围。

2026-10-30。本批补充活动页面事务后的客户端基础：新传输使用空 Y.Doc 加入，保留原窗口的本地编辑文档与个人历史；提供经过鉴权的只读事务查询。普通页面设置按钮、自动重绑和设备日志交接尚未接通，管理平台与实际提醒继续后置。

## 会话保留

直接用新 Y.Doc 重建编辑器会丢失本窗口的撤销栈；把旧完整快照发给新房间又可能把缓存中的同伴状态或未审阅输入带回服务端。`wordSessionBridge.ts` 将传输文档和本地编辑文档分开处理：

1. 新 Provider 始终使用空文档入房间，沿用 `WordBrowserState` 的成员接口、不可变投影与模型核验。
2. 在本地隔离副本中证明新传输状态完整包含旧编辑状态，同时检查待解析 Yjs 数据、区域身份与 story 拓扑。只允许已识别的页面字段及原生来源回执变化，未知字段不能被当作兼容变化。
3. 旧文档存在尚未包含的输入时拒绝桥接，保留原文档和个人历史，要求恢复审阅。状态编码每端上限 8 MiB，超限亦不自动放行。
4. 核验后断开旧传输，宿主须在 `beforeApply` 中同步销毁绑定旧布局的 ProseMirror 视图；然后再次核验，防止销毁期间的新输入被遗漏。
5. 仅把经过核验的新服务器状态应用到旧本地文档。旧文档的 clientID、保留的删除内容与撤销管理器继续存在，桥接建立时不向新传输发送旧快照。
6. 后续新传输更新进入本地编辑文档，本地新事务和显式设备恢复增量进入新传输。过期 Provider 的远端更新、受保护元数据修改或可写核验失败会关闭桥接；不会以完整快照补发。

桥接返回的新 `WordRegionStore` 不改变旧模型的布局守卫。保存后的来源回执仍须按原有不可变投影核验更新，不允许以桥接跳过授权、设备恢复或服务端更新守卫。story 创建、链接或其他拓扑变化不属于这条页面字段路径。

## 原事务的只读查询

`POST /v1/documents/{id}/collaboration/word-active-layout-status` 接受 `{epoch, transactionId}`。要求当前文档的读或写权限、相同 epoch、区域 `/2` 与布局版本声明，以及现有显式开关。查询不创建、提交、取消或重放页面事务，不返回 actor、页面请求或正文。

响应为 `hcd-word-active-layout-status/1`，回显 documentId、epoch、transactionId：

| status | 含义 |
| --- | --- |
| pending | 本进程持有确切事务，尚无完整安装/激活结果；不能据此判断原生内容未提交 |
| installed | 本进程已确认该事务安装并激活，另带确切 revision；仍须让新连接验证实际房间与不可变基线 |
| recovery-required | 本进程没有匹配的记录，须走原有签名恢复；不等于未提交或可换新编号 |

状态沿用活动事务现有的进程内、有界缓存。侧车进程丢失、缓存淘汰或另一轮事务替代记录时，未知结果仍需恢复，不以 HTTP 409 或缺少缓存清除原请求。客户端使用 30 秒取消时限、16 KiB 响应限制、严格 UTF-8、精确字段和身份回显核验。

`WordBrowserState` 的断开回调现携带 `{reason, topologyRequestId?}`，在同步通知观察者之前捕获本轮编号。该信息只用于查询确切轮次；旧控制器仍永久失效，迟到的 ready、release 或保存回执不能恢复其可写状态。普通连接故障及授权失败也不能凭编号直接重绑。

## 实际服务验证

`scripts/hcd-word-room.py --layout --active-layout` 使用隔离的原生服务、实际侧车、真实 WebSocket 和 Node 中的浏览器保存控制器：

- r6 保存自己的修改，页面事务在 r7 原生提交后截断实际 TCP 响应；重试同一请求只发生一次布局提交。
- 两名旧成员断开时均报告同一确切轮次。只读成员可查询未知、待处理及已安装状态；未鉴权、错误模型和错误 epoch/参数被拒绝。
- 新传输用空文档加入，保留旧本地 clientID 和个人历史；桥接建立不向新传输发缓存快照。
- 同伴在相同段落输入并保存 r8；保留文档的新 `WordBrowserState` 通过新 Provider 保存个人撤销 r9、重做 r10 和继续输入 r11，同伴文字始终保留。
- 实际 r9/r10 DOCX 分别核验自己的文字移除/恢复及同伴文字保留；最终纸张宽度、页眉页脚与替换图片一致。HCDZ 解包后 r1–r11 与原版本逐一相同。
- 稳定 `/2` 与旧 `/1` 房间回归，继续核验联合保存、重启、撤权、导出和离线回读。

首次新夹具使用整个正文区域的合并文本去修改一个段落，造成测试预期与实际块顺序不符；现改为只读取实际编辑的首个文字块，不改变跨段落结构或放宽历史保护。类型检查先后暴露未声明回执字段及擦除 section 类型的问题，均已修正，保留检查日志。

证据与命令摘要见 [validation.json](../assets/hcd-word-session-bridge-2026-10-30/validation.json)。这是本机合成文档和实际服务链路验证，尚无本批真实 DOM/IME、设备存储交接、自动重绑 UI、外部 Office 或多实例证据。页面字段自身的个人撤销也未由内容历史测试证明；普通操作区、刷新后的完整请求恢复及 story 结构编辑仍继续实施。
