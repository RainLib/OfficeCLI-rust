## 身份、预览和恢复

- 签名日志的 `topologyRecoveryIdentity` 识别原链接的 pending、已确认状态，以及紧邻的专用提升。后续普通保存会使该“紧邻转换”查询失效，不能把其他保存误当原轮次；已经安装的活动房间仍使用前批独立固定回执检查。
- 链接恢复要求 `/2`、节点/区域/布局版本及额外 `X-HCD-Word-Link-Version: 1`。旧客户端拒绝；只读或其他发起成员不能读取/恢复该私有请求。停止门禁、排他 owner 和即时成员授权覆盖读取及恢复过程。
- 影响详情从签名请求和固定基准布局计算，并核对基准布局摘要。每批最多 20 节，最多 4096 节；显示页眉/页脚及变体、继承来源或空来源、可见内容是否变化，以及原独立区域仍保留。没有把静态说明当作内容可视化差异。
- 恢复前先显示详情，再明确确认；不会自动恢复、创建新编号或清除私有草稿。确认始终恢复同一签名原请求。结果不明时仍核对同一编号。
- 未完成链接在原生提交后丢响应、侧车退出时仍保留版本 5 日志。新进程仅在没有活动内容房间时取得 owner，再按固定版本和原生签名核对；head 等于原目标才允许专用提升。
- 原 head 超过目标时，确认前显示当前与目标版本；原提交核对成功后返回独立的 `historical` 状态，保持版本 5 的确认及双方草稿，不提升、不覆盖当前文档。该状态不是“恢复完成且可以继续写入旧基线”。恢复页禁用不兼容的旧草稿比较、页面设置和独立区域动作，并明确历史比较/合并尚未接通。

链接响应另带 `headRevision`，与原目标 `revision` 分开；客户端校验两者及状态组合，拒绝历史状态伪装为已安装，或将普通页面/story 响应混入链接详情。现有页面/story 形状不变。

## 实际浏览器与文件验证

使用自有隔离原生/侧车、三角色 Socket，真实 loopback TCP 代理在原生 r2 已提交并读完成功响应后断开连接。活动请求返回未知并保留确切签名原请求及 Alice/Bob 的未保存正文；关闭这三个测试客户端、重启自有侧车后，通过普通嵌入编辑页完成恢复。

正常分支：

1. 普通页进入兼容性恢复视图；点击“检查待确认的更改”，显示第二节偶数页页眉将继承第一节、原独立内容保留。
2. 查看并明确确认后核对原 r2，没有重复链接提交；点击重新尝试进入正常区域编辑器，双方草稿均在。
3. 从操作区手动保存到新 r3。独立签名日志核对当前为模型 3，双方文字各一份。最终界面保护调整后另起新夹具重复同一完整流程。

历史分支：

1. 同样产生原生 r2 成功丢响应及侧车重启，再以 CLI 显式将 r1 还原为新 r3。
2. 普通恢复页在确认前显示文档 r3 已超过原目标 r2；明确确认后显示原链接在 r2、当前仍为 r3、私有草稿保留且未发布。
3. 独立核对版本 5 中原生确认和两名作者草稿均保留；再次核对同一原请求仍返回 historical，不改签名 tip，不推进规范 head。实际 HTTP 验证只读/其他成员 403、缺少链接声明 426、原发起成员可检查。

正常和历史分支均独立导出 r2/r3 语义 DOCX，检查页眉直接引用、正文标记出现时机和原图片字节；HCDZ 解包逐版本比较 r1–r3，区域目录及指定绑定变化正确，规范与离线校验通过。历史分支的两处私有标记没有进入任何规范版本或 DOCX。HCDZ 是规范版本归档，不包含这份未发布的私有签名日志。

前端完整 **1938 项**及 TypeScript、standalone/embed 构建通过；23 项相关专项与全量重叠，不相加。新增 5 项测试覆盖通用拓扑身份、源/空/同内容绑定、详情分页、实际翻译呈现、historical 响应及混合/伪造详情拒绝。按 React 技能复核了作用域取消、显式写操作、父级禁用、无条件 hooks、标量转义和有界列表；没有新增依赖。第三方 `use client` 和大包提示仍存在。

初次重启后立即检查遇到旧原生租约尚未到期，检查请求被拒绝；未重启或重提链接，稍后原检查成功。初次专项中的夹具把 prepare 结果对象误传为 tip 已修正；实际文件复验脚本现在先在自有临时目录生成并验证归档再替换证据文件，避免 `pack` 拒绝覆盖现存归档。最终证据与源码摘要见[验证清单](../assets/hcd-word-link-recovery-ui-2026-10-30/validation.json)。

## 复现及剩余边界

```bash
python3 scripts/hcd-word-layout-browser.py --clean --story-source --link-source --allow-restart --drop-native-link-response
node --import ./examples/hdoc/editor/node_modules/tsx/dist/loader.mjs scripts/hcd-word-link-recovery-prepare.mts ROOT OUT

python3 scripts/hcd-word-link-recovery-files.py ROOT OUT
# 历史样本另起夹具，在恢复前将原 r1 显式还原为新 r3，再从同样恢复页核对。

```

每套夹具结束后关闭自建浏览器页，停止自有父进程并确认所有子进程结束，再清理私有根；令牌、密钥及完整私有日志不归档。本批没有 Rust 修改/重建，使用有摘要的既有原生二进制；未重跑 Rust 全工作区或 Clippy，既有 Clippy 失败仍开放。

这证明真实原生、实际侧车、普通恢复 UI、签名草稿和规范文件的本机链路；不等于原窗口自动交接、跨物理设备、真实 IME、外部 Office、远端存储或生产多实例验收。正常链接 UI、设备原请求、历史草稿比较/合并/可携带私有恢复包、结构自身撤销和原稿混合导出仍需继续；各格式完整目标保持开放。
