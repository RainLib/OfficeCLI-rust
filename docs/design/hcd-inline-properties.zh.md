# 可编辑行内容器：属性候选与正文独立协同（2026-10-27）

本轮在内部 `hcd.extension/3` / `contentModel: inline` 正文载体、精确 PM 事务和签名保存基础上补齐属性协同。默认 schema、公开 SDK 和活动 wire7 房间没有开放新模型；管理平台、提醒发送仍后置。

## 实现与不变量

- `nodePropertyEdits.ts` 抽取已有节点字段候选协议，保留原节点命名空间、版本、预算、因果分支、完整候选和校验规则。`extensionEdits.ts` 继续只接受旧节点载荷，不把内部 envelope3 暗中加入公共注册协议。
- `inlineContainerPayload.ts` 保留原有严格内部解析器；`inlineContainerEdits.ts` 用独立 `hcd-inline-container-edits/1/{intents,materialized}` 复用同一候选算法。记录包含根载荷、修改前后值、父候选集合和触及字段。不同字段合并，同字段差异保留双方；资源/版本等信封变化保持完整候选，不拼装不相容的资源。
- 原始 definition 永久保留。可见属性由候选投影，正文仍使用独立 `Y.XmlText`；改属性不复制正文字符、不重建子节点、不改写来源或资源字节。未知业务字段、空值和原资源描述随载荷保留。
- `SemanticInlineContainers` 对整批根节点和属性记录先预检，再分配载体；准备完成后若候选或定义变化，拒绝执行过期准备。`SemanticBlockStore` 把属性记录与正文/结构写入同一用户事务，个人历史跟踪属性 intent，不跟踪永久定义或派生显示回执。
- 多人合并后，业务 codec 生成与当前候选集合绑定的可读回执。无 codec 或合并数据不合法时保持待处理；冲突选择使用精确候选 ID 集合，过期选择不写入共享状态。业务回调不能通过普通字段派生悄悄改掉实例、类型、版本、资源或数据。
- `businessDraftProblem` 和协调器观察值包含内部属性候选；未解决冲突或未就绪的合并不能提交，也不能显示为已保存。正文仍可继续输入。签名保存、迟到输入恢复、来源回执沿用显式内部模式，不另造无签名保存路径。
- 删除整个根节点时，审阅快照包含内部属性的候选 ID/就绪状态。即使迟到候选具有相同可见值，也重新进入删除审阅。原先阻止从保留段落直接移除内部包装器的门禁继续保留，尚未用根删除能力冒充行内删除审阅。
- 活动 `RoomProtocolGuard` 对只有属性命名空间、尚无正文或定义的更新同样拒绝。默认旧模型不会因新增内部模块而接受新模型写入。

实际原生 HTTP 验收使用源文件无关的 r8 HCDZ 副本，未修改输入归档：

1. 两个独立 Y.Doc 离线修改同一属性并保留正文输入；协调器确认冲突且没有发出 `/checkpoints`。
2. 选择 Bob 分支，个人撤销恢复冲突，再重做确认；同伴正文保留。r9 保存的是 Bob 属性与已确认状态，保留原未知字段和节点资源。
3. 原生服务成功提交 r9 后，由测试代理断开真实 TCP 响应；原进程继续输入正文并修改为“迟到属性”，持久化后退出。
4. 另一 Node 进程读取服务端实际 Yjs 字节和签名捕获，核实属性历史、迟到值及递归来源，保存为 r10。原 r9 请求幂等重放仍返回 r9，head 保持 r10；缺模型头为 426，只读写入为 403。
5. HCDZ 离线重开 r8/r9/r10 的投影逐项一致。r9/r10 各导出 DOCX、PPTX、PDF、Markdown，共八份实际文件；回读内容核实对应属性标签、同伴正文、迟到正文、内部提及及嵌套正文数量。两个资源引用对应同一原始文件，字节长度和 SHA256 一致。
6. 嵌套 `@Bob 李` 只在 r9 产生一条由 Alice 创建的关联事件；r10 属性/正文保存无重复关联，提醒关闭。
