# Agent 移动轨迹与预览稳定性

2026-11-15。对应反馈：光标从一个操作目标跳到另一个目标、操作时文档闪屏、箭头标签包含多余的提交状态。

## 修改

- 每位 Agent 的指针与目标区域分别保持稳定身份。目标变化时，从上一次位置沿二次曲线滑动到新位置，并显示短暂的轨迹；移动中再次收到目标时，从当前插值位置继续。使用浏览器原生 `transform` 动画，不通过每帧 React 状态更新驱动整个编辑器。
- 指针标签只显示 Agent 名称。真实提交状态和“动画仅为回放”的说明留在操作面板。回放完成后停在最后一项，不再跳回第一项。
- 播放时钟与文档上下文分开。只有光标层、目标区域和操作进度订阅播放状态；计时器只安排下一次步骤变化或轨迹过期，播放结束后不再持续定时刷新。
- Excel 的光标定位独立于工作簿组件；同一目标的原生定位锚点在回放阶段切换与心跳时复用，视口滚动、缩放或冻结设置改变时才更新。新锚点准备期间保留原指针，避免短暂消失后重新出现；没有可见 Agent 时停止几何测量。
- PPTX/PDF 收到远端修订时，保留当前页面，等待新索引准备完成后更新。固定预览保持同一个 iframe 和内部 Document，已准备好的内容就地替换，避免反复导航至空白页面。
- Agent 工作台轮询结果未变化时复用任务状态。减少动画偏好会跳过移动与轨迹；滚动和缩放同一目标时直接跟随画布坐标。

## 验证

新增 PPTX 和 XLSX 端到端用例，使用实际服务与官方 MCP SDK 发布连续定位；浏览器逐帧采样确认存在多个中间坐标，曲线轨迹已建立，指针 DOM 没有被替换，标签严格等于 Agent 名称。停下后检查位置稳定、没有额外文档内容请求。PPTX 再提交真实文字修改，确认同一个 iframe、同一个内部 Document，且没有发生新的 load。

批量操作回归同时检查 Excel 原生锚点在整段播放前后仍为同一组 DOM 节点；原有 MD/DOCX/XLSX 操作队列、冻结区域、画布缩放、历史比较、修订同步和导出用例继续验证。

本次完整 68 项浏览器回归首轮有 64 项通过，暴露了滚动后原生锚点不更新，以及指针/区域分离后的旧定位选择器歧义。修正后对这四个场景连同连续轨迹和锚点复用共 7 项进行复验，全部通过。TypeScript、应用构建、嵌入构建及差异空白检查通过。分轮结果与日志见 [验证记录](hcd-openai-agent-harness/motion-summary.json)。
